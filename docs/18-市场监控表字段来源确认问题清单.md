# 市场监控表字段来源确认问题清单

> 日期：2026-07-02  
> 目的：确认 `【市场监控】海外仓精品市场调研.xlsx` 每个字段最终来自哪张表 / 哪个字段，什么时候写入，以及是直接取数、人工填写还是计算得出。  
> 填写方式：请在每行的“业务确认来源表 / 字段”和“业务确认逻辑”里补精确来源；如果是直接取数，写来源表字段；如果不是直接取数，写清楚计算 / 判断逻辑。

## 1. 当前已知事实

- 当前本地文件：`【市场监控】海外仓精品市场调研.xlsx`。
- 当前 sheet：`说明`、`PH精品`、`TH精品`、`VN精品`、`MY精品`；其中 `MY精品` 当前为空。
- `PH精品`、`TH精品`、`VN精品` 表头在第 2 行，列到 `AZ`，结构基本一致。
- 当前本地文件实测：`AO=产品定位`，平台现行枚举为 `引流款 / 利润款 / 淘汰款 / 稳定款 / 清仓款`；`AQ=6.22号公司:单销`。截图或在线表版本可能有列号漂移，后续必须按表头匹配，不按固定列号。
- 这张表不是 PLM 原始表，也不是备货申请表；它是备货申请导出之后持续跟进的市场监控 / 二次调研工作表。
- 后续平台需要能按这张表结构组装数据，并导出为 Excel 文件。

## 1.1 本轮已确认字段口径

- `A 调研时间`：对平台自己导入 / 分配的新品任务，按 `B 货品` 里的期数日期默认填后一天。例如 `开发新品0609期` 默认填 `6.10`，`开发新品0629期` 默认填 `6.30`。如果后续是其他数据源，例如运营自己开的品，不由系统默认，销售 / 运营自己填写。
- `B 货品`：对平台自己导入 / 分配的新品任务，由系统按来源和期数生成，例如 `开发新品0609期`、`开发新品0629期`。其他来源的货品文案按该来源自己的规则或由销售 / 运营填写。
- `AL 调研时间`：运营点击“确认已调研”时由系统写入提交时间，不要求运营手工填写。
- `G 商品名称`：由平台内源数据按 `主 SKU + 子 SKU` 定位取得；PLM 商品名称只做补齐 / 校验，不作为优先覆盖来源。
- `I 二级类目`：第一版允许为空，暂不做自动补齐；后续如果业务需要，再从 ERP 产品列表下载匹配。
- `J 海外仓成本`：优先从导入源表按表头匹配，不按固定列号。`选品1` 优先匹配 `商品成本-含税（元）`；`选品2` 优先匹配 `进价`。列号如 R 列、G 列只代表当前截图位置，不能写死。兜底按字段别名匹配，找不到则导出留空并记录缺失来源。
- `直发热销转海外仓`：后续如果导入该类数据源，第一步只导入源表 `A-O` 字段；`P` 列及之后字段的来源、填写人、流转逻辑后续再对齐，当前不提前设计。
- `R-Z` 三组竞品链接 / 售价 / 月销：能从上游字段映射就带入；`选品2` 字段不完整也可以接受，缺失字段导出留空，不要求运营补齐。
- `AD-AI`：按目标字段名 / 语义从上游源表或中央新品表匹配，不按固定列号匹配。`产品类型 + AJ/AL/AM/AO/AP` 只作为部分历史 sheet 的位置参考；实际导入 / 导出以表头含义为准，字段位置变了也要识别。
- `AK 调研结论`：来自前段运营第一次认领 / 不认领时填写的“调研结论”，对应平台认领记录 `feedback_summary`；该字段可选，不强制每个 SKU 填写。
- 二次调研 `AL-AO`：`AL` 由系统写入提交时间并允许运营修改，`AM` 二次竞对链接选填，`AN` 二次调研结论必填，`AO` 产品定位必选。按主 SKU 整组提交时，任一子 SKU 必填项不完整则整组不得提交。

## 2. 已确认的基础行来源

这里的“基础行”指：系统最后生成 `【市场监控】海外仓精品市场调研.xlsx` 时，每一行商品 SKU 从哪里进入市场监控。

当前已确认：第一版市场监控表的基础行，只来自平台内“已通过主管复核、进入备货导出 / 市场监控”的子 SKU 记录。

也就是说，市场监控表不是从旧市场监控表、PLM 库存明细、选品4 直接铺行生成的。

按当前流程理解，行来源是：

```text
选品1 / 选品2 导入
-> 平台字段对齐
-> 主管分配
-> 运营认领 / 不认领
-> 主管复核通过
-> 生成备货申请导出行
-> 同一批通过复核的子 SKU 进入市场监控
```

`海外仓备货申请表.xlsx` 是这个环节导出的文件，不是市场监控表的上游源表本身；真正的上游是平台内已复核通过的备货子 SKU 记录。

当前已知文件在这个链路中的角色：

| 候选来源 | 具体文件 / 表 | 说明 | 是否作为市场监控表基础行 |
|---|---|---|---|

## 3. 行生成时点

建议先按最小规则：

| 时点 | 当前建议 | 业务确认 |
|---|---|---|
| 备货申请导出后 | 平台保存可监控候选行，但不一定立即要求运营二次调研 |  |
| PLM 拉到预计到港 / 到货 / 入库信息后 | 更新到货、库存、首次上架、预计到港等系统字段 |  |
| 新品首次到货识别后 | 运营进入市场监控 / 二次调研，填写二次竞对、二次调研结论和产品定位；现行新品候选按集团八部与前一天最后入库数据筛选，最终以 `最后一次入库时间` 和 `首次上架时间` 的北京时间日期相同判定。`海外仓可发`、`海外仓在途`、`公共池库存` 仅展示 / 对账，不单独触发 | 已确认 |
| 运营判定淘汰款后 | 通知主管去外部系统调整产品定位，避免清仓销量触发误补货 |  |
| 用户点击导出时 | 按当前市场监控表结构导出 Excel |  |
