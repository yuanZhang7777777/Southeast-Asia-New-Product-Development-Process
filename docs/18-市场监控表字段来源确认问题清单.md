## 1. 当前已知事实

- 当前 sheet：`说明`、`PH精品`、`TH精品`、`VN精品`、`MY精品`；其中 `MY精品` 当前为空。
- `PH精品`、`TH精品`、`VN精品` 表头在第 2 行，列到 `AZ`，结构基本一致。

- 后续平台需要能按这张表结构组装数据，并导出为 Excel 文件。

## 2. 已确认的基础行来源

这里的“基础行”指：系统最后生成 `【市场监控】海外仓精品市场调研.xlsx` 时，每一行商品 SKU 从哪里进入市场监控。

当前已确认：第一版市场监控表的基础行，只来自平台内“已通过主管复核、进入备货导出 / 市场监控”的子 SKU 记录。

也就是说，市场监控表不是从旧市场监控表、PLM 库存明细、选品4 直接铺行生成的。

按当前流程理解，行来源是：

```text
选品1 / 选品2 导入
-> 平台字段对齐
-> 主管分配
-> 运营认领 / 不认领
-> 主管复核通过
-> 生成备货申请导出行
-> 同一批通过复核的子 SKU 进入市场监控
```

`海外仓备货申请表.xlsx` 是这个环节导出的文件，不是市场监控表的上游源表本身；真正的上游是平台内已复核通过的备货子 SKU 记录。

当前已知文件在这个链路中的角色：

| 候选来源 | 具体文件 / 表 | 说明 | 是否作为市场监控表基础行 |
|---|---|---|---|

建议先按最小规则：

| 时点 | 当前建议 | 业务确认 |
|---|---|---|
| 备货申请导出后 | 平台保存可监控候选行，但不一定立即要求运营二次调研 |  |
| PLM 拉到预计到港 / 到货 / 入库信息后 | 更新到货、库存、首次上架、预计到港等系统字段 |  |

| 用户点击导出时 | 按当前市场监控表结构导出 Excel |  |
