# 销售自选、选品2与备货申请流程需求对齐

> 日期：2026-07-22
>
> 状态：业务口径已确认；`36a9ae9` 已部署开发环境并完成自动化与只读技术 UAT，写入式业务 UAT 和真实 ERP 查询仍待完成。实施规格见 `docs/superpowers/specs/2026-07-21-sales-self-stocking-request-design.md`。
> 本期范围：用一期真实数据验收选品1/选品2，并新增销售自选商品的备货申请填写入口；不接入旧选品3、选品4 Excel 流程。

## 1. 已核实的现状

本地仍保留四类真实源表：

1. `选品1：海外仓开发部门开发新品认领-反馈.xlsx`
2. `选品2：海外仓财根团队开发新品认领-反馈.xlsx`
3. `选品3：销售选品备货海外仓-销售调研.xlsx`
4. `选品4：直发热销转海外仓销售确认.xlsx`

当前统一开发分支已经实现选品1和选品2导入，并非只有选品1：

- 选品1：主管按主 SKU 分配，运营逐子 SKU 认领 / 不认领；开发环境在主管复核通过后生成备货申请草稿。
- 选品2：财根表导入后，表内主销售员可形成必处理任务，其他运营可以自领同一商品；开发环境在各运营提交并经主管复核通过后，分别生成各自的备货申请草稿。
- 选品3、选品4：只有历史源表和字段文档，没有平台运行入口；本期不接入。
- 开发环境已提供运营备货申请工作台和主管勾选导出页；技术部署和只读页面验收通过不等于写入式业务验收通过。

## 2. 本期新增业务对象

本期新增“销售自选商品”，但不复刻旧选品3 Excel：

- 运营在平台内主动创建一组商品。
- 一个主 SKU 可填写多个子 SKU；正式备货申请按“销售员 + 子 SKU”逐行保存和导出。
- 运营先自行到公司现有系统查看海外仓是否已有可用库存，平台本期不自动查询库存。
- 运营根据自己查到的库存结果选择是否需要新增备货。
- 需要备货时，填写并提交备货申请，后续进入备货表导出和待到货链路。
- 只有运营确认海外仓已有可用库存时，选择“不备货”才跳过备货申请、待到货和二次调研，直接进入待刊登。
- 海外仓无可用库存且不备货时，状态设为 `暂不推进`，不生成备货申请、待到货、二次调研或待刊登任务；保留记录和已填内容，运营后续改为备货时按正常备货链路继续。

为了复用现有到货、二次调研、刊登和观察能力，销售自选商品仍应形成平台内部商品机会和负责人记录；页面不要求运营再走一次“认领”表单。

## 3. 统一流程边界

### 3.1 选品1

开发环境现行流程（写入式业务 UAT 待完成）：

```text
导入 -> 主管分配 -> 运营认领 -> 主管复核生成备货申请草稿 -> 运营填写并提交 -> 主管勾选导出 -> 待到货
```

主管复核通过后按“销售员 + 子 SKU”生成草稿；运营只处理自己的草稿。提交后直接进入主管导出中心，不新增独立审核页面；主管选择并导出即完成确认，申请转为已导出，负责人记录进入 `waiting_arrival`。

### 3.2 选品2 / 财根

开发环境现行实现沿用多人认领能力（写入式业务 UAT 待完成）：

```text
导入 -> 主销售员必处理 / 其他运营自领 -> 主管复核生成各自草稿 -> 各运营填写并提交 -> 主管勾选导出 -> 待到货
```

各运营分别填写并提交自己的子 SKU 备货申请；提交后直接进入主管导出中心。主管选择并导出即完成确认，不新增独立审核页面。

同一子 SKU 被多个运营通过时，备货申请按“销售员 + 子 SKU”分别生成独立行，不合并；每位运营只填写和提交自己的申请，互不覆盖。该口径沿用当前按运营/认领记录分别导出的行为。

### 3.3 销售自选

开发环境现行实现只新增一个轻量入口，不新增第三套选品工作台（写入式业务 UAT 待完成）：

```text
运营新建主 SKU 与子 SKU
  -> 运营自行到公司系统查看海外仓库存
  -> 运营确认是否新增备货
  -> 按库存和备货决策进入对应后续状态
```

当前已经确认的分支是：

- 海外仓已有可用库存且选择不备货：跳过新增备货、待到货和二次调研，直接进入待刊登。
- 海外仓无可用库存且选择备货：进入备货申请、导出、待到货；到货后再进入二次调研。
- 海外仓无可用库存且选择不备货：状态设为 `暂不推进`，不生成后续任务；保留记录，后续改为备货时继续标准链路。

“已有库存”和“需要新增备货”不能同时选择；页面和 API 都必须拒绝这个矛盾组合，避免产生第四条未定义分支。

库存有无由运营人工判断并在平台确认；本期不新增库存查询接口，也不根据平台自动库存结果替运营做决定。

## 4. 正式备货申请表字段

正式模板为一张 16 列子 SKU 明细表：

| 列 | 字段 | 当前建议来源 |
|---|---|---|
| A | 操作状态 | 外部处理状态；平台首次导出留空 |
| B | 申请日期 | 必填；系统默认北京时间当天，运营可按实际备货批次修改；导出仅写日期 |
| C | 备货类型 | 运营选择，默认“首次备货”；模板现有下拉为“首次备货/补货” |
| D | 选品数据源 | 系统生成：选品1、选品2/财根、销售自选 |
| E | 销售员 | 当前登录运营；选品1/2取通过复核的运营 |
| F | 主 SKU | 选品1/2从来源带出；销售自选由运营填写 |
| G | 子 SKU | 每个子 SKU 单独一行；销售自选由运营填写 |
| H | 成本价 | 选品1自动带出“商品成本-含税（元）”，选品2自动带出“进价”，运营提交前可修改；销售自选由运营手工必填。货值计算和导出使用最终提交值，来源原值保留在来源快照中 |
| I | 单个体积 | 优先通过 ERP 子 SKU 产品列表计算；包装尺寸和产品尺寸都不完整时，由运营手工填写单个体积（m³），必须大于 0 后方可提交 |
| J | 备货单销 | 运营填写 |
| K | 备货数量 | 系统计算：`备货单销 × 30`，结果向上取整为整数件，例如 `60.3 → 61` |
| L | 备货国家 | 运营选择/确认 |
| M | 备货仓库 | 可选自由文本，不提供默认值或建议值；运营可填写，也可留空提交，由主管在导出的外部表中补填 |
| N | 货值 | 系统计算：`成本价 × 备货数量` |
| O | 体积 | 系统计算：`单个体积 × 备货数量` |
| P | 补货原因 | 备货类型为“首次备货”时可留空；备货类型为“补货”时运营必填 |

模板黄色列实测为 `B:H、J、L、P`；蓝色列为 `A、I、K、M、N、O`。颜色只能作为来源参考，最终页面的可编辑权限按业务确认执行。

## 5. ERP 单个体积规则

已核实产品列表下载接口可以按子 SKU 返回：

- 产品长、宽、高：`actualLength`、`actualWidth`、`actualHeight`
- 包装后长、宽、高：`pretendlength`、`pretendwidth`、`pretendlheight`

建议统一规则：

1. 包装后三个尺寸都有效时，整组使用包装后尺寸。
2. 包装尺寸缺失时，整组回退到产品长宽高，不混用两组尺寸。
3. `单个体积(m³) = 长(cm) × 宽(cm) × 高(cm) ÷ 1,000,000`。
4. 两组尺寸都不完整时，由运营手工填写单个体积（m³）；输入必须为大于 0 的数字，填写后方可提交。
5. 草稿不沿用来源表快照里的“包装后体积”作为静默预填，防止把旧表值误标为 ERP 或手填结果。

2026-07-21 样例核对：

- `GSHWAC225ND`：`10.1 × 9.4 × 1.4 ÷ 1,000,000 = 0.000132916 m³`
- `SH-OD-492-BL`：`6.7 × 5.3 × 2.5 ÷ 1,000,000 = 0.000088775 m³`

ERP 登录应使用现行 Open Login 获取临时访问令牌；业务接口继续使用 `Authorization: <accessToken>`，不得使用历史固定 token，也不得把账号、密码、Cookie 或 token 写入仓库和文档。

本期不同时铺开四种来源，建议分三步：

测试全部在独立开发环境和开发库进行；生产环境不用于写入式验收。

## 7. 后续逐项确认队列

已经确认：

- 库存由运营自己到公司系统查看，平台本期不自动查询。
- “不备货后直接进入待刊登”只适用于运营确认海外仓已有可用库存的情况。
- 备货仓库为可选自由文本，不提供默认值或建议值；运营可填写，也可留空提交，由主管在导出的外部表中补填。
- 运营提交备货申请后直接进入主管导出中心，不新增独立主管审核页面；主管选择并导出即视为确认。
- 选品2同一子 SKU 被多个运营通过时，按“销售员 + 子 SKU”分别生成备货申请行，不合并、不互相覆盖。
- 选品1/2成本价由系统从来源表自动带出，运营提交前可修改；销售自选成本价由运营手工必填。货值计算和导出均使用最终提交值，来源表原成本价仍保留在来源快照中。
- `备货数量 = 备货单销 × 30`；结果出现小数时统一向上取整为整数件。
- ERP 包装尺寸和产品尺寸都不完整时，允许运营手工填写单个体积（m³）；必须填写大于 0 的数字后才能提交。
- 备货类型为“首次备货”时补货原因可留空；备货类型为“补货”时补货原因必填。
- 海外仓无可用库存且选择不备货时进入 `暂不推进`，不生成后续任务；记录保留，运营之后可改为备货继续。
