# 东南亚新品流程协同平台系统架构重新设计方案

> 日期：2026-06-29  
> 状态：MVP 技术方案已落地为项目骨架，业务细节继续按模块确认。

## 1. 系统定位

本系统是钉钉在线表、ERP、库存、销售数据之上的“新品流程协同层”，不替代 ERP，也不把第一版做成大而全 BI 平台。

第一阶段业务验收只跑通：

```text
入池 -> 分配 -> 销售认领 -> 主管审核
```

> ⚠️ 口径校正：本平台是“两段主流程 + 一座外部桥”。最初 MVP 止于导出可备货清单；2026-07-21 已确认的新增方向是在平台内让运营填写、确认并保存 `stocking_request` 后导出，但不把采购 / 供应链 / 下单执行搬进平台。销售自选入口及字段权限已在 `docs/23-销售自选与备货申请需求对齐.md` 收敛，尚未实现。
>
> **采购 / 供应链 / 下单执行 = 外部桥**；平台内只负责备货申请填写、确认、保存、导出与外部状态登记，不做采购执行工作流。

第一阶段验收范围不变；后段已在独立开发环境继续实现到二次调研和刊登观察。其中现有 `stocking` 已支持导出 / 外部状态登记，下一步计划增加运营填报与确认；`arrival` 承接 PLM 到货通知，`listing_workbench` 负责刊登和 Item 周期观察。完整端到端链路见 `docs/08-端到端流程链路规划.md`。

## 2. 技术栈

| 层级 | 选型 | 当前落地 |
|---|---|---|
| 前端 | React + Vite + TypeScript | `frontend/` 已建立 MVP 工作台 |
| 后端 | FastAPI | `backend/` 已建立 API、模型、服务和测试 |
| 数据库 | PostgreSQL | `docker-compose.yml` 已配置，开发默认可用 SQLite |
| 队列/缓存 | Redis | `docker-compose.yml` 已配置 |
| 部署 | Docker Compose + Caddy | `deploy/` 已配置反向代理和服务器初始化脚本 |
| 通知适配 | Notification Adapter 独立容器 | 仅做消息通道适配和发送验证，不直接访问业务库 |
| 工程约束 | Ponytail | 仅用于开发和 review，不进入业务运行时 |

## 3. 后端模块

当前代码已经建立这些模块边界：

- `auth`：钉钉登录占位接口，本地先生成测试用户。
- `opportunities`：新品机会池，保留来源文件、sheet、行号、快照。
- `assignments`：分配预览、确认分配、改派。
- `claims`：销售认领、不认领校验。
- `reviews`：主管审核，第一阶段结束于通过、驳回、退回补充。
- `stocking`：平台协同入口——现有导出与外部状态登记已落地，计划增加运营填写、提交和保存备货申请；提交后直接进入现有主管导出中心，由主管选择并导出完成确认，不新增独立审核页面。采购 / 供应链 / 下单执行仍在平台外。
- `arrival`：后段（Phase 2）到货通知回流入口占位，不作为第一阶段验收。
- `listing_workbench`：从待刊登主 SKU 派生刊登任务，管理 Item 独立周期、复盘、停止/恢复、主管作废和商品详情只读汇总。
- `notifications`：通知日志和 `dedupe_key` 去重。
- `admin`：人员映射、角色配置。

## 4. 数据表

以下表已在 SQLAlchemy ORM 中建模（**含后段 / 外部桥表，并非都是前段 MVP 必需**：`stocking_request` 为导出/桥、`supply_chain_quote` 为外部只读、`arrival_record` 为后段）：

| 表 | 用途 |
|---|---|
| `users` | 用户基础信息 |
| `role_mapping` | 人员、角色、小组、站点映射 |
| `new_product_opportunity` | 新品机会主表 |
| `source_record_snapshot` | 源表行快照 |
| `market_research_item` | 竞品、售价、月销等多行明细 |
| `flow_instance` | 流程实例 |
| `flow_task` | 待办任务 |
| `sales_claim_forecast` | 销售认领和预估单销 |
| `review_record` | 主管审核记录 |
| `supply_chain_quote` | 供应链报价 |
| `stocking_request` | 可备货清单导出 / 外部桥申请记录 |
| `arrival_record` | 到货记录 |
| `listing_record` | 主 SKU 下的店铺 + Item 刊登记录，保存来源责任、刊登策略、首周周期、跟踪/作废状态 |
| `item_observation_period` | Item 每个周四至周三周期的指标、定位、优化操作和第 4 周总结 |
| `notification_log` | 通知日志和去重 |
| `audit_log` | 审计日志 |

## 6. 第一版刻意不做

- 不做 Kubernetes。
- 不做复杂 BI。
- 不做全量在线表写回，先保留写回开关。
- 实际周 Item 接口未提供前，不猜测接口、鉴权或凭据；当前只提供稳定的指标落库边界。
- 不把 Ponytail 或外部 Agent 工具当成业务系统依赖；Notification Adapter 只作为消息通道边界。
