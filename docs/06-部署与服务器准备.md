## 5. 开发部署流程

发布包、备份和回滚目录位于 `/opt/hengzhe-new-product-dev`；所有 `docker compose` 命令必须在 `/opt/hengzhe-new-product-dev/app` 下执行：

1. 确认目标是 `hz-new-product-dev`，不要连接生产服务器。
2. 对开发 PostgreSQL 执行带时间戳的 `pg_dump`，写入 `backups/`。
3. 上传不含 `.env`、测试数据库、缓存、`node_modules` 和私密源表的发布包。
4. 保留服务器现有 `.env`；发布包不得覆盖它。
5. 运行 `docker compose config`，确认项目名和 `18081` 映射。
6. 执行 `docker compose build` 和 `docker compose up -d`；`migrate` 只升级开发库。
7. 检查迁移版本、容器健康、API 健康、首页和关键接口。
8. 写入 `DEPLOYED_COMMIT`，并保留发布包和数据库备份用于回滚。

迁移 `a8d4e6f7b901` 会在开发库创建 `listing_record`、`item_observation_period`，并删除无数据的旧 `four_week_summary`。不得把这条迁移直接用于当前生产库。

## 6. 回滚

应用代码回滚优先使用 `releases/` 中上一份发布包，并保留当前 `.env` 和 Docker volumes。数据库结构回滚前必须再次备份；若新表已经出现真实业务数据，不得直接执行 Alembic downgrade，应先评估并导出数据。

## 7. 安全与备份

- `.env` 永不入库，发布包不得包含 `.env`。
- 开发环境每次迁移前先备份 PostgreSQL。
- 上传文件和数据库卷不随代码目录替换。
- 外网只开放必要的 SSH 与 `18081`；数据库、Redis、worker、scheduler 不直接暴露。
- 日志不得记录含 Token 的完整访问 URL。
- 生产服务器在用户使用期间绝不重启。
