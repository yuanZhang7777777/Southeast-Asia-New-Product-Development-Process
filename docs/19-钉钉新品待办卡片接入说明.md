# 钉钉新品待办卡片接入说明

> 日期：2026-07-06  
> 读者：主线后端 / 前端开发  
> 用途：说明当前已经设计并验证的钉钉新品待办卡片、变量、触发逻辑和调用方式。  
> 安全边界：本文不记录 Client Secret、access token、callback secret、完整 DingTalk userId、服务器密码或任何 `.env` 值。

## 1. 当前结论

第一版只用一张通用互动卡片模板：

```text
新品待办
```

同一张模板同时服务运营和主管。后端按收件人角色传不同变量，不需要维护两套卡片，也不需要新建复杂 v2 变量。

当前使用模板：

```text
a428e864-5416-4ea6-ad29-36e19e0615e2.schema
```

图片固定在钉钉卡片模板里即可。不要再把图片做成变量；钉钉卡片图片变量通常要求 `mediaId`，普通公网图片 URL 不能稳定展示。

## 2. 卡片结构

卡片固定展示两个待办槽位：

```text
固定图片

新品待办
你有 X 项新品事项待处理

左侧事项：数量    右侧事项：数量

说明文案

[按钮]
```

第一版不在卡片里展示商品明细、不认领理由、证据图或淘汰款明细。卡片只负责提醒和入口，业务处理进入平台页面完成。

## 3. 变量清单

所有变量按字符串传入。

| 变量 | 必填 | 示例 | 说明 |
|---|---|---|---|
| `card_title` | 是 | `新品待办` | 卡片标题 |
| `summary_text` | 是 | `你有 14 项新品事项待处理` | 总提示文案，由后端拼好 |
| `left_label` | 是 | `待认领` | 左侧事项名称 |
| `left_count` | 是 | `12` | 左侧事项数量 |
| `right_label` | 是 | `待补充` | 右侧事项名称 |
| `right_count` | 是 | `2` | 右侧事项数量 |
| `tip_text` | 是 | `请处理待认领新品和退回补充事项` | 底部说明 |
| `action_text` | 是 | `立即处理` | 按钮文案 |
| `action_url` | 是 | `https://example.com/?from=ding&role=operator` | 按钮跳转地址 |

不要在 `action_url` 里携带用户身份、token、手机号或姓名。身份由钉钉 H5 免登进入平台后识别。

## 4. 运营卡片

运营只展示两类当前要处理的事项：

```text
待认领
待补充
```

公开 Mock 数据填这个：

```json
{
  "card_title": "新品待办",
  "summary_text": "你有 14 项新品事项待处理",
  "left_label": "待认领",
  "left_count": "12",
  "right_label": "待补充",
  "right_count": "2",
  "tip_text": "请处理待认领新品和退回补充事项",
  "action_text": "立即处理",
  "action_url": "https://www.baidu.com"
}
```

触发来源：

| 场景 | 触发时机 | 统计口径 |
|---|---|---|
| 待认领 | 主管确认分配 / 改派后 | 当前运营名下待处理 `sales_claim` 任务，排除已退回补充状态，按主 SKU 去重 |
| 待补充 | 主管退回不认领补充后 | 当前运营名下 `returned_for_supplement` 的待处理 `sales_claim` 任务，按主 SKU 去重 |

`到货未处理` 是后续到货/二次调研环节，不放进当前运营卡片第一版。

## 5. 主管卡片

主管同一张模板，展示两类复核事项：

```text
认领待复核
不认领待复核
```

主管预览 Mock 数据可以填这个：

```json
{
  "card_title": "主管新品待办",
  "summary_text": "你有 7 项主管事项待处理",
  "left_label": "认领待复核",
  "left_count": "5",
  "right_label": "不认领待复核",
  "right_count": "2",
  "tip_text": "请按小时汇总复核运营提交的认领和不认领",
  "action_text": "进入主管处理",
  "action_url": "https://www.baidu.com"
}
```

触发来源：

| 场景 | 触发时机 | 统计口径 |
|---|---|---|
| 认领待复核 | 每小时汇总更新一次，不按单条提交即时推送 | 状态为 `待复核-认领` 的记录数 |
| 不认领待复核 | 每小时汇总更新一次，不按单条提交即时推送 | 状态为 `待复核-不认领` 的记录数 |

第一版不推送“主管待分配”，因为主管本人就是分配动作发起人。后续如果运营把商品改为 `淘汰款`，再新增主管提醒口径；当前不进入本卡片。

## 6. 后端发送规则

最小规则：

1. 后端按收件人角色计算两个数量。
2. 两个数量都为 `0` 时不发卡片。
3. 至少一个数量大于 `0` 时发送卡片。
4. `action_url` 指向平台页面，由平台页面完成钉钉 H5 免登和权限校验。
5. 运营卡片由分配、改派、退回补充等个人待办变化触发。
6. 主管卡片做小时级汇总更新，不在运营每提交一条认领/不认领时即时发送。

建议去重：

```text
receiverDingtalkUserId + role + scene + businessDate
```

状态进入型提醒仍可保留业务去重键：

```text
taskId + status + receiverDingtalkUserId
```

不要把完整 DingTalk userId 写入业务日志。需要排查时只打印前缀或 hash。

## 7. 调用方式

已验证的发送接口：

```text
POST https://api.dingtalk.com/v1.0/card/instances/createAndDeliver
```

请求头：

```text
x-acs-dingtalk-access-token: <enterprise_access_token>
Content-Type: application/json
```

获取企业 access token：

```text
POST https://api.dingtalk.com/v1.0/oauth2/accessToken
```

`appKey` / `appSecret` 从生产 secret manager 或环境变量读取，不要写入仓库。

发送 payload 形态：

```json
{
  "userId": "<receiver_dingtalk_user_id>",
  "cardTemplateId": "a428e864-5416-4ea6-ad29-36e19e0615e2.schema",
  "outTrackId": "new-product-todo-<role>-<business-key>",
  "cardData": {
    "cardParamMap": {
      "card_title": "新品待办",
      "summary_text": "你有 14 项新品事项待处理",
      "left_label": "待认领",
      "left_count": "12",
      "right_label": "待补充",
      "right_count": "2",
      "tip_text": "请处理待认领新品和退回补充事项",
      "action_text": "立即处理",
      "action_url": "https://example.com/?from=ding&role=operator"
    }
  },
  "openSpaceId": "dtv1.card//IM_ROBOT.<receiver_dingtalk_user_id>",
  "imRobotOpenSpaceModel": {
    "supportForward": true,
    "notification": {
      "alertContent": "新品待办",
      "notificationOff": false
    }
  },
  "imRobotOpenDeliverModel": {
    "spaceType": "IM_ROBOT"
  },
  "userIdType": 1
}
```

`outTrackId` 要保证业务侧可追踪、可去重。不要包含明文手机号、姓名或 secret。

## 10. 不做的事

第一版不要做：

- DingTalk Todo。
- 钉钉在线表自动写回。
- 在 URL 中携带身份。
- 为运营和主管维护两套卡片模板。
- 在卡片里展示详细商品明细、不认领理由、图片证据或淘汰款明细。
- 把后续 `到货未处理`、`淘汰款待处理`、`四周总结` 混进当前运营卡片。

这些内容进入平台页面或后续阶段处理，卡片只负责提醒和入口。

## 11. 后段到货 / 淘汰款通用卡片

2026-07-08 新增一张后段通用卡片，服务两个场景：

- 到货通知：每天早上 08:30 同步 PLM 到货数据后，按运营汇总推送。
- 淘汰款通知：每天北京时间 10:00 左右汇总推给主管，不在运营每提交一条时立即推送；清仓款不触发该通知。

### 11.1 卡片设计器排版

> 2026-07-17 实际测试纠正：当前共享投放模板只有顶部图片、标题、汇总说明和明细正文，没有按钮组件。历史 `a405` 模板能显示按钮且已启用“链接跳转”事件，但设计器中的“链接值”选择了空的静态值，没有绑定 `action_url`；分别传入开发业务地址和公开 HTTPS 地址后，客户端点击均无跳转。后端传入 `action_text` / `action_url` 只是在 `cardParamMap` 中提供变量值，模板组件仍必须显式绑定。下方结构是**目标结构**，不是当前已实现状态。

卡片顶部图片固定在模板里，不作为变量传入。当前图片口径是“小猫小狗 + 人，你在干嘛”的轻松梗图，后续上传到 OSS 或钉钉卡片素材后在模板中固定引用。

模板只保留以下结构：

```text
固定顶部图片

${card_title}

${summary_text}

${sku_markdown}

按钮组件：文案绑定 ${action_text}
按钮交互：打开链接，地址绑定 ${action_url}
```

不要再放 `left_label` / `left_count` / `right_label` / `right_count`。数量已经出现在 `summary_text` 里，额外数字块会重复。

### 11.2 变量清单

| 变量 | 设计器类型 | 必填 | 说明 |
|---|---|---|---|
| `card_title` | 普通文本 | 是 | 卡片标题，例如 `到货通知` / `淘汰款通知` |
| `summary_text` | 普通文本 | 是 | 汇总说明，包含主 SKU 数量 |
| `sku_markdown` | 富文本 | 是 | 主 SKU 明细，使用 Markdown 文本 |
| `action_text` | 普通文本 | 是 | 目标按钮文案；必须由设计器中的按钮组件绑定后才会显示 |
| `action_url` | 普通文本 | 是 | 目标按钮跳转地址；必须由按钮交互事件绑定后才会生效 |

接口层仍然通过 `cardParamMap` 传字符串；即使 `sku_markdown` 在设计器里绑定富文本变量，后端也传普通字符串。后端 sender 已能提供这两个变量。`a405` 的修复方式是：选中按钮的“事件”页，把“链接值”从空的“静态值”切换为“变量/绑定变量”并选择 `action_url`，保存发布后只向指定测试接收人复测。其他共享模板未经开发验证和用户批准不得直接修改。

### 11.5 Node 接入要点

复用钉钉官方 `createAndDeliver` 调用。最终 `cardDataCardParamMap` 只传新模板绑定到的五个变量：

```js
const cardTemplateId = 'a4053068-a70c-4ec8-a5b7-293d38a67a84.schema';

const cardDataCardParamMap = {
  card_title: '到货通知',
  summary_text: '今日有 4 个主 SKU 到货，请进入系统查看',
  sku_markdown: '**到货主SKU：**\n\n1. HZD032｜3L双喷口加湿器\n2. AZSOS882｜彩色画笔套装\n3. ABC123｜折叠收纳箱\n4. DEF456｜户外露营灯',
  action_text: '进入系统查看',
  action_url: 'http://101.132.26.138:8080/?from=ding&module=arrival'
};
```

发送请求保持以下关键字段：

```js
const createAndDeliverRequest = new dingtalkcard_1_0.CreateAndDeliverRequest({
  userId,
  cardTemplateId,
  outTrackId: `new-product-arrival-${Date.now()}`,
  callbackType: 'STREAM',
  cardData,
  imRobotOpenSpaceModel,
  imRobotOpenDeliverModel,
  openSpaceId: `dtv1.card//im_robot.${userId}`,
  userIdType: 1,
});
```

`accessToken`、`robotCode`、`clientSecret`、`userId` 从环境变量、数据库或钉钉接口获取，不写入仓库。

### 11.6 去重和频率

| 场景 | 接收人 | 频率 | 去重建议 |
|---|---|---|---|
| 到货通知 | 对应运营 | 每天 08:30 同步完成后推送 | `arrival:<date>:<operatorUserId>:<cardIndex>` |
| 淘汰款通知 | 对应主管 | 每天北京时间 10:00 左右汇总推送 | `eliminated:<date>:<managerUserId>:<cardIndex>` |

两个场景都只展示主 SKU。完整子 SKU、商品图、调研字段、淘汰原因和主管处理动作都进入平台详情页。
