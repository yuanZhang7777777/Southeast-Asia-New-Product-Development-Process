## 0. 2026-07-01 会后修正

- 本轮开发范围收敛为两张内部反馈表导入、主管分配、运营填写是否认领和认领单销、主管复核汇总、导出。在线表写回 / 中间桥先不作为第一版闭环要求。
- 需要导入的表只有：
  - `海外仓开发部门开发新品认领-反馈`
  - `海外仓财根团队开发新品认领-反馈`
- 暂不纳入本轮系统范围：
  - `直发热销转海外仓销售确认`
  - `销售选品备货海外仓-销售调研`
- `海外仓开发部门开发新品认领-反馈` 是人工从 `海外仓开发新品表-分站点` 下的 `东南亚海外仓新品表-PH / TH / VN ...` 汇总出来的内部反馈表。
- `东南亚海外仓新品表` 由公司维护；BV 列之后是不同部门填写区。本系统只服务本集团内部人员，只处理本集团对应销售员 / 团队列。
- 反馈表 BV-CB 区域字段包括：`开发是否接受核价结果`、`不认领理由`、`主销售员`、`是否认领`、`认领单销`、`销售反馈总结`、`备注`。
- 本集团平台处理字段为：主管分配 / 确认 `主销售员`；运营手动选择 `是否认领`，填写 `认领单销`、`销售反馈总结`、`备注`；不认领时填写 `不认领理由`。
- `开发是否接受核价结果` 属于外部部门字段，本轮只作为导入参考 / 展示，不由本集团运营填写。
- 选品1旧周期已有的 `是否认领`、`认领单销`、`主销售员`、`不认领理由`、`销售反馈总结`、`备注`仅保留来源快照，不预填、不推荐、不进入业务展示；财根选品2按独立机会池规则处理。
- 内部反馈表导入时优先读取行内 `站点` / `国家` 字段；选品1当前实测为 `A=站点`。不能仅凭固定文件名或 sheet 名推断站点。
- 当前本地 `选品2：海外仓财根团队开发新品认领-反馈.xlsx` 最新 `5.26期` 未发现站点字段；实测 20 个 SKU 可全部唯一匹配到 `东南亚海外仓新品表-PH.xlsx` 的 `5.26` sheet，站点取中央表行内 `菲律宾`。后续规则：无站点字段时可先按 SKU 回查 PH / TH / VN 中央表辅助带出站点；匹配不到或匹配多行不阻塞认领和导出，第一版不做异常清单流程。
- 平台字段口径以 `东南亚海外仓新品表-PH/TH/VN` 为目标字段字典。导入、展示、认领、复核和导出都尽量往中央表字段对齐；来源扩展字段保留；中央表字段补不出来时默认空值，不阻塞流程。
- `海外仓财根团队开发新品认领-反馈` 第一版作为机会池：主销售员 / 主认领销售是必须处理对象，不认领必须填原因；其他运营可以自领同一 SKU，人数不设上限。
- 两张内部反馈表实测字段清单保存于 `docs/16-新品认领反馈源表实测字段清单.md`。
- 系统需要保证导出结果可用于外部备货汇总；导出优先，不因中央表匹配问题阻塞。
- 后续可预留通过钉钉在线表能力写回 `东南亚海外仓新品表` 对应国家站点、对应集团 / 销售员列，但中间桥第一版不作为平台闭环要求。
- 写回 `东南亚海外仓新品表` 时，目标列不按固定列号，按表头匹配，例如 `销售员1\n仔云`、`预估单销\n仔云`、`销售员2\n财根`、`预估单销\n财根`。
- 写回范围先按中央表对应集团 / 销售员列处理，只写销售员和对应预估单销；不写 `合计单销`，由在线表原公式或人工维护。
- 不认领记录只在平台 / 内部反馈表留痕并进入主管确认；汇总到中央表时不写不认领字段，只写认领通过的销售员和预估单销。
- 写回必须依赖源表、国家站点、导入批次 / 来源快照、主 SKU、子 SKU、目标列映射，不能只靠商品名称模糊匹配；源行号只作为追溯信息，不作为写回匹配依据；行匹配推荐先按 `站点 + 主 SKU + 子 SKU`。
- 如果后续启用自动写回，`站点 + 主 SKU + 子 SKU` 匹配不到或匹配到多行时，第一版不自动写回、不生成异常清单、不推主管；由外部在线表人工处理，不影响平台导出。
- 如后续启用在线表写回，主管复核完成后需要主管点击“确认写回”才执行；未启用时平台只导出。
- SLA 会后口径：周三早上主管练玉君导入系统并开始分配；新品表和财根团队新品认领截止按周四 18:00 处理。

## 1. 角色

- 只做两个角色：运营、主管。
- 运营只能看到自己需要处理的模块，不显示主管分配台和主管审核页。
- 主管负责分配和审核。

## 2. 顶部流程

顶部先放一个独立总览入口：

```text
商品看板
```

- 商品看板用于查看全部商品 SKU 当前状态，不是流程节点，不放在箭头链路里。
- 商品看板运营和主管都可见，按主 SKU 分组，展开看子 SKU。

流程处理采用一条线：

```text
机会池 -> 分配台 / SKU 商品池 -> 运营认领 -> 主管审核 -> 可备货清单 -> 到货承接 -> 二次市场调研 -> 具体调整 / 竞品监控 -> 刊登确认 -> 1-4周监控 -> 四周总结
```

- `分配台` 和 `SKU 商品池` 是进入认领的两种入口，不是先后关系。
- 默认打开 `商品看板`，先看完整商品列表和当前状态，再进入具体处理节点。
- 产品界面不展示“主管只看结果”“不走审批”这类说明性口径，只展示真实状态、数据、筛选和动作。
- 状态模型采用两层：主 SKU 组显示任务流转状态，子 SKU 显示认领结果状态。
- 主 SKU 组状态用于列表筛选、待办流转和主管审核；子 SKU 状态用于明细、可备货清单和导出。
- 当同一主 SKU 组内只有部分子 SKU 认领通过时，主 SKU 组展示“部分认领通过”，子 SKU 分别展示“可备货 / 已确认不认领”。
- 子 SKU 认领结果状态先按以下中文枚举设计：未处理、可备货、已确认不认领。
- 运营提交前选择的认领 / 不认领只作为当前页面表单状态，不单独落成子 SKU 状态。
- 主 SKU 组状态先按以下中文枚举设计：
  - 待分配
  - 待认领
  - 待主管审核
  - 待补充
  - 认领通过
  - 部分认领通过
  - 已确认不认领
  - 已导出可备货清单
- `已导出可备货清单` 只适用于存在认领通过子 SKU 的主 SKU 组；导出后子 SKU 认领结果仍保留。
- 主管确认不认领后的终态名称固定为 `已确认不认领`；第一版不允许自动重新打开或再次认领；如导出后业务需要调整，由外部导出表 / 备货流程人工处理，不回流平台。
- 需要人处理或确认的关键状态生成系统内部待办，并发送钉钉推送入口；钉钉不生成待办任务。
- 第一版触发钉钉推送的关键状态至少包括待分配、待认领、待主管审核 / 待确认、待补充。
- 状态进入时立即推送一次；同一任务对同一接收人在未发生状态变化前，不重复发送相同推送。
- 钉钉推送和系统内部待办的去重 key 第一版按 `taskId + status + receiverUserId`；同一任务状态对不同接收人独立发送，适配几百人使用规模。
- 第一版钉钉推送内容包含：商品图缩略图、主 SKU、商品名称、当前状态、责任人、处理入口。
- 处理入口默认直接打开对应任务详情页；URL 只携带任务定位参数，用户身份通过钉钉免登获取，不从 URL 参数判断。
- 打开详情页后必须按当前钉钉用户做权限校验；无权限、任务不存在或链接失效时，提示原因并回到对应模块列表。
- 人员身份和主管关系优先从现有人员表或钉钉通讯录同步；第一版不做首次登录人工绑定。若现有数据无法定位主管，再补最小运营 / 主管映射配置。
- SLA 指每个节点允许处理的时限；超过 SLA 当天推送责任人，继续逾期后继续推送责任人，并同步推送主管。逾期扫描第一版每天 09:30 执行一次；具体节点时长待业务复核后确认。
- 前段按周批次处理：周三主管拿到开发 / 数据侧提供的数据并完成分配；周四运营完成认领 / 不认领填写并提交；周四主管完成复核汇总。

## 3. 机会池

- 选品1机会池是主管分配池，不是运营自领取池。
- 财根团队反馈表作为财根机会池，允许运营自领取同一 SKU。
- `选品1` 导入的数据先进机会池 / 待主管分配。
- 选品1源表已有主销售员也只作原值追溯，不作为分配推荐；必须主管分配后才生成运营认领任务。
- 主管可以选择暂不分配，机会保留在机会池，后续可重新分配。
- 展示形态：主 SKU 分组卡片列表，一行一个主 SKU，展开或详情查看子 SKU。
- 默认排序：按状态优先。
- 默认展示：
  - 商品图
  - 主 SKU
  - 产品名称 / 关键词
  - 站点
  - 一级类目
  - 子 SKU 数
  - 开品理由摘要
  - 竞品调研摘要：竞品数量、月销最高、价格区间
  - 当前状态
  - 当前负责人
  - 操作入口
- 不默认展示，仅放详情追溯：
  - 源文件
  - sheet
  - 行号
  - 原始快照

## 4. 分配台

- 仅主管可见。
- 按主 SKU 整组分配，组内子 SKU 不拆散。
- `选品1` 任务第一版一个主 SKU 组只分配给一个运营；子 SKU 不单独分配。
- 第一版主管角色固定为练玉君；销售员信息表里的 `岗位=组长` 只作为人员属性，不等同于平台主管角色。
- 展示推荐运营、推荐原因、当前负载。
- 不做改派。
- 支持一键自动分配：按 `重点站点硬过滤 -> 当前主 SKU 组负载 -> 重点品类命中 -> 同负载人员优先级 -> 站点内顺序` 批量生成分配草稿。
- 历史业绩不纳入第一版分配规则。
- 当前负载按未完成主 SKU 组数量 + 本次一键分配草稿数量计算，不按子 SKU 数量计算。
- 一键分配后仍允许主管在确认前人工调整推荐人。
- 前段批次时限：主管周三完成分配，运营周四完成提交，主管周四完成复核汇总。

## 5. SKU 商品池

- 运营可见。
- 第一版先不接泛化 SKU 商品池真实系统来源；财根团队反馈表作为机会池来源。
- 财根机会池不承接 `选品1` 默认未分配数据。
- SKU 商品池只有“认领”动作；运营不点击认领就不产生处理记录，不设计“不认领”动作。
- 财根机会池允许多个运营认领同一个主 SKU / 子 SKU，人数不设上限。
- 财根机会池中，被分配 / 指定的主销售员仍有必处理任务；如果不认领，必须填写不认领原因并进入主管审核。
- 多个运营认领后各自填写自己的子 SKU 认领单销，各自提交主管审核。
- 主管可以通过同一主 SKU 的多个运营认领。
- 同一个子 SKU 如果被多个运营认领通过，可备货清单按运营 / 认领任务分别出多行，不合并。
- 运营点击认领后生成运营认领任务，后续认领提交仍进入主管审核。

## 6. 运营认领页

- 认领任务按主 SKU 组展示，展开后处理子 SKU 明细。
- 子 SKU 默认全选为认领；运营可以取消部分子 SKU，标记为不认领。
- 认领的子 SKU 必填认领单销；不需要填写认领理由。
- `认领单销` 按日销理解；子 SKU 可备货量预览 = 该子 SKU 认领单销 × 30，结果出现小数时向上取整为整数件。
- 整组不认领时，默认全组子 SKU 都不认领，只填写主 SKU 组级不认领原因。
- 不认领原因支持固定选项多选，并允许同时填写自定义原因；固定选项和自定义内容继续写入现有字符串字段。
- `是否认领`、`认领单销`、`不认领原因 / 不认领理由`、销售反馈总结、备注等运营提交字段需要记录首次创建时间和最后更新时间。
- 补充材料可选，支持文字 / 链接 / 图片截图；不是所有不认领都必须补充截图。
- 图片附件支持三种录入方式：点击选择图片、拖拽图片到上传区、从剪贴板粘贴图片。
- 图片附件仅支持 JPG / PNG / WebP / GIF，单张不超过 20MB，不限制数量。
- 竞品参考不在认领表单重复展示，商品详情里已经展示。
- 提交前可以随时撤销、切换认领 / 不认领和修改子 SKU 选择。
- 提交前不写数据库，只在当前页面内实时保留填写内容。
- 进入商品详情页再返回运营认领页时，未提交草稿必须保留。
- 刷新、关闭页面或换设备后，未提交内容不保证保留。
- 点击提交时校验必填项：认领的子 SKU 必填认领单销；不认领的子 SKU 必填不认领原因。
- 校验不通过时不能提交，不进入主管审核。
- 只有点击提交时，才把子 SKU 选择、认领单销、不认领原因、反馈 / 备注和可选图片附件写入平台，并进入主管审核。
- 提交后、主管复核前，原运营可以修改并重新提交同一条记录；主管复核通过或确认不认领后不再进入运营认领可编辑列表，主管退回补充后可继续修改。
- 选品1源表已有 `CE/CF/CC/CG/CH` 值时只保留原值追溯，不进入运营表单；运营平台填写后，点击提交才进入主管审核。
- 运营上次在平台提交的调研图片重新打开时必须展示；切换认领 / 不认领不能清空另一模式已填内容；修改后在提交按钮旁显示`已填写未提交`。

## 7. 主管审核页

- 仅主管可见。
- 认领和不认领同时进入审核。
- 认领任务：主按钮为通过认领，次要动作可退回运营补充。
- 不认领任务：主按钮为确认不认领，次要动作可退回运营补充。
- 主管不允许代运营修改 `认领单销` / `不认领原因`；内容不对只能退回补充。
- 退回补充按主 SKU 组任务退回，保留运营已填内容，运营修改后重新提交。
- 退回补充必须填写原因，用于告诉运营需要补充的子 SKU / 内容。
- 退回补充后，运营可以保留旧图片、删除旧图片、追加新图片；重新提交时以当前附件列表为准。
- 财根机会池多人认领场景下，主管审核页需要展示同主 SKU 其他运营认领对比：运营、子 SKU、认领单销、审核状态。
- 主管审核页和运营认领页不新增单独“详情”按钮；点击主 SKU / 子 SKU 文本进入商品详情页，并默认定位到对应子 SKU。
- 商品详情页的返回入口放在页面标题旁，不放在商品卡片内部；刷新成功等系统状态用右上角小提示展示，不占主内容布局。

## 8. 可备货清单

- 按子 SKU 行展示。
- 暂时只负责导出清单。
- 不展示开品邮件状态。
- 只进入主管审核通过的认领子 SKU。
- 不做主 SKU 汇总页；主 SKU 只作为明细行中的分组 / 追溯字段。
- 同一次导出批次包含两个子 SKU 明细导出：
  - `备货申请表`：按 `海外仓备货申请表.xlsx` 的 16 列结构，用于下游备货操作。
  - `全字段留痕明细`：和 `备货申请表` 在同一个“主管复核通过后点击导出”环节生成；不是导入来源表，也不是人工填写表。行范围与本次备货导出的子 SKU 一致，字段先导出 `东南亚海外仓新品表-PH/TH/VN.xlsx` 中 `开发是否接受核价结果` 前的字段，再拼接平台内部认领 / 复核 / 导出字段，用于领导查看和追溯备用。
- `备货申请表` 中 `时间` 取系统写入 / 导出时间；当前已实现旧导出的 `补货原因` 留空，新备货申请填报目标为“首次备货”可空、“补货”必填。
- 主 SKU 组如果只有部分子 SKU 认领通过，主 SKU 组状态显示为“部分认领通过”，组内子 SKU 分别显示“可备货 / 已确认不认领”。
- 财根机会池多人认领通过时，同一子 SKU 可以按不同运营 / 认领任务导出多行，不合并。
- 导出批次最小元数据为导出人、导出时间、导出文件名、导出范围。
- 主管审核通过后只进入“可备货清单”，不自动生成 Excel。
- 主管 / 数据人员点击“导出”时生成导出批次；导出后相关主 SKU 组状态更新为“已导出可备货清单”。

## 9. 后续链路

- 可备货清单之后，到货承接数据优先从现有系统自动同步。
- 自动同步字段至少包括预计到货时间、实际入仓时间、仓库。
- 平台按主 SKU / 子 SKU 匹配到货记录。
- 后段默认入口需要有完整商品状态列表，按主 SKU 分组，展开看子 SKU。
- 商品状态列表展示每个商品的当前状态和健康标签：正常、需关注、异常。
- 主管可通过商品看板审视整条链路，包括运营提交的二次市场调研、竞品分析、具体调整 / 竞品监控、刊登信息、1-4周监控和四周总结。
- 暂时只监控到货是否完成和到货时间，不做到货数量不足异常。

后段流程先按以下口径设计：

```text
到货承接
-> 二次市场调研
-> 具体调整 / 竞品监控
-> 刊登确认
-> 1-4周监控
-> 四周总结
```

## 10. 二次市场调研

- 每个到货主 SKU 在刊登前都必须做一次二次市场调研。
- 二次市场调研 SLA：实际入仓后 1 天内完成。
- 二次市场调研由运营填写；主管可在商品看板 / 调研记录里查看全局结果。
- 调研结论先按“进入定价 / 失去市场”两类设计。
- 结论为“进入定价”时，直接进入具体调整 / 竞品监控，不需要主管审批。
- 结论为“失去市场”时，提交主管确认。
- 主管确认动作：不继续刊登、暂缓观察、退回补充。
- 退回补充后回到运营补充调研；不继续刊登或暂缓观察后，流程停在二次调研结论。
- 必填字段：
  - 竞品链接
  - 竞品售价
  - 销量 / 热度
  - 调研结论

## 11. 具体调整 / 竞品监控

- 二次市场调研之后进入具体调整 / 竞品监控。
- 由运营处理，不需要主管审批。
- 最终刊登售价必填后，才能进入刊登确认。
- 如果价格差异过大，先只打“需关注”标签，不阻塞流程。
- 字段：
  - 竞品链接
  - 竞品价格 / 销量
  - 产品定位
  - 原建议售价
  - 二次调研参考价
  - 最终刊登售价
  - 调价原因

## 12. 刊登确认

- 由运营填写。
- 字段：
  - ItemID
  - 刊登链接
  - 店铺
  - 售价
  - 刊登日期
- ItemID、刊登链接、售价、刊登日期必填。
- 店铺从现有店铺列表选择。
- 填完刊登日期后，从刊登日期开始生成每周监控。

## 13. 上线后每周监控

- 监控起点从刊登日期开始。
- 监控周期按刊登日期起每 7 天切分，不按自然周；刊登日期算第 1 天。
- 第 1-4 周窗口分别为第 1-7 天、第 8-14 天、第 15-21 天、第 22-28 天。
- 每周监控记录按刊登记录 / ItemID 生成；主 SKU 页面做汇总展示。
- 主 SKU 汇总口径：销量、销售额、广告费求和；库存显示所有 ItemID 当前库存合计；ROI / ACOS 按汇总后的销售额和广告费重新计算。
- 指标数据第一版以系统自动同步为主；运营只填写处理动作和备注。
- 异常标签第一版只做三类：销量低、广告异常、库存风险。
- 异常标签先打在刊登记录 / ItemID 明细上；主 SKU 汇总时，只要任一 ItemID 命中异常，就显示对应标签。
- 异常标签不额外生成待办，只在商品看板 / 每周监控列表展示和筛选；运营在周监控记录里填写处理动作和备注。
- 有异常标签的周监控记录，处理动作必填；无异常标签时处理动作可不填。
- 指标先保留：
  - 销量
  - 销售额
  - 库存
  - 广告费
  - ROI / ACOS
  - 异常标签
- 每周监控触发的调整动作由运营直接处理，不需要主管确认。
- 调整动作先做四类：
  - 调价
  - 优化刊登
  - 广告调整
  - 继续观察

## 14. 四周总结

- 由运营填写四周总结。
- 主管只看汇总结果，不做确认流程。
- 刊登日期后第 28 天自动生成四周总结记录，运营填写总结。
- 不生成钉钉待办；系统内生成四周总结记录 / 待填写项，并发送钉钉推送入口。
