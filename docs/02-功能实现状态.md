## 1. 第一版冻结范围

第一版已经确认冻结为：

```text
两张内部反馈表导入
  -> 主管一键分配 / 调整分配
  -> 运营认领或不认领
  -> 主管复核
  -> 运营填写 / 提交备货申请
  -> 主管勾选导出 Excel
```

第一版不做：

- 在线表自动写回入口。
- 中间桥 / 采购 / 供应链 / 下单待办。
- 匹配异常清单流程。
- 选品3、选品4、直发转海外仓、老品来源。
- 钉钉待办。

## 4. 最新导出实现

正式备货申请按 A-P 共 16 列导出；字段顺序、业务校验和 ERP 体积降级的唯一业务真源见 `docs/2026-07-09-已确认需求记录.md`。服务端计算备货数量、货值和总体积，保存最终申请快照及体积来源，主管不能代填运营申请；开发部署已支持填写长 / 宽 / 高（cm），并由服务端重新计算单个体积。

`新品中央字段导出`：

- 行粒度：当前 `submitted + waiting_export` 的子 SKU 申请，加上已确认不认领的追溯行。
- 字段：中央表 A-CB 共 80 个字段（包含 `开发是否接受核价结果`）+ 平台认领/复核/导出字段。
- 用途：领导查看和追溯，不是在线表写回。

导出边界：

- 当前开发部署 `b0f27fde5109` 的正式备货导出只处理主管勾选的已提交申请；按业务期重复导出仅作为历史行为保留在旧版本记录中。
- 正式备货导出只列出 `request.status=submitted` 且 claim 为 `waiting_export` 的申请；主管提交非空、去重的 `request_ids`，服务端整批校验后生成一次不可变 `stocking_available` 快照。
- 导出成功后所选申请转为 `exported`、claim 转为 `waiting_arrival`，不再出现在待导出列表；任何一条校验失败则整批不导出。
- `全字段留痕明细` 是独立导出，不代替正式备货申请、不共享同一导出动作，也不推进到货状态。
- 原实现头 `41080bc` 已随 `lxc/pricing-review-edit` 合入统一分支；当前开发部署为 `b0f27fde5109`。新品流程生产环境仍为 `b373d65`，未部署本次备货申请和后半段开发能力。

## 7. 下一步建议

如果继续开发，不要再回头问“第一版是不是只导出”。直接按这个顺序推进：

1. 与业务确定切入业务期；该期起所有新增机会平台先行，停止继续在旧表和平台双录。
2. 对两份历史市场监控表只生成只读对账报告；确认 A:AR 字段合同、重复冲突和历史完成时间规则后，才允许只补平台空值的受控导入。
3. 下一笔正式备货导出后，用真实 PLM 到货做一次当前精确门槛的一对一写入 UAT；持久自动化和发卡继续关闭。
4. 取得周 Item 内部接口、鉴权和未过滤样例后，再接真实取数、调度与失败重试。
5. 汇总实际使用反馈和开放风险后再申请生产窗口；生产变更另行审批。
