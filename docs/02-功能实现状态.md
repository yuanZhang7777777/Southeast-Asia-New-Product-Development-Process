## 1. 第一版冻结范围

第一版已经确认冻结为：

```text
两张内部反馈表导入
  -> 主管一键分配 / 调整分配
  -> 运营认领或不认领
  -> 主管复核
  -> 导出 Excel
```

第一版不做：

- 在线表自动写回入口。
- 中间桥 / 采购 / 供应链 / 下单待办。
- 匹配异常清单流程。
- 选品3、选品4、直发转海外仓、老品来源。
- 钉钉待办。

## 4. 最新导出口径

`备货申请表`：

| 字段 | 来源/逻辑 |
|---|---|
| `操作状态` | 第一版不写，留空 |
| `时间` | 系统导出时间 |
| `备货类型` | 新品开发流程导出，可按当前实现默认 |
| `选品数据源` | 平台来源：选品1或选品2/财根 |
| `销售员` | 通过主管复核的运营 |
| `主SKU` / `子sku` | 源表字段 |
| `成本价` | 选品1取 `商品成本-含税（元）`；选品2取 `进价` |
| `单个体积` | 选品1取 `包装后体积`；选品2能可靠映射才写，否则空 |
| `备货单销` | 平台复核通过的 `认领单销` |
| `备货数量` | `认领单销 × 30` |
| `备货国家` / `备货仓库` | 由站点/国家映射 |
| `货值` | `成本价 × 备货数量` |
| `体积` | `单个体积 × 备货数量` |
| `补货原因` | 第一版不写，留空 |

`新品中央字段导出`：

- 行粒度：通过复核的子 SKU 明细。
- 字段：中央表 73 个开发字段 + 平台认领/复核/导出字段。
- 用途：领导查看和追溯，不是在线表写回。

## 7. 下一步建议

如果继续开发，不要再回头问“第一版是不是只导出”。直接按这个顺序推进：

1. 重跑后端测试和前端构建。
2. 启动本地服务，使用本地演示数据脚本检查全状态页面。
3. 用少量真实 `选品1`、`选品2` 文件跑端到端导入到导出。
4. 对照原型和最新需求修 UI 细节。
5. 准备云服务器部署和生产配置。
