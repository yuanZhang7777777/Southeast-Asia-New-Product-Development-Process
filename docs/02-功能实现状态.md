## 1. 第一版冻结范围

第一版已经确认冻结为：

```text
两张内部反馈表导入
  -> 主管一键分配 / 调整分配
  -> 运营认领或不认领
  -> 主管复核
  -> 导出 Excel
```

第一版不做：

- 在线表自动写回入口。
- 中间桥 / 采购 / 供应链 / 下单待办。
- 匹配异常清单流程。
- 选品3、选品4、直发转海外仓、老品来源。
- 钉钉待办。

## 4. 最新导出口径

`备货申请表`：

| 字段 | 来源/逻辑 |
|---|---|
| `操作状态` | 第一版不写，留空 |
| `时间` | 系统导出时间 |
| `备货类型` | 新品开发流程导出，可按当前实现默认 |
| `选品数据源` | 平台来源：选品1或选品2/财根 |
| `销售员` | 通过主管复核的运营 |
| `主SKU` / `子sku` | 源表字段 |
| `成本价` | 选品1取 `商品成本-含税（元）`；选品2取 `进价` |
| `单个体积` | 选品1取 `包装后体积`；选品2能可靠映射才写，否则空 |
| `备货单销` | 平台复核通过的 `认领单销` |
| `备货数量` | `认领单销 × 30` |
| `备货国家` / `备货仓库` | 由站点/国家映射 |
| `货值` | `成本价 × 备货数量` |
| `体积` | `单个体积 × 备货数量` |
| `补货原因` | 第一版不写，留空 |

`新品中央字段导出`：

- 行粒度：通过复核的子 SKU 明细。
- 字段：中央表 73 个开发字段 + 平台认领/复核/导出字段。
- 用途：领导查看和追溯，不是在线表写回。

按期重复导出：

- 同一业务期数每次下载都包含下载时全部仍有效、主管已通过的记录；中央字段追溯表同时包含已确认不认领记录。
- 每次下载创建新的导出批次及行审计；首次下载仍按既有流程推进，重复下载不回退或重复推进已经进入后续状态的记录。
- 新建及批量复核记录按认领明细写入 `claim_record_id`；历史空范围的通过复核适用于复核时已存在的全部认领，确认不认领和退回补充只指向当时最新的平台认领提交。
- 原实现头 `41080bc` 已随 `lxc/pricing-review-edit` 合入统一分支；当前开发部署为 `b564815`。新品流程生产环境未部署按期重复导出和后半段功能。

## 7. 下一步建议

如果继续开发，不要再回头问“第一版是不是只导出”。直接按这个顺序推进：

1. 在开发地址用少量 `选品1`、`选品2` 数据完成前后段业务验收。
2. 取得周 Item 内部接口地址、鉴权方式和原始聚合字段样例后，再接入自动调度和失败重试。
3. 观察真实运营和主管使用反馈后只做局部调整。
4. 生产变更另行安排窗口，绝不在用户使用期间重启生产。
