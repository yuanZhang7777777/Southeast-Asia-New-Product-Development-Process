## 1. 第一版冻结范围

第一版已经确认冻结为：

```text
两张内部反馈表导入
  -> 主管一键分配 / 调整分配
  -> 运营认领或不认领
  -> 主管复核
  -> 导出 Excel
```

第一版不做：

- 在线表自动写回入口。
- 中间桥 / 采购 / 供应链 / 下单待办。
- 匹配异常清单流程。
- 选品3、选品4、直发转海外仓、老品来源。
- 钉钉待办。

## 4. 最新导出口径

`备货申请表`：

| 字段 | 来源/逻辑 |
|---|---|
| `操作状态` | 第一版不写，留空 |
| `时间` | 系统导出时间 |
| `备货类型` | 新品开发流程导出，可按当前实现默认 |
| `选品数据源` | 平台来源：选品1或选品2/财根 |
| `销售员` | 通过主管复核的运营 |
| `主SKU` / `子sku` | 源表字段 |
| `成本价` | 选品1取 `商品成本-含税（元）`；选品2取 `进价` |
| `单个体积` | 选品1取 `包装后体积`；选品2能可靠映射才写，否则空 |
| `备货单销` | 平台复核通过的 `认领单销` |
| `备货数量` | `认领单销 × 30` |
| `备货国家` / `备货仓库` | 由站点/国家映射 |
| `货值` | `成本价 × 备货数量` |
| `体积` | `单个体积 × 备货数量` |
| `补货原因` | 第一版不写，留空 |

`新品中央字段导出`：

- 行粒度：通过复核的子 SKU 明细。
- 字段：中央表 73 个开发字段 + 平台认领/复核/导出字段。
- 用途：领导查看和追溯，不是在线表写回。

按期重复导出：

- 同一业务期数每次下载都包含下载时全部仍有效、主管已通过的记录；中央字段追溯表同时包含已确认不认领记录。
- 每次下载创建新的导出批次及行审计；首次下载仍按既有流程推进，重复下载不回退或重复推进已经进入后续状态的记录。
- 本轮未发生数据库迁移、Excel 模板变更、生产部署或开发部署。`lxc/listing-observation-workbench` 保持独立分叉，未合并或覆盖；分支整合与发布另行处理。

## 7. 下一步建议

如果继续开发，不要再回头问“第一版是不是只导出”。直接按这个顺序推进：

1. 每次发布前重跑前端测试/构建和后端完整测试。
2. 生产发布继续使用候选容器健康检查和 Caddy 原子切换，不重启 PostgreSQL、Redis、worker 或 scheduler。
3. 用少量可控的 `选品1`、`选品2` 数据复核导入到导出前状态，避免用真实批量业务写操作做冒烟测试。
4. 观察不同运营同时填写和主管筛选/分配的真实使用反馈，再做局部界面调整。
5. 保持钉钉 userId、账号角色、推送日志和生产备份的日常巡检。
