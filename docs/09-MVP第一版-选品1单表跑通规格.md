# MVP 第一版 · 选品1 单表跑通规格（Codex 实施用）

> 日期：2026-06-29  
> 状态：实施规格，交 Codex 实现，Claude 验收  
> 目标：用 **选品1（海外仓开发部门开发新品认领-反馈）单张源表**，跑通 MVP 前段：`入池 → 主管分配 → 销售认领 → 主管审核 → 出可备货清单`。  
> 边界：平台代码归 Codex；本文件是规格。其余源表、钉钉对接、部署都不在本次范围。

## 0. 关键口径（来自已确认结论）

- 框架 = 两段 + 一桥；本次只做 **前段，止于“出可备货清单”**。
- 角色：销售 = 运营；主管 = 运营负责人。
- 入池粒度：源表按 **子 SKU 为记录，主 SKU 分组**；流程任务按 **主 SKU 组** 走。
- 状态模型采用两层：主 SKU 组记录任务流转状态，子 SKU 记录认领结果状态。
- `选品1` 任务必须由主管分配后才生成销售认领任务，不做销售自领。
- 备货量 = **子 SKU 认领单销 × 30**（销售自己填每个认领子 SKU 的认领单销）。
- `认领单销 × 30` 是当前暂定计算口径，后续需要和业务人员复核。
- 不认领原因 = 自定义文本；整组不认领时填写主 SKU 组级原因，部分子 SKU 不认领时可填写对应原因。
- 不认领也必须进入主管审核，不允许在前端审核队列中消失。
- 商品图片、备注截图和市场调研证据是审核依据，第一版必须可见。

## 3. 入池规则

- 子 SKU(J) 为一条记录；主 SKU(H) 用于分组。
- **去重**：`source_file + source_sheet + source_row`（现有唯一约束 `uq_opportunity_source_row`），importer 可重复跑、幂等。
- 每行存一份整行快照到 `source_record_snapshot` / `opportunity.snapshot`。
- **跳过无效行**：H 主SKU 或 J 子SKU 为空、或整行为小计/空行的，不入池。

## 4. 跑通前段（用现有骨架）

1. **入池**：importer 落库 → 机会列表（按主 SKU 分组展示，站点过滤）。
2. **主管分配**：所有 `选品1` 数据先进机会池；源表 CD 不参与推荐，主管确认后才生成销售认领任务。
3. **认领 / 不认领**：销售按主 SKU 组处理，展开子 SKU 明细；认领子 SKU 的平台认领单销必填，整组或部分不认领时填写平台不认领原因。源表 CE/CF/CC/CG/CH 不预填业务表单，状态完全以平台提交为准。
4. **审核**：认领和不认领都生成 review 任务。认领任务主管可通过认领或退回补充；不认领任务主管可确认不认领或退回补充。退回补充后原主 SKU 组任务变为“待补充”，保留已填内容，销售修改后重新提交。
5. **减法（务必一起改）**：审核通过 **不再自动按 ×30 建 `stocking_request`**（现 `backend/app/services.py:182` 的 `create_stocking_draft_from_claim` 要改）——改成把机会标记为“可备货”，进入第 5 节导出。

状态模型：

- 主 SKU 组状态用于分配、认领、审核、待补充、部分通过等流程流转。
- 子 SKU 状态用于记录该子 SKU 的认领结果：通过后进入可备货清单，确认不认领后不导出。
- 主 SKU 组为“部分认领通过”时，只表示组内子 SKU 结果不一致；导出仍按子 SKU 行判断。
- 主 SKU 组状态枚举：待分配、待认领、待主管审核、待补充、认领通过、部分认领通过、已确认不认领、已导出可备货清单。
- 子 SKU 认领结果状态枚举：未处理、可备货、已确认不认领。
- 提交前的子 SKU 勾选、取消勾选、单销填写只作为当前页面表单状态，不单独落成子 SKU 状态。
- 提交前不写数据库，不做后端草稿保存；刷新、关闭页面或换设备后，未提交内容不保证保留。
- 点击提交时校验：认领的子 SKU 必填认领单销；不认领的子 SKU 必填不认领原因；校验不通过不能进入主管审核。
- 只有点击提交时，才写入平台并进入主管审核。
- 补充材料 / 截图可选；没有附件也允许提交。
- 图片附件支持点击选择、拖拽到上传区、从剪贴板粘贴图片；提交时随表单一起写入平台。
- 图片附件仅支持 JPG / PNG / WebP / GIF，单张不超过 20MB，不限制数量。
- 退回补充后，销售可以保留旧图片、删除旧图片、追加新图片；重新提交时以当前附件列表为准。
- `已导出可备货清单` 只适用于存在认领通过子 SKU 的主 SKU 组；导出后不覆盖子 SKU 认领结果。

审核页展示要求：

- 认领审核：展示商品图、主 SKU 组、子 SKU 明细、开品理由、竞品链接、认领单销、销售反馈。
- 不认领审核：展示商品图、不认领原因、销售反馈总结、备注文字、备注截图/附件、竞品链接。
- 主管确认不认领后，对应子 SKU 不进入可备货清单；若同一主 SKU 组内还有子 SKU 通过认领，主 SKU 组显示“部分认领通过”。
- 退回补充按主 SKU 组退回，备注可填可不填。
- 前端所有节点、角色、状态、任务类型必须展示中文，不得直接展示内部编码。

## 6. 验收标准（Claude 审）

1. 导入 `开发0623期`：入池机会数 = 有效数据行数；重复跑不产生重复（去重生效）。
2. 来源快照保留 `A:BX` 及 `CC:CH` 追溯字段；选品1 `CC:CH` 不生成认领业务记录。
3. 子 SKU 为记录、主 SKU 分组、站点取自 A 列正确。
4. 认领→审核走得通；**审核通过不再自动建 stocking_request**。
5. 导出可备货清单 Excel：备货量 = 认领单销 × 30；成本/货值列留空；含开品邮件两列。
6. 无效/空行被正确跳过。
7. F 列产品图片在机会池、销售认领、主管审核三处可见；缺图有占位。
8. 运营在平台上传的调研图片可在运营修改页恢复，并在主管审核页追溯。
9. 不认领提交后必须出现在主管审核列表，主管能看到不认领原因和证据；主管确认后不进入可备货清单。
10. 机会池和分配台支持按主 SKU、子 SKU、关键词、站点、一级类目、销售员、状态搜索/筛选。
11. 分页可用且不影响搜索结果，默认页大小不低于 50。
12. 待办、机会池、认领、审核页面不得出现 `sales_claim`、`sales`、`pending`、`claim_rejected` 等内部编码。
13. `选品1` 不存在销售自领入口；所有源表数据必须先由主管分配。
14. CD 有值、CE/CF/CC/CG/CH 有值都只能保留在来源快照，不生成任务、不进入推荐、不预填认领表单。
15. 部分子 SKU 认领通过时，只导出通过的子 SKU 行，并保留主 SKU 组的部分通过状态。
16. 状态必须支持两层表达：主 SKU 组任务状态 + 子 SKU 认领结果状态。
17. 主 SKU 组状态必须支持：待分配、待认领、待主管审核、待补充、认领通过、部分认领通过、已确认不认领、已导出可备货清单。
18. 子 SKU 认领结果状态只保留：未处理、可备货、已确认不认领；提交前选择不作为状态。
19. 认领页提交前不写数据库；未提交内容只作为当前页面表单状态，点击提交后才写入平台并进入主管审核。
20. 提交校验：认领子 SKU 必填认领单销，不认领子 SKU 必填不认领原因；反馈 / 备注不做必填。
21. 补充材料 / 截图可选；图片支持点击选择、拖拽上传、剪贴板粘贴。
22. 图片附件仅支持 JPG / PNG / WebP / GIF，单张不超过 20MB，不限制数量。
23. 退回补充后，附件可保留、删除或追加；重新提交以当前附件列表为准。
24. 可备货清单不自动生成 Excel；点击导出时生成导出批次，并把相关主 SKU 组更新为“已导出可备货清单”。
