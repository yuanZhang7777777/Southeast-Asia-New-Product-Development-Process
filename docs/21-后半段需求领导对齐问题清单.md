# 后半段需求领导对齐问题清单

> 目的：只整理已经确认的后半段口径和仍需领导拍板的问题。不要把推测写成已确认。

## 1. 已确认口径

- 平台前段商品在“备货申请导出”后仍进入 `waiting_arrival`，用于商品看板追踪；但“到货通知”的名单不依赖平台备货导出、认领或复核记录。
- 测试阶段边界（2026-07-10）：PLM 只允许下载、缓存和核验字段，不创建真实运营待办，不向运营发送到货钉钉卡片；必须由业务明确确认“正式启用”后，才能开放真实待办和推送。
- 后半段固定顺序：`PLM 每日筛选与销售归属 -> 到货提醒 -> 二次调研待办 -> 具体调整 / 竞品监控 -> 刊登确认 -> 1-4 周监控 -> 四周总结 / 后续动作`。到货提醒负责通知对应运营，二次调研待办负责承接后续填写，不能颠倒成“先有待办再提醒到货”。
- PLM 到货候选规则：`集团=集团八部 + 最后一次入库时间=北京时间前一天`。以 PLM 公司端数据为准，不要求子 SKU 已经存在于本平台。
- 老品补货不发送“新品到货通知”。`最后一次入库时间=前一天`只能筛出候选，不能单独作为“新品首次到货”的最终判定。
- 新品首次到货最终判定：PLM `AL=最后一次入库时间`与`AM=首次上架时间`按北京时间取日期后相同；AL 或 AM 缺失、日期不同的记录不发送新品到货通知。
- 2026-07-10 已用真实集团八部文件验证：2143 条明细中，AL/AM 同一天 18 条、不同天 2124 条、AL 缺失 1 条、AM 无缺失。该分布符合“同一天为首次到货、不同天为老品补货”的业务判断，测试阶段按此规则执行。
- 到货通知按 `到货日期 + 子 SKU + 国家 + PLM销售员` 去重；同一销售员、子 SKU、国家下的多仓记录合并成一个通知项，仓库明细保留展示。
- 某个`子 SKU + 国家`一旦确认并记录过首次到货，后续`最后一次入库时间`因补货更新时只更新库存信息，不再发送新品到货通知。
- 到货通知接收人取 PLM `销售员`，再通过集团八部人员配置映射启用状态、站点和钉钉身份；不再回退使用平台认领负责人。人员缺失或站点冲突时进入主管异常预览，不自动发给其他人。
- `海外仓可发`、`海外仓在途`、`公共池库存`作为通知和详情参考数据，不作为到货触发条件。
- PLM 来源的二次调研任务粒度为 `PLM到货记录ID + 子 SKU + 国家 + 销售员`；若平台内已有同子 SKU 记录则建立关联，没有则创建 PLM 来源的到货档案，不阻断通知。
- 备货导出后进入 `waiting_arrival`，集成在现有商品看板状态里展示，不新建单独页面。
- 运营只看自己负责的后半段商品；主管 / 管理员可看全部。
- 市场监控表 `A 调研时间`：平台导入 / 分配的新品任务，按 `B 货品` 期数日期后一天默认生成，例如 `开发新品0609期` -> `6.10`；其他来源如运营自己开的品，由销售 / 运营自己填写。
- 市场监控表 `B 货品`：平台导入 / 分配的新品任务，由系统按来源和期数生成，例如 `开发新品0609期`、`开发新品0629期`；其他来源按来源规则或由销售 / 运营填写。
- 市场监控表 `I 二级类目`：第一版允许为空，暂不做自动补齐；后续如果业务需要，再从 ERP 产品列表下载匹配。
- 市场监控表 `J 海外仓成本`：优先从导入源表按表头匹配，不按固定列号。`选品1` 优先匹配 `商品成本-含税（元）`，`选品2` 优先匹配 `进价`；找不到则导出留空并记录缺失来源。
- 市场监控表 `K 真实头程运费`：`选品1`、`选品2` 两类新品开发数据源没有真实头程，第一版导出留空；后续导入老品数据源且源表有真实头程字段时，才按表头匹配带入。PLM `头程费用` 不写入 K。
- 市场监控表 `L 计算头程`：到货后每日 PLM 同步时，如果实际下载表头存在 `头程费用` 且值非空，则写入 L；如果 PLM 没有该字段或该值为空，则用 `M*N*O/1000000*820` 计算；M/N/O 不足时 L 留空。当前 PLM 样例只证明曾出现 `头程费用` 表头，正式同步仍按实际表头判断。
- 市场监控表 `AD-AI`：按目标字段名 / 语义从上游源表或中央新品表匹配，不按固定列号匹配。`产品类型 + AJ/AL/AM/AO/AP` 只作为部分历史 sheet 的位置参考；实际导入 / 导出以表头含义为准，字段位置变了也要识别。
- `直发热销转海外仓` 数据源：后续导入时第一步只导入源表 `A-O` 字段；`P` 列及之后字段的来源、填写人、流转逻辑后续再对齐。
- 二次调研 `AL-AO` 都允许选择性填写；字段为空时导出保持空。
- `AL 调研时间` 由系统记录运营点击“确认已调研”的提交时间。
- 运营可以只按主 SKU 填一份调研内容，再批量应用到选中的子 SKU。
- 运营点击“确认已调研”即可完成二次调研，字段可以全空。
- 只有 `AO=淘汰款` 时，才触发主管外部产品定位调整提醒。
- 市场监控表 `G 商品名称` 由平台源数据按 `主 SKU + 子 SKU` 定位取得；PLM 商品名称只做补齐 / 校验。
- 市场监控表 `R-Z` 竞品字段能映射就带入；`选品2` 不完整也没关系，缺失留空。
- 市场监控表 `AK 调研结论` 来自前段运营第一次认领 / 不认领时填写的“调研结论”，对应平台认领记录 `feedback_summary`；该字段可选，不强制每个 SKU 填写。
- 商品详情页的“市场调研”主来源是选品1源表 `Z-AN` 字段；`AO-AV` 作为价格 / 毛利参考字段展示，不能和市场调研字段混成同一来源口径。
- 商品详情页按子 SKU 查看全局档案：市场调研、价格 / 毛利参考、认领与复核、源表字段与来源追溯都围绕当前选中的子 SKU 展示。
- 选品1字段展示 / 结构化导入不按固定列号硬取；市场调研、价格 / 毛利参考等字段优先按表头语义匹配，匹配不到时才按历史列号兜底。
- 商品详情页分区口径：`A-L` 为基础信息，`M-Y` 为开发询价 / 规格成本，市场调研按表头匹配历史 `Z-AN` 兜底，价格 / 毛利参考按表头匹配历史 `AO-AV` 兜底，`AQ-BR` 作为成本参数分区展示。
- 分配推荐必须先按站点硬隔离：同主 SKU 如果存在不同国家 / 站点的子 SKU，推荐分配时也要拆成不同站点任务；品类不命中时只在同站点候选人里按负载均衡，不能把泰国品分给越南运营。
- 商品详情页必须能从商品看板、运营认领、主管复核进入；从子 SKU 任务进入时默认定位到该子 SKU。
- 商品详情页 `认领与复核` 里的运营列只显示实际认领 / 不认领提交人；没有提交记录时显示空，不能回退展示开发员。
- 商品详情页返回入口放在页面标题旁，不放在商品卡片内部；档案分区选择尽量上移并保持紧凑。
- 刷新成功等非阻断系统状态用右上角小提示，不在主内容区占一整行。
- 运营认领页和主管复核页点击主 SKU / 子 SKU 文本进入商品详情页，不额外新增重复的详情按钮。
- 从运营认领或主管复核进入商品详情再返回时，未提交草稿和已选复核动作不能被清空；刷新、关闭页面或换设备不承诺保留。
- 二次调研确认后，运营可以直接在外部平台刊登。
- `【推品】海外仓精品流程.xlsx` 是刊登后运营陆续填写 / 跟进的表，不是刊登前必须完成的动作。

## 2. PLM 每日获取技术口径

> 本节记录可复用的获取方式，不记录真实账号、密码或 Token。运行凭据只放服务器 `.env` 的 `PLM_USERNAME`、`PLM_PASSWORD`。

- 服务地址：`PLM_BASE_URL=http://103.198.125.2:7878`。
- 当前项目使用 `PLM_BLOC_NAME=集团八部`。2026-07-10 已完成一次真实导出核验：工作簿 `汇总表格` 共 44 列，`集团` 列去重后只有 `集团八部`。
- 每天北京时间 `08:00` 获取前一天数据。日期窗口为当天 `00:00:00+08:00` 到 `23:59:59+08:00` 的毫秒时间戳。
- PLM 不是直接返回 Excel，而是异步流程：登录获取 Token -> 读取下载中心已有记录 -> 创建库存明细导出任务 -> 轮询下载中心 -> 下载 MinIO 文件。
- 登录：`POST /api/system/login`，后续请求只带 `authorization: <token>`；不依赖浏览器 Cookie、`Origin` 或 `Referer`，每次完整重试都重新登录。
- 下载中心：`POST /api/hz-inventory/minioDownloadFile/selectPage`。创建任务前记录已有 `id`，防止误取历史文件。
- 创建导出：`POST /api/hz-inventory/overseas/details/exportSummaryExcel`，请求中的 `blocNameList` 使用 `PLM_BLOC_NAME`，时间使用上述北京时间窗口。
- 每 10 秒轮询一次，最多 10 分钟。只接受 `status=2`、存在 `downloadUrl`、`id` 不在任务前快照中、文件名 13 位时间戳不早于任务创建前 60 秒的记录。
- 文件下载后先用 Excel 解析器验证，再原子写入 `PLM_CACHE_DIR/plm-YYYY-MM-DD.xlsx`。有效缓存直接复用；无效或缺失缓存重新执行完整流程。
- 单次任务失败后等待 5 分钟，从重新登录开始完整重试，直到成功。历史日期补数必须串行，避免多个异步导出混在下载中心。
- 首份真实文件已确认存在 `子SKU`、`主SKU`、`国家`、`海外仓`、`集团`、`单销`、`海外仓在途`、`海外仓可发`、`公共池库存`、`最后一次入库时间`、`首次上架时间`、`头程费用` 等表头。
- 文件同时存在 `本地海外仓可发` 和 `海外仓可发`。根据本文件第 1 节已确认口径，到货待办触发使用精确表头 `海外仓可发 > 0`，不能误用 `本地海外仓可发`。
- 当前实现边界已到“每天稳定取得并校验集团八部 Excel”。下一步按 `认领记录ID + 子 SKU + 国家` 匹配备货导出记录；多仓库存的展示 / 汇总口径仍按第 4 节问题 6 待确认，不提前求和。

## 3. “刊登确认”目前是什么意思

“刊登确认”不是已确认业务动作，只是一个待定义的平台承接点。

如果后续要做，它的最小含义是：系统需要知道某条 `认领记录ID + 子 SKU + 国家` 已经在外部平台刊登，从而可以开始生成 / 关联 `【推品】海外仓精品流程.xlsx` 的基础行和后续 1-4 周监控。

它可能有三种实现方式：

- 方式 A：运营在商品看板 / 到货任务详情里点击“已刊登”，录入店铺、Item、操作日期等字段。
- 方式 B：主管 / 管理员批量导入刊登信息，系统据此标记已刊登。
- 方式 C：不在平台做刊登确认，只通过飞书表格 / 推品表外部维护，平台暂不生成推品流程记录。

当前不能把方式 A 写成已确认，需要领导确认。

## 4. 需要领导确认的问题

### 市场监控表

2. `AC/AF/AG/AI 毛利相关字段` 是复制前段结果，还是平台按市场监控公式重算？如果重算，汇率、平台扣点、固定费用参数是什么？

4. `AQ-AW 公司口径字段` 是否每天取 PLM 最新值？表头里的日期是否跟着同步日期自动变化？
5. `AX-AZ 集团八部字段` 是否按 `集团=集团八部` 过滤后，以 `子 SKU + 国家` 汇总？多仓、多销售员时如何合并？

7. 最终导出的市场监控 Excel 是否必须保持现有 sheet 名、sheet 顺序、列顺序和表头完全一致？
