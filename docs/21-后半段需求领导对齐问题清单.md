## 1. 已确认口径

- 标准备货链路为：主管复核通过后按“销售员 + 子 SKU”生成备货申请草稿，运营填写并提交，主管勾选已提交申请导出；导出成功后申请转为已导出，负责人记录进入 `waiting_arrival`，用于商品看板追踪。
- 测试阶段边界（2026-07-10，2026-07-22 补充）：正式 PLM 流程只允许下载、缓存和核验字段，不创建真实运营待办，不向运营批量发送；唯一例外是用户批准的开发历史关注试运行，只向刘学城发送命中卡且不写业务表。正式待办和其他人员推送仍须另行确认启用。
- 后半段固定顺序：`PLM 每日筛选与销售归属 -> 到货提醒 -> 二次调研待办 -> 具体调整 / 竞品监控 -> 刊登确认 -> 1-4 周监控 -> 四周总结 / 后续动作`。到货提醒负责通知对应运营，二次调研待办负责承接后续填写，不能颠倒成“先有待办再提醒到货”。
- 销售自选商品由运营自行到公司系统判断库存并选择三条分支：①已有可用库存且不备货，跳过备货申请、待到货和二次调研，直接进入待刊登；②无可用库存且备货，生成草稿并走“填写提交 -> 主管勾选导出 -> 待到货”；③无可用库存且不备货，进入可恢复的 `暂不推进`，不生成后续任务，后续可改为备货继续。该例外不改变选品1/选品2标准链路。
- 备货申请中的 `备货仓库`为可选自由文本，不提供默认值或建议值；运营可留空提交，主管在导出的外部表中补填。
- PLM 到货候选规则：`集团=集团八部 + 最后一次入库时间=北京时间前一天`。以 PLM 公司端数据为准，不要求子 SKU 已经存在于本平台。
- 老品补货不发送“新品到货通知”。`最后一次入库时间=前一天`只能筛出候选，不能单独作为“新品首次到货”的最终判定。
- 新品首次到货最终判定：PLM `AL=最后一次入库时间`与`AM=首次上架时间`按北京时间取日期后相同；AL 或 AM 缺失、日期不同的记录不发送新品到货通知。
- 2026-07-10 已用真实集团八部文件验证：2143 条明细中，AL/AM 同一天 18 条、不同天 2124 条、AL 缺失 1 条、AM 无缺失。该分布符合“同一天为首次到货、不同天为老品补货”的业务判断，测试阶段按此规则执行。
- 到货通知按 `到货日期 + 子 SKU + 国家 + PLM销售员` 去重；通知始终按 PLM 销售员隔离，只通知各自负责的人，不跨运营合并。同一运营、子 SKU、国家下的多仓明细可在该运营自己的通知项内汇总展示。
- 某个`子 SKU + 国家`一旦确认并记录过首次到货，后续`最后一次入库时间`因补货更新时只更新库存信息，不再发送新品到货通知。
- 到货通知接收人取 PLM `销售员`，再通过集团八部人员配置映射启用状态、站点和钉钉身份；不再回退使用平台认领负责人。人员缺失或站点冲突时不自动发给其他人，也不创建未确认的“主管异常列表”；具体故障处理方式仍待确定。
- `海外仓可发`、`海外仓在途`、`公共池库存`作为通知和详情参考数据，不作为到货触发条件。
- PLM 来源的二次调研任务粒度为 `PLM到货记录ID + 子 SKU + 国家 + 销售员`；若平台内已有同子 SKU 记录则建立关联，没有则创建 PLM 来源的到货档案，不阻断通知。
- 平台备货商品采用精确关联：只考虑负责人状态为 `waiting_arrival`、存在 `stocking_available` 导出批次 `ExportRow` 且备货申请已导出的记录，再按 `PLM 销售员 + 子 SKU + ExportRow 导出快照国家` 匹配。国家取导出快照，不取后续可能变化的商品当前站点；该能力已部署开发环境，待控制数据写入式 UAT。
- 上述精确关联只用于新品流程平台把 PLM 行挂接到已导出的备货商品；独立到货通知程序仍按 PLM 销售员生成通知名单，不以平台认领、复核或导出状态作为发卡前提。
- 备货导出后进入 `waiting_arrival`，集成在现有商品看板状态里展示，不新建单独页面。
- 运营只看自己负责的后半段商品；主管 / 管理员可看全部。
- 市场监控表 `A 调研时间`：平台导入 / 分配的新品任务，按 `B 货品` 期数日期后一天默认生成，例如 `开发新品0609期` -> `6.10`；其他来源如运营自己开的品，由销售 / 运营自己填写。
- 市场监控表 `B 货品`：平台导入 / 分配的新品任务，由系统按来源和期数生成，例如 `开发新品0609期`、`开发新品0629期`；其他来源按来源规则或由销售 / 运营填写。
- 市场监控表 `I 二级类目`：第一版允许为空，暂不做自动补齐；后续如果业务需要，再从 ERP 产品列表下载匹配。
- 市场监控表 `J 海外仓成本`：优先从导入源表按表头匹配，不按固定列号。`选品1` 优先匹配 `商品成本-含税（元）`，`选品2` 优先匹配 `进价`；找不到则导出留空并记录缺失来源。
- 市场监控表 `K 真实头程运费`：`选品1`、`选品2` 两类新品开发数据源没有真实头程，第一版导出留空；后续导入老品数据源且源表有真实头程字段时，才按表头匹配带入。PLM `头程费用` 不写入 K。
- 市场监控表 `L 计算头程`：到货后每日 PLM 同步时，如果实际下载表头存在 `头程费用` 且值非空，则写入 L；如果 PLM 没有该字段或该值为空，则用 `M*N*O/1000000*820` 计算；M/N/O 不足时 L 留空。当前 PLM 样例只证明曾出现 `头程费用` 表头，正式同步仍按实际表头判断。
- 市场监控表 `AD-AI`：按目标字段名 / 语义从上游源表或中央新品表匹配，不按固定列号匹配。`产品类型 + AJ/AL/AM/AO/AP` 只作为部分历史 sheet 的位置参考；实际导入 / 导出以表头含义为准，字段位置变了也要识别。
- `直发热销转海外仓` 数据源：后续导入时第一步只导入源表 `A-O` 字段；`P` 列及之后字段的来源、填写人、流转逻辑后续再对齐。
- 二次调研 `AL` 由系统在提交时自动记录并只读展示，不允许运营手填或纠错；`AM` 改名为锚定链接并复用原二次竞对链接字段，选填；`AN` 二次调研结论必填；`AO` 产品定位必选；新增目标单销和卖点总结，提交必填。
- `AO` 只允许 `引流款 / 利润款 / 淘汰款 / 稳定款 / 清仓款`。
- 运营可以先按主 SKU 填一份调研内容，再批量应用到选中的子 SKU；应用后各子 SKU 仍可独立修改。
- 二次调研按主 SKU 整组提交，存在必填项未完成的子 SKU 时不得提交。
- `AO=淘汰款` 或 `AO=清仓款` 的子 SKU 不进入刊登；`AO=引流款 / 利润款 / 稳定款` 的子 SKU 进入待刊登。只有淘汰款通知主管，清仓款不通知；淘汰款按每天北京时间 `10:00` 左右汇总提醒。
- 平台只负责把淘汰款通知给主管，不接入或写回主管使用的外部系统，不建设“外部定位已处理”按钮、状态或待办；通知发送成功即完成平台责任，失败继续重试。
- 市场监控表 `G 商品名称` 由平台源数据按 `主 SKU + 子 SKU` 定位取得；PLM 商品名称只做补齐 / 校验。
- 市场监控表 `R-Z` 竞品字段能映射就带入；`选品2` 不完整也没关系，缺失留空。
- 市场监控表 `AK 调研结论` 来自前段运营第一次认领 / 不认领时填写的“调研结论”，对应平台认领记录 `feedback_summary`；该字段可选，不强制每个 SKU 填写。
- 商品详情页的“市场调研”主来源是选品1源表 `Z-AN` 字段；`AO-AV` 作为价格 / 毛利参考字段展示，不能和市场调研字段混成同一来源口径。
- 商品详情页按子 SKU 查看全局档案：市场调研、价格 / 毛利参考、认领与复核、源表字段与来源追溯都围绕当前选中的子 SKU 展示。
- 选品1字段展示 / 结构化导入不按固定列号硬取；市场调研、价格 / 毛利参考等字段优先按表头语义匹配，匹配不到时才按历史列号兜底。
- 商品详情页分区口径：`A-L` 为基础信息，`M-Y` 为开发询价 / 规格成本，市场调研按表头匹配历史 `Z-AN` 兜底，价格 / 毛利参考按表头匹配历史 `AO-AV` 兜底，`AQ-BR` 作为成本参数分区展示。
- 分配推荐必须先按站点硬隔离：同主 SKU 如果存在不同国家 / 站点的子 SKU，推荐分配时也要拆成不同站点任务；品类不命中时只在同站点候选人里按负载均衡，不能把泰国品分给越南运营。
- 商品详情页必须能从商品看板、运营认领、主管复核进入；从子 SKU 任务进入时默认定位到该子 SKU。
- 商品详情页 `认领与复核` 里的运营列只显示实际认领 / 不认领提交人；没有提交记录时显示空，不能回退展示开发员。
- 商品详情页返回入口放在页面标题旁，不放在商品卡片内部；档案分区选择尽量上移并保持紧凑。
- 刷新成功等非阻断系统状态用右上角小提示，不在主内容区占一整行。
- 运营认领页和主管复核页点击主 SKU / 子 SKU 文本进入商品详情页，不额外新增重复的详情按钮。
- 从运营认领或主管复核进入商品详情再返回时，未提交草稿和已选复核动作不能被清空；刷新、关闭页面或换设备不承诺保留。
- 二次调研确认后，运营可以直接在外部平台刊登。
- `【推品】海外仓精品流程.xlsx` 是刊登后运营陆续填写 / 跟进的表，不是刊登前必须完成的动作。

> 本节记录可复用的获取方式，不记录真实账号、密码或 Token。运行凭据只放服务器 `.env` 的 `PLM_USERNAME`、`PLM_PASSWORD`。

- 当前项目使用 `PLM_BLOC_NAME=集团八部`。2026-07-10 已完成一次真实导出核验：工作簿 `汇总表格` 共 44 列，`集团` 列去重后只有 `集团八部`。
- 每天北京时间 `08:00` 获取前一天数据。日期窗口为当天 `00:00:00+08:00` 到 `23:59:59+08:00` 的毫秒时间戳。
- PLM 不是直接返回 Excel，而是异步流程：登录获取 Token -> 读取下载中心已有记录 -> 创建库存明细导出任务 -> 轮询下载中心 -> 下载 MinIO 文件。

- 创建导出：`POST /api/hz-inventory/overseas/details/exportSummaryExcel`，请求中的 `blocNameList` 使用 `PLM_BLOC_NAME`，时间使用上述北京时间窗口。
- 每 10 秒轮询一次，最多 10 分钟。只接受 `status=2`、存在 `downloadUrl`、`id` 不在任务前快照中、文件名 13 位时间戳不早于任务创建前 60 秒的记录。

- 单次任务失败后等待 5 分钟，从重新登录开始完整重试，直到成功。历史日期补数必须串行，避免多个异步导出混在下载中心。

## 3. 刊登与观察工作台已确认口径（2026-07-16）

- 平台建设独立的“刊登与观察工作台”，同时支持查看权限范围内全部记录、筛选、刊登录入和周期复盘；商品看板作为全生命周期只读档案，不重复建设编辑表单。

- 刊登记录关联主 SKU，不关联子 SKU。一个主 SKU 可由运营自增多条 Item；每个 Item 独立观察四周、单独填写四周总结，首周周期由系统按刊登操作时间自动计算。
- 工作台由系统带出并锁定主 SKU、国家、负责人等上下文；每条刊登记录的人工必填项为 `店铺`、`Item` 和自由文本 `刊登策略`，均由运营填写；第一周周期由系统按操作时间自动计算；店铺不接固定清单或配置模块，不再提供优化、刷单、广告、联盟、活动等固定选项。
- 不提供全局“新增 Item”。运营在 `待刊登` 列表的对应主 SKU 行内通过外露 `新增刊登 Item` 新增刊登记录，系统锁定主 SKU、国家和负责人，由运营填写店铺、Item 和刊登策略；同一主 SKU 可连续新增多条“店铺 + Item”记录后统一提交。
- 批量提交采用整批原子规则：任意一条 Item 重复、必填项缺失或服务端校验失败，本批全部不落库；页面保留内容并定位、标红错误行，修正后重新整批提交，不出现部分成功。
- 每个 Item 的第一周由系统自动设为刊登操作日后的下一个完整周四至周三周期；周四当天提交也从下一个周四开始，不提供人工改选。
- 每周四获取上一个完整周期的数据：订单量、总收入、一次毛利额、一次毛利率；一次毛利率按 `一次毛利额 / 总收入` 计算并显示百分比。每个 Item 周期只成功抓取一次，第一次有效写入后不再重复抓取或覆盖。
- 正在跟踪的 Item 在某周期完全查不到周数据时，内部保持 `待取数`，不得自动按 `0` 销量、`0` 收入或 `0` 毛利处理；系统自动重试，具体重试频率留给技术设计。未来未开始周期不展示；当前周期只显示预计取数提示，周期结束仍未取到数据时显示“数据准备中”，数据成功入库后才展示完整指标和复盘表单。
- 首轮第 1-4 周及所有后续新增周期都必须填写产品定位和优化操作。产品定位允许在观察过程中变化，但不会自动停止跟踪。
- 第 1 周产品定位默认带出二次调研定位；第 2 周及后续周期默认带出该 Item 最近一个已有定位，前序周期还没有定位时回退到二次调研定位。默认带出只是编辑初值，运营仍须确认或修改后提交。
- 刊登行和周期复盘的未提交内容使用浏览器本地自动保存，按登录用户及任务 / 周期隔离；刷新或误关后恢复，提交成功后清除。不新增服务端草稿表、接口或跨设备同步。
- 观察期某周期改为 `淘汰款` 后，Item 仍保持正常跟踪；后续周期继续生成和取数，数据入库后继续提醒运营并要求复盘，后续任一周期可再改为其他定位。第 4 周改为淘汰款时仍要填写四周总结；首轮完成后仍按人工“新增周期”继续，不因淘汰款自动无限生成。
- 观察期淘汰款主管提醒按定位变化去重，首次提交和修改已复盘记录采用同一规则：从非淘汰款改为淘汰款时提醒；连续周期仍为淘汰款不重复；改成其他定位后再改回淘汰款时重新提醒。每次变化事件仍进入每天 `10:00` 左右的未成功通知汇总。
- Item 跟踪状态单独使用 `正常跟踪 / 停止跟踪`；只有明确停止跟踪后，系统才不再取数、不再提醒。
- `停止跟踪` 后允许恢复；保留此前已完成的周记录，不补停止期间的数据，从恢复后的下一个周期继续未完成周次。
- `停止跟踪` 只阻止后续周期生成、后续取数和后续提醒；停止前已经成功取数但尚未复盘的周期仍可由负责人运营或主管填写并提交，已取数据继续保留。
- 周数据成功入库后立即提醒对应运营一次，最晚在下周三下班前提交复盘，本周期不重复催促。
- 刊登时只记录操作时间，不再选择第 1 周起始周期；首轮第 1-4 周从下一个完整周四至周三周期起自动生成并取数，不等待上一周期提交。上一周期逾期未填时，下一周期仍正常取数并进入待复盘。
- 停止跟踪期间暂停生成和取数；恢复后从下一业务周期继续未完成周次、不补停用期间。首轮四周全部完成后停止自动生成，后续周期只允许运营或主管手动新增。
- 第 4 周提供 Item 级四周总结填写区；同一主 SKU 后续新增 Item 时，仍从该 Item 自己选择的周期独立观察四周。
- 四周总结与第 4 周产品定位、优化操作一起提交，统一截止到周数据成功入库并提醒后的下周三下班前。
- 第 4 周产品定位、优化操作和四周总结全部提交后，该 Item 进入 `首轮观察完成`。系统不自动创建第 5 周；运营或主管可以点击“延长观察”继续新增第 5 周及后续周期，序号不设上限。延长周期继续自动取数、发送一次提醒，并要求填写产品定位和优化操作；历史继续保留可查。
- Item 总状态保留 `首轮观察完成`，新增后续周期时不来回切换；每条周期记录内部独立使用 `待取数 / 待复盘 / 已完成`。待取数不生成运营待办，数据成功入库后才进入待复盘；不增加 `后续观察中` 总状态。
- 新增后续周期默认选下一个周四至周三周期，可改选当前周期，不允许选择已结束的历史周期；中间有空档也不自动补齐，周次按实际新增顺序继续编号。
