# 分配任务规则设计草案

> 日期：2026-06-29  
> 状态：MVP 已实现最小规则，销售主攻品类规则待业务确认。

## 1. 当前已实现的最小规则

| 规则点 | 当前实现 | 待业务确认 |
|---|---|---|
| 分组单位 | 按 `main_sku` 聚合预览 | 是否所有主 SKU 必须整组分配 |
| 负载单位 | 用子 SKU 数量衡量任务量 | 是否需要按类目、站点、难度加权 |
| 候选人 | 分配台手工输入候选销售 | 是否从人员映射自动筛选 |
| 推荐逻辑 | 把主 SKU 组分给当前负载最低的候选人 | 是否要加入历史业绩、站点熟悉度、类目熟悉度 |
| 生效方式 | 系统只预览建议，人工确认后生成销售认领任务 | 是否允许系统自动分配 |
| 改派 | 第一版不做改派；只支持分配前调整推荐人 | 后续如需要再设计审计规则 |

## 2. MVP 分配流程

```text
待分配新品机会
  -> 按 main_sku 聚合
  -> 计算每组子 SKU 数
  -> 输入候选销售
  -> 系统给出均衡建议
  -> 组长人工确认
  -> 为销售生成认领任务
```

## 4. 后续可扩展但不进 MVP 的规则

- 按站点、类目、历史业绩、当前缺货压力综合打分。
- 黑名单/白名单：某销售不接某类目或优先接某类目。
- 大主 SKU 自动拆组，但需要业务明确拆组边界。
- 批量导入人员容量，如每天最多可接几个主 SKU。
- 改派及对应审计。

## 5. 类目与人员配置底座（规划）

目标：后续让系统根据商品类目和人员关系给出更准确的分配建议，但仍保留组长人工确认。

当前口径：第一版先使用“销售员重点站点 + 主攻品类”作为分配建议依据；“组长 -> 销售员”精确归属关系暂不作为第一版关键条件。

当前来源文件：`集团八部销售员信息表.xlsx`

| 字段 | 用途 |
|---|---|
| 销售员 | 分配候选人 |
| 岗位 | 区分组员 / 组长；第一版组长是否参与认领待确认 |
| 运营分层 | 可作为后续优先级或容量参考 |
| 业务类型 | 过滤精品（海外仓）业务人员 |
| 重点站点 | 站点匹配 |
| 重点品类1 | 主攻品类，优先级高 |
| 重点品类2 | 辅助主攻品类，优先级次之 |

### 5.1 一级/二级类目配置

建议维护 `category_assignment_rule`：

| 字段 | 说明 |
|---|---|
| `site` | 站点，如 PH / TH / VN |
| `category_level1` | 一级类目，来自源表 D 列 |
| `category_level2` | 二级类目，来源待确认 |
| `salesperson_name` | 主攻该类目的销售 |
| `priority` | 优先级，数值越高越优先 |
| `capacity_limit` | 可选，周期内最大待认领主 SKU 数 |
| `enabled` | 是否启用 |
| `remark` | 说明，如“只接摩配外观件” |

待确认：

- 二级类目来自源表、人工维护映射，还是后续由系统/AI 辅助归类。
- 一个类目是否允许多个销售主攻。
- 销售是否可以配置“不接某类目”的排除规则。

### 5.2 主管-销售人员配置（后续可选）

当前结论：暂时不重要，第一版不依赖“组长 -> 销售员”关系。后续如果要做审核权限隔离、逾期升级、主管工作量统计，再补充。

建议维护 `manager_sales_mapping`：

| 字段 | 说明 |
|---|---|
| `site` | 站点 |
| `manager_name` | 主管 / 组长 |
| `salesperson_name` | 销售 / 运营 |
| `team_name` | 小组 |
| `enabled` | 是否启用 |
| `effective_from` / `effective_to` | 生效时间，可选 |

规则：

- 第一版不按主管范围过滤候选销售，先按站点、主攻品类、负载推荐。
- 后续如启用主管范围，主管只能分配、审核自己配置范围内的销售任务，除非管理员授权跨组处理。
- 人员配置变更要保留历史，历史任务不因人员表变化而丢失责任人。

### 5.3 分配建议评分顺序

建议优先级：

1. 站点匹配：只在同站点候选销售中推荐。
2. 主攻品类匹配：优先匹配 `重点品类1`，其次匹配 `重点品类2`。
3. 类目匹配：一级类目先匹配，二级类目来源确认后再加权。
4. 当前负载：待认领主 SKU 数、子 SKU 数越少越优先。
5. 人工覆盖：组长可以在确认前手动指定推荐人，第一版不要求填写改派原因。
6. 主管范围匹配：后续可选项，不进入第一版必要规则。

选品1源表 `CD` 主销售员仅保留原值追溯，不进入推荐评分。

分配台必须展示推荐原因，例如：

```text
推荐给 张三：TH 站点匹配；主攻品类1=汽配与摩配；当前待认领 3 个主 SKU。
```
