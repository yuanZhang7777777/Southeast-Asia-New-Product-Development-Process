## 当前状态

前段 MVP 已进入本地实现和验证阶段。最新代码已覆盖两张内部反馈表导入、主管分配、运营认领 / 不认领、主管复核、导出、商品看板、源表上传、人员配置、演示数据、以及 2026-07-03 确认的来源路由 / 批量认领 / 复核状态规则。

最新第一版口径：

```text
内部反馈表导入 -> 主管分配 -> 运营填写是否认领和认领单销 -> 主管复核汇总 -> 导出
```

第一版先不做：

- 在线表自动写回
- 中央表匹配异常清单
- 钉钉待办任务
- 采购 / 供应链 / 下单平台待办
- 直发热销确认表
- 销售选品备货海外仓-销售调研表

如果中央表或财根表后续匹配不上，第一版不阻塞平台认领、复核和导出，由外部在线表人工处理。

## 角色

- `运营`：旧讨论里的“销售”，负责认领 / 不认领、填写认领单销、反馈总结、备注。
- `主管`：负责分配、复核、查看汇总、导出。

业务材料里不要把接收材料的人写进标题或正文，用“评审材料 / 业务人员 / 主管视角”等中性表达。

## 前段规则

- 主 SKU 组是核心流程单位。
- 子 SKU 是明细和导出单位。
- 主 SKU 组部分子 SKU 认领通过、部分确认不认领时，主 SKU 组显示 `部分认领通过`，子 SKU 分别显示 `可备货` / `已确认不认领`。
- 主管按主 SKU 组分配，组内子 SKU 不拆散。
- 支持一键自动分配：先按站点硬过滤，再按未完成主 SKU 组负载做均衡；只有负载相同时才比较重点品类、人员优先级和站点内顺序，历史业绩不纳入第一版规则。
- 当前负载按未完成的主 SKU 组数量 + 本次一键分配草稿数量计算，不按子 SKU 数量计算。
- 运营默认认领组内子 SKU，但可把部分子 SKU 改为不认领。
- 认领的子 SKU 必填认领单销。
- `认领单销` 按日销理解；`备货数量 = 认领单销 × 30`。
- 不认领必须填不认领原因。
- 认领和不认领都可以填写可选的调研结论，后续写入市场监控表 `AK 调研结论`；不强制每个 SKU 都填写。
- 认领和不认领都可预留调研图片证据，支持运营粘贴、拖拽或选择图片；第一版可先随认领记录 note 保存，后续如需要再拆独立文件存储。
- 运营认领页不使用右侧统一处理面板，认领 / 不认领输入直接放在商品卡片上；认领填认领单销和可选调研结论 / 图片，不认领填不认领原因和可选调研结论 / 图片，两个动作互斥。
- 运营认领页按主 SKU 分组展示子 SKU；支持一键提交全部已填写或提交本组已填写，系统只提交填写完整的子 SKU，未填完整的子 SKU 保持草稿。
- 提交前可修改；提交后不能自行撤回，只能等主管退回补充。
- 主管同时复核认领和不认领。
- 主管不允许代改运营提交的 `认领单销` / `不认领原因`；内容不对只能通过退回补充让运营修改。
- 复核状态文案：认领提交显示 `待复核-认领` / `运营已认领`，不认领提交显示 `待复核-不认领` / `运营不认领`。
- 第一版认领提交复核只允许 `通过认领`，不要求复核意见；不认领提交可 `确认不认领` 或 `退回补充`，退回补充必须填写原因。
- 退回补充状态显示为 `已驳回-待运营补充`，运营重新打开认领页时必须能看到主管退回原因。
- 主管确认不认领后的终态名称固定为 `已确认不认领`；第一版不自动重新打开，也不做平台返工入口；导出后如业务需要调整，在外部导出表 / 备货流程人工处理。
- 主管通过后进入可备货导出范围；点击导出时生成导出批次。
- 可备货清单只做子 SKU 明细导出，不做主 SKU 汇总页。
- 同一次导出批次包含两个子 SKU 明细导出：
  - `备货申请表`：按 `海外仓备货申请表.xlsx` 的 16 列结构，用于下游备货操作。
  - `全字段留痕明细`：和 `备货申请表` 在同一个“主管复核通过后点击导出”环节生成；不是导入来源表，也不是人工填写表。行范围与本次备货导出的子 SKU 一致，字段先放 `东南亚海外仓新品表-PH/TH/VN.xlsx` 中 `开发是否接受核价结果` 前的字段，再拼接平台内部认领 / 复核 / 导出字段，用于领导查看和追溯备用。
- `备货申请表` 中 `时间` 取系统写入 / 导出时间；`补货原因` 第一版留空。
- 导出批次最小元数据：导出人、导出时间、导出文件名、导出范围。
- 同一子 SKU 被多个运营认领通过时，导出按运营 / 认领任务另起多行，不合并。
- `不认领原因` / `不认领理由` 等运营提交字段需要记录首次创建时间和最后更新时间。

## 第一版页面范围补充

- 商品看板必须保留在第一版：它是完整商品状态总览，不是后续阶段页面，也不是只看待处理机会的列表。
- 商品看板按主 SKU 分组，展开子 SKU；默认筛选项为站点、运营、状态、健康标签、一级类目 / 二级类目、来源批次；搜索框支持主 SKU、子 SKU、商品名、关键词。
- `开品理由` 按主 SKU 组共用展示，子 SKU 明细不重复展示。
- 第一版商品看板没有更完整的详情页 / 详情抽屉，因此只保留 `展开 / 收起子 SKU` 操作，不保留与展开作用重复的 `查看详情` 按钮。
- 商品看板和机会池分开：商品看板看全量商品走到哪里，机会池只看待处理 / 可自领的新品机会。
- 主管模式下机会池不能出现“认领”动作，也不能跳到运营认领页；主管只能查看、分配、复核和导出。运营模式下，选品1的待分配记录不显示为可自领；财根待分配记录可以显示为自领机会。
- 源表导入页必须使用拖拽 / 点击选择文件上传，不让用户填写服务器本地路径；`默认表` 只可作为开发调试口径，不出现在业务 UI。
- 本地演示数据脚本：`backend/scripts/seed_demo_statuses.py`，只清理并重建 `source_type=local_demo_status_coverage` 的 demo 记录，用于覆盖待分配、待认领、财根机会池、待复核、退回补充、可导出、已确认不认领、多状态等测试场景。
- 健康标签 `正常 / 需关注 / 异常` 第一版用于展示和筛选，不阻塞流程；复杂评分不做，后段到货 / 监控等触发规则等对应阶段实现时再细化。

## 后段规划

这些已讨论，但不是第一版立即实现：

- 钉钉只做提醒和入口；用户从钉钉入口打开平台页面后交互提交，第一版写平台数据库，不写钉钉在线表；钉钉在线表写回后续单独实现。
- 到货承接：数据源为 PLM 下载中心导出的 `真仓库存明细数据-普通商品-汇总数据`；每天早上 8 点多拉取前一天数据；字段包括子 SKU、主 SKU、海外仓、国家、预计到港时间、最后一次入库时间、首次上架时间、海外仓可发、真仓库存；第一版后段只监控到货时间。
- PLM / 库存同步业务账号：后续默认使用练玉君账号拉取数据，因为当前后段平台归属练玉君部门；账号密码只放服务器环境变量，不写入仓库、文档或代码。
- 二次市场调研：实际入仓后、刊登前，每个主 SKU 做一次；运营填写，主管可查看。
- 具体调整 / 竞品监控：竞品链接、竞品价格 / 销量、产品定位、原建议售价、二次调研参考价、最终刊登售价、调价原因。
- 刊登确认：ItemID、刊登链接、店铺、售价、刊登日期。
- 每周监控：从刊登日期起每 7 天一周，按 ItemID 生成记录，主 SKU 汇总。
- 市场监控表：`【市场监控】海外仓精品市场调研.xlsx` 是备货申请导出后的二次调研、具体调整 / 竞品监控工作表，不是 PLM 原始表；当前本地实测 `AO=产品定位`、`AQ=公司单销`，后续按表头匹配；二次调研判定为淘汰款时通知主管去外部系统调整定位，避免清仓销量触发误补货。
- 市场监控表逐字段来源确认文档：`docs/18-市场监控表字段来源确认问题清单.md`，后续在该文档里补每列来源表、来源字段、直接取数或计算逻辑、填写时点。
- 四周总结：第 28 天生成，运营填写，主管查看汇总。
