## 前段规则

- 主 SKU 组是核心流程单位。
- 子 SKU 是明细和导出单位。
- 主 SKU 组部分子 SKU 认领通过、部分确认不认领时，主 SKU 组显示 `部分认领通过`，子 SKU 分别显示 `可备货` / `已确认不认领`。
- 主管按主 SKU 组分配，组内子 SKU 不拆散。
- 支持一键自动分配：先匹配重点站点，再匹配重点品类1，再匹配重点品类2，最后按当前负载均衡；历史业绩不纳入第一版规则。
- 当前负载按未完成的主 SKU 组数量 + 本次一键分配草稿数量计算，不按子 SKU 数量计算。
- 运营默认认领组内子 SKU，但可把部分子 SKU 改为不认领。
- 认领的子 SKU 必填认领单销。
- `认领单销` 按日销理解；`备货数量 = 认领单销 × 30`。
- 不认领必须填不认领原因。
- 认领和不认领都可以填写可选的调研结论，后续写入市场监控表 `AK 调研结论`；不强制每个 SKU 都填写。
- 认领和不认领都可预留调研图片证据，支持运营粘贴、拖拽或选择图片；第一版可先随认领记录 note 保存，后续如需要再拆独立文件存储。
- 运营认领页不使用右侧统一处理面板，认领 / 不认领输入直接放在商品卡片上；认领填认领单销和可选调研结论 / 图片，不认领填不认领原因和可选调研结论 / 图片，两个动作互斥。
- 运营认领页按主 SKU 分组展示子 SKU；支持一键提交全部已填写或提交本组已填写，系统只提交填写完整的子 SKU，未填完整的子 SKU 保持草稿。
- 提交前可修改；提交后不能自行撤回，只能等主管退回补充。
- 主管同时复核认领和不认领。
- 主管不允许代改运营提交的 `认领单销` / `不认领原因`；内容不对只能通过退回补充让运营修改。
- 复核状态文案：认领提交显示 `待复核-认领` / `运营已认领`，不认领提交显示 `待复核-不认领` / `运营不认领`。
- 第一版认领提交复核只允许 `通过认领`，不要求复核意见；不认领提交可 `确认不认领` 或 `退回补充`，退回补充必须填写原因。
- 退回补充状态显示为 `已驳回-待运营补充`，运营重新打开认领页时必须能看到主管退回原因。
- 主管确认不认领后的终态名称固定为 `已确认不认领`；第一版不自动重新打开，也不做平台返工入口；导出后如业务需要调整，在外部导出表 / 备货流程人工处理。
- 主管通过后进入可备货导出范围；点击导出时生成导出批次。
- 可备货清单只做子 SKU 明细导出，不做主 SKU 汇总页。
- 同一次导出批次包含两个子 SKU 明细导出：
  - `备货申请表`：按 `海外仓备货申请表.xlsx` 的 16 列结构，用于下游备货操作。
  - `全字段留痕明细`：和 `备货申请表` 在同一个“主管复核通过后点击导出”环节生成；不是导入来源表，也不是人工填写表。行范围与本次备货导出的子 SKU 一致，字段先放 `东南亚海外仓新品表-PH/TH/VN.xlsx` 中 `开发是否接受核价结果` 前的字段，再拼接平台内部认领 / 复核 / 导出字段，用于领导查看和追溯备用。
- `备货申请表` 中 `时间` 取系统写入 / 导出时间；`补货原因` 第一版留空。
- 导出批次最小元数据：导出人、导出时间、导出文件名、导出范围。
- 同一子 SKU 被多个运营认领通过时，导出按运营 / 认领任务另起多行，不合并。
- `不认领原因` / `不认领理由` 等运营提交字段需要记录首次创建时间和最后更新时间。

- 平台只负责通知主管，不接入或写回外部系统，也不增加“已处理”按钮、状态或待办；钉钉发送成功即完成平台责任，失败继续重试。
- 具体调整 / 竞品监控：竞品链接、竞品价格 / 销量、产品定位、原建议售价、二次调研参考价、最终刊登售价、调价原因。
- 刊登与观察工作台：刊登记录只关联主 SKU；一个主 SKU 可新增多条“店铺 + Item”记录，运营填写店铺、Item 和自由文本刊登策略，商品详情只汇总展示。Item 在平台内全局唯一，不按运营、平台、国家、店铺或主 SKU 分范围，重复录入时弹窗并阻止提交。
- 商品详情只读展示同一主 SKU 的全部刊登与观察历史，按来源业务期明确分组并默认展开当前业务期，不得把不同业务期记录混在一组。
- 观察工作台采用一张 Excel 式全量表，不再使用待刊登、待复盘等顶部状态页签；业务状态改为筛选条件，默认筛选 `待刊登`，切换为 `全部` 时展示待刊登任务和全部 Item 周期记录。自动指标只读，产品定位和优化操作表内编辑，支持勾选后一键提交；主 SKU 作为分组层，Item 周期作为明细层。运营由权限强制只看本人，主管默认看全部并可按负责人筛选。周次、定位和跟踪状态放高级筛选；第 4 周总结通过侧边编辑入口填写，不占常驻宽列。
- 周期提交为“本周已复盘”后不锁定：负责人运营仍可直接修改本人填写的产品定位、优化操作和第 4 周四周总结，主管也可纠错；无需单独填写修改原因，保存时沿用原必填校验并保留审计，周期仍保持已完成。自动抓取的订单量、收入和毛利继续只读。
- Item 不允许从全局入口随意新增，只能在 `待刊登` 列表的对应主 SKU 行内添加刊登记录；主 SKU、国家、负责人由系统锁定，运营填写店铺、Item、刊登策略和第一周起始周期，同一主 SKU 可连续新增多条后统一提交。
- 刊登批量提交采用整批原子规则：任意一条重复、漏填或服务端校验失败，本批全部不落库；保留内容并标红错误行，修正后重新提交，不允许部分成功。
- 店铺已确认由运营自由输入，不建设固定店铺清单或配置模块；店铺筛选按已保存文本搜索。
- 自由文本刊登策略已确认为必填。
- 每周观察：每个 Item 独立选择第一周周期，默认下一周期、可改当前周期；统一按周四至下周三取数，不从刊登日期滚动 7 天。
- 刊登时只选第 1 周起始周期；首轮四周自动连续生成和取数，不等待上一周期提交，允许同时存在多个待复盘周期。停止跟踪期间暂停，恢复后从下一周期续接且不补停用期间；首轮完成后才改为手动新增周期。
- 周数据自动带出订单量、总收入、一次毛利额和一次毛利率；每周产品定位、优化操作必填。产品定位为引流款、利润款、淘汰款、稳定款、清仓款，定位变化不等于停止跟踪。
- 观察期某周期改为淘汰款后仍继续后续周期生成、取数、运营提醒和复盘，并允许以后周期改回其他定位；第 4 周仍需总结。只有显式“停止跟踪”才暂停，首轮完成后的后续周期仍由运营或主管手动新增。
- 观察期淘汰款主管提醒只在定位从非淘汰款变为淘汰款时生成；连续周期保持淘汰款不重复，改成其他定位后再改回淘汰款时重新生成，仍按每天 10:00 左右汇总未成功通知记录。
- 正在跟踪的 Item 某周期完全查不到周数据时，内部保持 `待取数` 并自动重试，不得自动记成订单量、收入或毛利为 0；运营页面统一显示“观察中”，订单量、收入和毛利指标显示 `-`，且该周期不可复盘。
- Item 是周数据唯一值，同一周期内每个 Item 只会有一条周汇总，不做多行合并。
- 同一主 SKU、国家 / 站点和负责人跨业务期重现时，低频兜底为展示并沿用仍有效的已有 Item；不重复建刊登记录，只有新店铺或新 Item 才新增，各期来源追溯仍独立。
- 停止跟踪的 Item 允许恢复；保留已完成的周记录，不补停止期间数据，从恢复后的下一周期继续未完成周次。
