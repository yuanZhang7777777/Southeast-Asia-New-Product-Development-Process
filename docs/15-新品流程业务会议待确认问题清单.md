## 1. 总流程与角色

已确认口径：

- 角色按“运营”和“主管”两类设计。
- 本轮开发范围收敛为：内部反馈表导入 -> 主管分配 -> 运营填写是否认领和认领单销 -> 主管复核汇总 -> 导出。在线表写回 / 中间桥先不作为第一版闭环要求。
- 备货、采购、供应链核价、下单属于外部流程；平台本轮不做这些部门的待办。
- 主管可查看分配、运营填写、复核汇总和导出结果；如后续启用在线表写回，再补充写回结果查看。

会议待确认问题：

无。

## 2. 数据入口、来源表和写回目标

已确认口径：

- 本轮只导入两张内部反馈表：
  - `海外仓开发部门开发新品认领-反馈`
  - `海外仓财根团队开发新品认领-反馈`
- 本轮不处理：
  - `直发热销转海外仓销售确认`
  - `销售选品备货海外仓-销售调研`
- `海外仓开发部门开发新品认领-反馈` 是人工从 `海外仓开发新品表-分站点` 下的 `东南亚海外仓新品表-PH / TH / VN ...` 汇总出来的内部反馈表。
- `东南亚海外仓新品表` 由公司维护；BV 列之后是不同部门填写区。
- 系统只给本集团内部人员使用，只处理本集团对应销售员 / 团队列。
- 反馈表 BV-CB 区域字段包括：`开发是否接受核价结果`、`不认领理由`、`主销售员`、`是否认领`、`认领单销`、`销售反馈总结`、`备注`。
- 本集团平台处理字段为：主管分配 / 确认 `主销售员`；运营手动选择 `是否认领`，填写 `认领单销`、`销售反馈总结`、`备注`；不认领时填写 `不认领理由`。
- `开发是否接受核价结果` 属于外部部门字段，本轮只作为导入参考 / 展示，不由本集团运营填写。
- 选品1旧周期已有的认领字段仅保留来源快照，不预填、不推荐、不进入业务展示；财根选品2按独立机会池规则处理。
- 内部反馈表导入时优先读取行内 `站点` / `国家` 字段；选品1当前实测为 `A=站点`。不能仅凭固定文件名或 sheet 名推断站点。
- 当前本地 `选品2：海外仓财根团队开发新品认领-反馈.xlsx` 最新 `5.26期` 未发现站点字段；实测 20 个 SKU 可全部唯一匹配到 `东南亚海外仓新品表-PH.xlsx` 的 `5.26` sheet，站点取中央表行内 `菲律宾`。后续规则：无站点字段时可先按 SKU 回查 PH / TH / VN 中央表辅助带出站点；匹配不到或匹配多行不阻塞认领和导出，第一版不做异常清单流程。
- 两张内部反馈表实测字段清单保存于 `docs/16-新品认领反馈源表实测字段清单.md`。
- 项目根目录其他可复用源表字段快照保存于 `docs/17-源表字段总字典.md`，后续导入 / 写回 / 页面字段设计先查该总字典。
- 已确认平台以 `东南亚海外仓新品表-PH/TH/VN` 为目标字段字典。来源表字段通过字段名 / 语义映射写入目标字段；来源表有但中央表没有的字段作为扩展字段保留；中央表有但来源表没有、且无法唯一匹配补全的字段默认空值，不用 `0`。
- `海外仓财根团队开发新品认领-反馈` 第一版作为机会池来源：主销售员 / 主认领销售必须处理，不认领必须填理由；其他运营可自领同一 SKU，人数不设上限，不自领不产生不认领任务。
- 导出结果需要能用于外部备货汇总；导出优先，不因中央表匹配问题阻塞。
- 后续可预留通过钉钉在线表能力把认领单销写回 `东南亚海外仓新品表` 对应国家站点、对应集团 / 销售员列，但中间桥第一版不作为平台闭环要求。
- 写回 `东南亚海外仓新品表` 时，目标列不按固定列号，按表头匹配，例如 `销售员1\n仔云`、`预估单销\n仔云`、`销售员2\n财根`、`预估单销\n财根`。
- 写回范围先按中央表对应集团 / 销售员列处理，只写销售员和对应预估单销；不写 `合计单销`，由在线表原公式或人工维护。
- 不认领记录只在平台 / 内部反馈表留痕并进入主管确认；汇总到中央表时不写不认领字段，只写认领通过的销售员和预估单销。
- 写回定位必须保留源表、国家站点、导入批次 / 来源快照、主 SKU、子 SKU 和目标列映射；源行号只作为追溯信息，不作为写回匹配依据。
- 如果自动写回时 `站点 + 主 SKU + 子 SKU` 匹配不到或匹配到多行，第一版不做自动写回、不生成异常清单、不推主管；由外部在线表人工处理，不影响平台导出。
- 如后续启用在线表写回，主管复核完成后需要主管点击“确认写回”才执行；未启用时平台只导出。

## 3. 主 SKU / 子 SKU 状态模型

已确认口径：

- 主 SKU 组是核心流程单位；子 SKU 做明细展示、认领结果、可备货清单和导出明细。
- 两张反馈表导入后按主 SKU 组分配，组内子 SKU 不拆散分配。
- 子 SKU 默认全选为认领，运营可以把部分子 SKU 改为不认领。
- 主 SKU 组状态先按中文枚举设计：待分配、待认领、待主管审核、待补充、认领通过、部分认领通过、已确认不认领、已导出可备货清单。
- 子 SKU 结果状态先按中文枚举设计：未处理、可备货、已确认不认领。
- 主 SKU 组内部分子 SKU 认领通过、部分确认不认领时，主 SKU 组显示“部分认领通过”，子 SKU 分别显示“可备货 / 已确认不认领”。
- 主管确认不认领后的终态名称固定为 `已确认不认领`；第一版不允许自动重新打开或再次认领；如导出后业务需要调整，由外部导出表 / 备货流程人工处理，不回流平台。

会议待确认问题：

无。

## 4. 分配与认领规则

已确认口径：

- 主管可按站点、主攻品类、当前负载查看推荐，并一键分配 / 确认后生成运营认领任务。
- 第一版主管角色固定为练玉君；销售员信息表里的 `岗位=组长` 只作为人员属性，不等同于平台主管角色。
- `集团八部销售员信息表.xlsx` 是第一版人员配置初始化源；当前启用人员、站点、重点品类、同负载优先级和站点内顺序以生产数据库“运营配置”为准。
- 一键自动分配按主 SKU 组执行，组内子 SKU 不拆散。
- 自动分配先按商品站点过滤启用运营，再优先选择当前主 SKU 组负载更少的人；负载相同时才按重点品类命中、人员优先级和站点内自定义顺序推荐，`重点品类1`、`重点品类2` 命中同层。
- 如果商品站点没有启用运营，系统标记“无站点匹配”，不跨站点自动分配，由主管补充配置或人工处理。
- 当前负载按未完成的主 SKU 组数量 + 本次一键分配草稿数量计算，不按子 SKU 数量计算；`assignment_priority` 只是同负载且同类目匹配情况下的决胜项，不能突破负载均衡。
- 历史业绩第一版不纳入自动分配规则。
- 一键分配后，主管在确认前仍可人工调整推荐人。
- 后续建库时建立人员配置表，最小字段为销售员、岗位、运营分层、业务类型、重点站点、重点品类1、重点品类2、是否启用、来源行、更新时间；源 Excel 用作初始化和人工校验。
- 前段按周批次处理：周三主管拿到开发 / 数据侧数据并完成分配；周四运营完成认领 / 不认领提交；周四主管完成复核汇总。
- 本轮运营需要手动选择 `是否认领`，并填写 `认领单销`、`销售反馈总结`、`备注`；不认领时填写 `不认领理由`。
- `认领单销` 按日销理解；子 SKU 备货数量按 `认领单销 × 30` 计算。
- 提交前可随时撤销、切换和修改；提交后不能自行撤回，只能等主管退回补充。
- 选品1源表已有认领值不进入业务层；运营平台填写并提交后才进入主管审核。财根选品2的源表已有值仍按机会池规则作为预填 / 参考。

会议待确认问题：

无。

## 5. 主管审核与可备货清单

已确认口径：

- 主管审核同时覆盖认领和不认领提交。
- 认领任务可通过认领，也可退回运营补充。
- 不认领任务可确认不认领，也可退回运营补充。
- 主管不允许代运营修改 `认领单销` / `不认领原因`；内容不对只能退回补充。
- 退回补充按主 SKU 组退回，保留已填内容；退回备注可填可不填。
- 如果同一主 SKU / 子 SKU 有多个运营填写单销，主管审核页展示运营、子 SKU、认领单销、审核状态对比。
- 可备货清单只进入主管审核通过的认领子 SKU。
- 可备货清单只做子 SKU 明细导出，不做主 SKU 汇总页。
- 同一次导出批次包含两个子 SKU 明细导出：
  - `备货申请表`：按 `海外仓备货申请表.xlsx` 的 16 列结构，用于下游备货操作。
  - `全字段留痕明细`：和 `备货申请表` 在同一个“主管复核通过后点击导出”环节生成；不是导入来源表，也不是人工填写表。行范围与本次备货导出的子 SKU 一致，字段为 `东南亚海外仓新品表-PH/TH/VN.xlsx` 中 `开发是否接受核价结果` 前的字段 + 平台内部认领 / 复核 / 导出字段，用于领导查看和追溯备用。
- `备货申请表` 中 `时间` 取系统写入 / 导出时间；`补货原因` 第一版留空。
- 同一子 SKU 被多个运营认领通过时，按运营 / 认领任务另起一行，不合并。
- 主管审核通过后只进入可备货清单，不自动生成 Excel。
- 主管 / 数据人员点击导出时生成导出批次；导出批次最小元数据为导出人、导出时间、导出文件名、导出范围；导出后主 SKU 组状态更新为“已导出可备货清单”。
- `是否认领`、`认领单销`、`不认领原因 / 不认领理由`、销售反馈总结、备注等运营提交字段需要记录首次创建时间和最后更新时间。

会议待确认问题：

## 6. 人员、权限与钉钉

已确认口径：

- 钉钉不生成待办任务；必须处理的事项在系统内生成内部待办，钉钉只做推送和处理入口。
- 推送入口默认直接打开任务详情页。
- URL 只携带 `taskId`、`module`、`from=ding` 等定位参数，不携带或信任用户身份。
- 用户身份通过钉钉 H5 免登获取，后端用钉钉用户身份映射系统用户、角色和主管关系。
- 推送去重 key 为 `taskId + status + receiverUserId`。
- 逾期扫描每天 09:30 执行一次。
- 继续逾期时继续提醒原责任人，并同步推送主管。
- 第一版推送内容包含商品图缩略图、主 SKU、商品名称、当前状态、责任人、处理入口。
- 人员身份和主管关系优先从现有人员表或钉钉通讯录同步；第一版不做首次登录人工绑定。
- 第一版主管角色固定为练玉君；所有分配、审核和导出管理入口对练玉君开放。
- 钉钉只做提醒和入口；用户从钉钉入口打开平台页面后交互提交，第一版写平台数据库，不写钉钉在线表。
- 钉钉在线表写回后续单独实现，第一版对外衔接通过导出处理。

## 7. 商品看板

- 商品按主 SKU 分组，展开看子 SKU。

## 8. 到货承接

已确认口径：

- 到货承接数据优先从现有系统自动同步。
- 到货承接数据源确认为 PLM 系统下载中心导出的 `真仓库存明细数据-普通商品-汇总数据`。
- 拉取节奏：每天早上 8 点多拉取前一天数据；时间窗口按 Asia/Shanghai 前一自然日 00:00:00-23:59:59 计算。
- 接口链路：登录 PLM 后发起库存汇总导出任务，文件生成到下载中心，再从下载中心下载 xlsx。账号、密码、token 不写入需求文档。
- 2026-07-02 实测：PLM 登录成功，下载中心列表可查询，已生成文件可直接下载；下载 URL 中中文文件名需要标准 URL 编码。
- 2026-07-08 实测：IT 新开放库存接口登录和分页查询成功；后续默认使用练玉君账号作为业务同步账号，真实凭据只放服务器环境变量。日常“前一天到货”拉取优先使用带 `latestStorageTimeStart/latestStorageTimeEnd` 的 PLM 导出链路；新开放库存明细接口可用于当前库存查询 / 对账，若做全量分页同步需先确认固定排序，避免默认分页顺序导致漏数或重复。

- 展示主 SKU、子 SKU、站点、运营、预计到货时间、实际入仓时间、仓库、当前状态。
- 平台按主 SKU / 子 SKU 匹配到货记录。
- 第一版只监控是否到货和到货时间，不监控到货数量不足。
- 到货待办的运营归属以平台内已通过复核的认领销售 / 运营为准；PLM `销售员` 字段只做校验和补充展示，不覆盖平台认领结果。
- 到货 / 二次调研待办触发字段已确认：PLM `海外仓可发 > 0`。
- 去重唯一键已确认：`认领记录ID + 子 SKU + 国家`；同一唯一键只在第一次满足可发条件时生成待办 / 推送，后续每日同步只更新库存和最后同步时间。
- 其他集团库存不阻塞待办：只要平台已有通过复核的认领记录且 PLM `海外仓可发 > 0`，仍生成给集团八部对应认领运营。
- `公共池库存` 第一版只作为展示 / 对账字段，不单独触发到货待办。
- 有实际入仓时间后，商品进入待二次市场调研。
- 预计到货时间已过但还没有实际入仓时间时，商品标记为需关注。

会议待确认问题：

1. 当同一子 SKU + 国家在多个海外仓同时可发时，市场监控 / 二次调研待办是合并为一个待办，还是按仓库拆分展示？
2. 是否需要第二版基于最后一次入库时间 / 首次上架时间做提前提醒；第一版已确认 `海外仓可发 > 0` 才触发待办。
3. 预计到货超期未入仓时，由谁负责跟进外部流程？

## 9. 二次市场调研

已确认口径：

- 后半段真实任务按 `认领记录ID + 子 SKU + 国家` 流转，主 SKU 只做展示分组和批量填写入口。
- 二次调研由运营处理；主管可在商品看板 / 调研记录里查看全局结果。
- 二次调研 `AL-AO` 字段全部允许选择性填写，字段为空时导出保持空，不自动编值。
- `AL 调研时间` 由系统记录运营点击“确认已调研”的提交时间，不要求运营手工填写。
- 运营可以只按主 SKU 填一份调研内容，再批量应用到选中的子 SKU。
- `AM 竞对链接`、`AN 二次调研结论`、`AO 产品定位` 都可以为空。
- 只有 `AO=淘汰款` 时，才触发主管外部产品定位调整提醒。
- 运营点击“确认已调研”即可完成二次调研，字段可以全空。
- 二次调研确认后可以直接去外部平台刊登；第一版不强制设置“具体调整 / 竞品监控”作为刊登前门槛。

会议待确认问题：

1. 二次调研是否仍有 SLA 要求，例如到货可发后 1 天内确认，还是只做提醒不考核？
2. `AO=淘汰款` 后，平台是只推送主管，还是要生成“外部定位调整待办 / 已处理状态”？

## 10. 刊登承接 / 推品流程触发

已确认口径：

- 二次调研确认后，运营可以直接在外部平台刊登。
- `【推品】海外仓精品流程.xlsx` 是刊登后运营陆续填写 / 跟进的表，不是刊登前必须完成的动作。
- “刊登确认”目前不是已确认业务操作，只是待定义的平台承接点：用于让系统知道某条后半段任务已经刊登，并能开始生成 / 关联推品流程记录。

会议待确认问题：

1. 平台是否需要一个明确的“刊登确认”操作，还是只通过外部推品表 / 飞书表导入或同步来判断已经刊登？
2. 如果需要平台内“刊登确认”，入口在哪里：商品看板明细、到货待办详情、批量导入，还是管理员代录？
3. 如果需要平台内“刊登确认”，最小字段是什么：店铺、Item、操作日期 / 刊登日期、刊登链接、售价，哪些必填、哪些可空？
4. 是否允许一个 `认领记录ID + 子 SKU + 国家` 对应多个店铺 / 多个 Item？
5. 平台确认刊登后，是否立即生成 `【推品】海外仓精品流程.xlsx` 的 A-F 基础信息行，并从操作日期 / 刊登日期开始切 1-4 周监控？
6. 店铺列表来源是什么：从现有店铺系统同步，还是平台维护？
7. 刊登承接是否需要 SLA；如果需要，从二次调研确认后开始算，还是从 PLM 可发后开始算？

## 11. 每周监控

已确认口径：

- 从刊登日期起生成第 1-4 周监控记录。
- 刊登日期算第 1 天；每 7 天切分一个监控窗口，不按自然周。
- 每周监控记录按刊登记录 / ItemID 生成，主 SKU 页面做汇总展示。
- 主 SKU 汇总口径为销量、销售额、广告费求和；库存显示所有 ItemID 当前库存合计；ROI / ACOS 按汇总后的销售额和广告费重新计算。
- 指标数据第一版以系统自动同步为主；运营只填写处理动作和备注。
- 监控指标先保留销量、销售额、库存、广告费、ROI / ACOS、异常标签。
- 异常标签第一版只做销量低、广告异常、库存风险。
- 异常标签先打在刊登记录 / ItemID 明细上；主 SKU 汇总时，只要任一 ItemID 命中异常，就显示对应标签。
- 异常标签不额外生成待办，只在商品看板 / 每周监控列表展示和筛选。
- 有异常标签的周监控记录，处理动作必填；无异常标签时处理动作可不填。
- 调整动作先做调价、优化刊登、广告调整、继续观察；运营直接处理，不需要主管确认。
- `【市场监控】海外仓精品市场调研.xlsx` 的定位是备货申请导出之后持续跟进的市场监控 / 二次调研工作表，不是 PLM 原始表，也不是备货申请表。
- 当前本地文件实测 sheet 为 `说明`、`PH精品`、`TH精品`、`VN精品`、`MY精品`；国家 sheet 表头在第 2 行，结构基本一致，`MY精品` 暂为空。
- 当前本地文件实测 `AO=产品定位（引流款/利润款/淘汰款）`，不是 `AQ`；截图或在线表版本可能有列号漂移，后续同步必须按表头匹配，不按固定列号。
- 市场监控表 `A 调研时间`：平台导入 / 分配的新品任务，按 `B 货品` 期数日期后一天默认生成，例如 `开发新品0609期` -> `6.10`；其他来源如运营自己开的品，由销售 / 运营自己填写。
- 市场监控表 `B 货品`：平台导入 / 分配的新品任务，由系统按来源和期数生成，例如 `开发新品0609期`、`开发新品0629期`；其他来源按来源规则或由销售 / 运营填写。
- 市场监控表 `I 二级类目`：第一版允许为空，暂不做自动补齐；后续如果业务需要，再从 ERP 产品列表下载匹配。
- 市场监控表 `J 海外仓成本`：优先从导入源表按表头匹配，不按固定列号。`选品1` 优先匹配 `商品成本-含税（元）`，`选品2` 优先匹配 `进价`；找不到则导出留空并记录缺失来源。
- 市场监控表 `K/L 头程字段`：`K 真实头程运费` 只从老品等源表真实头程字段带入；`选品1` / `选品2` 新品开发源没有则留空。`L 计算头程` 到货后优先取每日 PLM 实际下载表中的 `头程费用`，没有该字段或值为空时按 `M*N*O/1000000*820` 计算，M/N/O 不足则留空。
- 市场监控表 `AK 调研结论`：来自前段运营第一次认领 / 不认领时填写的“调研结论”，对应平台认领记录 `feedback_summary`；该字段可选，不强制每个 SKU 填写。
- `直发热销转海外仓` 数据源：后续导入时第一步只导入源表 `A-O` 字段；`P` 列及之后字段的来源、填写人、流转逻辑后续再对齐。
- 逐字段来源确认以 `docs/18-市场监控表字段来源确认问题清单.md` 为准；该文档列出 A:AZ 每个字段的当前建议来源、填写时点和待业务填写的精确来源表 / 字段 / 逻辑。
- 运营 / 销售需要填写或确认：销售备注、认领单销、前段调研结论、二次调研时间、二次竞对链接、二次调研结论、产品定位。
- PLM / 系统侧优先带出或辅助带出：到货通知、公司单销、海外仓在途、海外仓可发、公共池库存、首次上架时间、产品定义、预计到港时间、集团八部单销 / 在途 / 可发；公司口径和集团八部口径是否完全来自同一 PLM 明细，后续用样例 SKU 核对。
- 如果运营二次调研后判定产品定位为“淘汰款”，需要通知主管去外部系统调整产品定位，避免淘汰款因清仓销量被系统误判为高销量并触发持续自动补货。

会议待确认问题：

1. 每周监控指标数据来自哪里？销量、销售额、库存、广告费、ROI / ACOS 分别来自哪些系统？
2. 指标同步频率是什么？每日一次、每周一次，还是手动刷新？
3. 异常标签阈值如何定义？销量低、广告异常、库存风险分别按什么规则判断？
4. 广告主指标使用 ROI 还是 ACOS？是否两个都展示、一个作为判断依据？
5. 周监控处理动作是否允许多选？
6. `【市场监控】海外仓精品市场调研.xlsx` 中公司口径和集团八部口径字段是否都来自 PLM？是否还有其他销售 / 库存系统来源？

## 12. 四周总结
