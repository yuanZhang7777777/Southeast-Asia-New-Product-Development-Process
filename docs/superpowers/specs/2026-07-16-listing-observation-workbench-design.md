# 刊登与观察工作台设计

日期：2026-07-16  
状态：核心流程和单表工作台已实现并部署开发环境；真实周 Item 接口、自动调度与运营消息发送链路待接入

## 1. 目标

在现有 `二次调研 -> 待刊登` 之后增加独立的“刊登与观察工作台”，完成：

1. 运营按主 SKU 新增一条或多条“店铺 + Item”刊登记录。
2. 每个 Item 独立选择第一周起始周期，并独立完成首轮四周观察。
3. 每个周期自动带出订单量、总收入、一次毛利额和一次毛利率，运营填写产品定位与优化操作。
4. 第 4 周填写四周总结；完成后允许手动新增不限数量的后续周期。
5. 商品详情页只读汇总刊登和观察历史。

## 2. 本次范围

包含：

- 新数据表、迁移、后端接口、权限、审计和自动化测试。
- 刊登与观察工作台前端页面、筛选、批量提交、表内复盘和第 4 周总结入口。
- 首轮四个周四至周三周期生成、停止 / 恢复跟踪、后续周期新增。
- 周 Item 汇总数据的标准导入边界及字段映射。
- 商品详情页的只读刊登 / 周期汇总。
- 删除旧 `four_week_summary` 模型、接口和表定义；新开发库不迁移旧数据。
- 修正二次调研定位漂移：支持引流款、利润款、淘汰款、稳定款、清仓款；引流款、利润款、稳定款进入待刊登，淘汰款、清仓款不进入刊登，只有淘汰款触发主管提醒。

本次不猜测或硬编码尚未提供的公司内部周数据接口账号、密码和请求方式。核心流程先通过标准导入服务接收周 Item 汇总；取得实际接口后只替换数据适配入口，不改业务表和页面。

## 3. 角色与权限

- 运营：只查看自己的刊登与周期记录；在自己的待刊登主 SKU 下新增记录，编辑允许修改的字段，提交周期复盘，停止 / 恢复自己的 Item，新增后续周期。
- 主管 / 超级管理员：查看全部记录，按负责人筛选；可代录、纠错、停止 / 恢复、作废和新增后续周期。
- 所有写操作记录 `AuditLog`。
- 商品详情汇总对有商品查看权限的运营和主管开放；运营仍只看到自己的责任记录。

## 4. 刊登录入

### 4.1 待刊登来源

- 来源为二次调研已经提交且 `SalesClaimForecast.downstream_status = waiting_listing` 的责任记录。
- 按 `来源 + 业务期数 + 国家 / 站点 + 主 SKU + 负责人` 聚合成一条待刊登任务。
- 刊登只关联主 SKU，不关联子 SKU；保存聚合键和来源 claim ID 列表用于追溯。

### 4.2 新增方式

- 不提供脱离商品上下文的全局新增入口。
- 只能从对应主 SKU 的待刊登行内“新增一条”。
- 系统锁定主 SKU、国家、负责人。
- 每条记录必填：店铺、Item、刊登策略、第一周起始周期。
- 店铺、Item、刊登策略由运营自由文本填写；不建设店铺配置模块。
- 第一周默认下一业务周期，可改当前业务周期，不允许已结束的历史周期。
- 同一主 SKU 可一次添加多条记录。

### 4.3 校验与提交

- Item 去除首尾空白后必须非空，并在平台内全局唯一。
- 店铺和刊登策略去除首尾空白后必须非空。
- 批量提交为单数据库事务。任何一条重复、漏填、越权或服务端校验失败，整批回滚。
- 返回结构化错误，前端保留输入并标红具体行。
- 成功后为每个 Item 一次性创建首轮第 1-4 周记录，状态为 `待取数`。

## 5. 周期规则

- 业务周期固定为周四至下周三，以 Asia/Shanghai 计算。
- 一个 Item 的首轮四周从它选择的起始周期连续生成。
- 周次按该 Item 实际记录顺序编号；同一主 SKU 的不同 Item 周次互不影响。
- 首轮四周全部完成后，Item 里程碑为 `首轮观察完成`，不自动生成第 5 周。
- 运营或主管可手动新增后续周期；默认下一周期、可改当前周期，不允许已结束周期，不补历史空档。
- 后续周期继续使用 `待取数 -> 待复盘 -> 已完成`。

## 6. 周数据与复盘

### 6.1 自动字段

- 已核对 `group8_item_week_package_20260715.zip`：真实上游为 FineBI `ItemID财务数据八部`，现有脚本按 `站点 + 销售员 + 店铺 + ITEMID` 聚合。平台适配器应在成品表的 `订单量汇总 < 7` 过滤之前读取或接收聚合结果，不能直接依赖已过滤的 `ITEM周数据` 成品表。
- 订单量 = 周 Item 数据的订单量汇总。
- 总收入 = 总收入汇总。
- 一次毛利额 = 一次毛利汇总。
- 一次毛利率 = 一次毛利额 / 总收入，页面按百分比展示。
- 总收入为 0 时毛利率不可计算，接口返回空值、页面显示 `-`，不得误显示为 `0%`。
- 周 Item 数据按 `Item + 业务周期` 唯一；不做多行合并。
- 源数据无该 Item 时内部保持 `待取数`，不得写成 0；运营页面显示 `观察中` 和 `-` 指标，且不可复盘。
- 真实存在的源记录即使数值为 0，也保存为真实 0。

### 6.2 人工字段

- 每个周期的产品定位必填，只允许：引流款、利润款、淘汰款、稳定款、清仓款。
- 每个周期的优化操作必填，自由文本。
- 第 4 周额外要求四周总结必填；通过侧边编辑区填写，不占用常驻宽列。
- 自动字段只读；人工字段批量提交也使用整批原子校验。

### 6.3 跟踪状态

- Item 跟踪状态为 `正常跟踪 / 停止跟踪`，独立于产品定位。
- 任一观察周期改为淘汰款或清仓款都不改变 Item 跟踪状态。后续周期继续生成、取数、提醒和复盘，后续周期可以再选择其他定位；第 4 周仍要求四周总结。只有显式停止跟踪才暂停这些动作。
- 停止后不再取数、不再生成提醒；保留历史。
- 恢复后从下一业务周期继续尚未完成的周次，不补停止期间数据。
- 已产生周数据的刊登记录不得物理删除；真正下架、换店、换 Item 或重新刊登时作废旧记录并新增记录。
- 尚未产生任何周数据时，运营可纠正自己的店铺、Item、刊登策略和起始周期；产生周数据后，Item 和起始周期锁定，真实换店 / 换 Item 走作废旧记录并新增记录。刊登策略纠错继续允许并写审计。

## 7. 数据模型

### 7.1 `listing_record`

- 主键、来源聚合键、来源 claim ID 列表。
- 业务期数、国家 / 站点、主 SKU、主 SKU 名称、负责人。
- 店铺、Item（全局唯一）、刊登策略。
- 第一周期起止日期。
- 状态：`active / voided`；跟踪状态：`active / stopped`。
- 首轮完成时间、停止 / 恢复 / 作废时间及原因。
- 创建人、更新时间戳。

### 7.2 `item_observation_period`

- 主键、`listing_record_id` 外键。
- 周次、周期开始日、周期结束日。
- 状态：`pending_data / pending_review / completed`。
- 订单量、总收入、一次毛利额；一次毛利率读取时由一次毛利额 / 总收入计算，不重复落库。
- 产品定位、优化操作、四周总结。
- 数据来源快照、数据获取时间、提交时间。提醒去重复用 `NotificationLog`，不重复存提醒字段。
- 唯一约束：`listing_record_id + week_number`、`listing_record_id + period_start`。

使用现有 `AuditLog` 和 `NotificationLog`，不再增加专用审计表或通知表。

## 8. 接口

- `GET /listing-workbench`：返回待刊登任务、刊登记录和周期行；支持视图、关键词、周期、国家、店铺文本、负责人、周期状态、周次、定位、跟踪状态筛选。
- `POST /listing-workbench/listings/batch`：按一个主 SKU 任务原子创建多条刊登记录。
- `PATCH /listing-workbench/listings/{id}`：允许范围内的纠错、停止、恢复或作废。
- `POST /listing-workbench/listings/{id}/periods`：首轮完成后新增后续周期。
- `POST /listing-workbench/periods/review-batch`：原子提交一条或多条周期复盘。
- `GET /listing-workbench/summary`：按主 SKU 返回商品详情只读汇总。

周数据先提供内部服务函数 `apply_week_metrics(...)`，供现有周 Item 自动化或后续真实接口适配器调用；实际接口未确认前不创建猜测性的公开导入 API或配置项。

现有 `/summary/four-week` 路由删除，不保留兼容层。

## 9. 页面

- 导航新增“刊登与观察”，运营和主管均可进入。
- 页面只保留一张 Excel 式全量表，不使用顶部状态分栏。业务状态改为筛选条件，默认 `待刊登`；选择 `全部` 时展示待刊登主 SKU 任务和全部 Item 周期记录。待取数保留为系统内部状态，不作为运营筛选项。
- 运营强制本人范围；主管默认查看全部并可按负责人筛选。
- 删除“只看待我处理”：普通运营的本人范围由后端身份强制；主管通过负责人筛选缩小范围。主管切换运营视角时按所选运营查询，隐藏的旧负责人筛选不得继续生效，也不得把双角色主管自动切回本人。
- 业务状态为单选筛选：`全部 / 待刊登 / 待复盘 / 首轮观察完成 / 停止跟踪 / 已作废`，默认 `待刊登`。不提供 `待取数` 选项。
- 其他常用筛选：主 SKU / Item / 商品名称关键词、业务周期、国家、店铺文本、负责人。高级筛选：周次、产品定位、跟踪状态和周期处理状态；周期处理状态仅提供 `全部 / 待复盘 / 本周已复盘`。
- 表格采用两层结构：`来源 + 业务期数 + 国家 / 站点 + 主 SKU + 负责人` 为分组行，Item 周期为明细行。分组行解决待刊登主 SKU 与 Item 周期粒度不同的问题，不用空白字段伪装成同一种业务记录。
- 没有任何刊登记录的分组才属于 `待刊登`；一旦首次刊登成功，该分组不再属于待刊登。已有刊登分组仍在全量表中保留“新增店铺 + Item”入口，后续新增不重新制造待刊登状态。
- 分组行可展开批量刊登编辑区，继续支持同一主 SKU 一次填写多条店铺、Item、刊登策略和第一周起始周期，并保持整批原子提交。
- 明细区一行一个 Item 周期；冻结主 SKU、店铺、Item、负责人、周次、业务周期。自动指标只读，产品定位和优化操作只在待复盘行可编辑；只有待复盘行显示批量勾选框。
- 内部 `pending_data` 在页面显示为中性的 `观察中`，四个自动指标统一显示 `-`，不形成运营任务；数据成功入库后自动显示 `待复盘`；`completed` 显示为 `本周已复盘`。
- 选择 `全部` 时按需要行动的记录优先排序：待刊登、待复盘在前，观察中和已完成历史在后；同一分组内按 Item、周次稳定排序。
- 待刊登为空时提示“当前没有待刊登主 SKU，可选择全部查看观察记录”；其他筛选为空时提示当前条件下没有记录。
- 暂不增加页签数量角标或待办统计字段；现有返回结构没有可靠的待刊登计数口径。
- 第 4 周通过“填写 / 查看总结”打开侧边编辑区。

## 10. 通知

- 周数据成功入库后给对应运营提醒一次；同一 Item 周期通过 `NotificationLog.dedupe_key` 去重。
- 内部待取数状态不发送待复盘提醒，后续导入成功后再发送。
- 停止跟踪不提醒。
- 二次调研和观察周期提交的淘汰款都复用每天 10:00 左右的主管汇总提醒；清仓款不触发。观察期按定位变化事件去重：首次进入淘汰款生成事件，连续淘汰不重复，改为其他定位后再次进入淘汰款时生成新事件。平台不接入或写回外部系统，也不增加主管“已处理”按钮、状态或待办；发送成功即完成平台责任，失败继续重试。

## 11. 迁移与安全

- 新迁移创建 `listing_record` 和 `item_observation_period`，并删除旧 `four_week_summary`。
- 只在新开发环境执行迁移；不得对 `101.132.26.138` 或生产库执行。
- 不提交 `.env`、密码、Token 或真实接口凭据。

## 12. 验收

- 一个待刊登主 SKU 可原子创建多条“店铺 + Item”。
- 重复 Item 或任何漏填导致整批零落库并返回行级错误。
- 每个 Item 正确生成四个周四至周三周期；不同 Item 可从不同周期开始。
- 周数据缺失与真实 0 可区分；毛利率正确按百分比展示。
- 每周定位和优化操作必填；第 4 周总结必填。
- 停止 / 恢复、首轮完成和后续新增周期符合规则。
- 第 N 周提交淘汰款后 Listing 仍为正常跟踪，第 N+1 周仍可取数、提醒和复盘，并可选择利润款等其他定位；第 4 周淘汰款仍校验四周总结。
- 利润款 -> 淘汰款 -> 淘汰款 -> 稳定款 -> 淘汰款只生成两次观察期淘汰提醒事件；同一事件发送成功后不重复，发送失败仍可进入下一次 10:00 汇总。
- 运营不能读取或修改他人记录，主管可以按负责人查看和纠错。
- 工作台只有一张分组表且没有顶部状态页签；默认显示待刊登，选择全部能看到待刊登分组和全部 Item 周期。
- 待取数不作为筛选项，观察中行不可复盘；数据到达后的待复盘行可勾选、编辑和提交。
- 普通运营只看本人；主管首次进入默认看全部，切换角色和负责人后不存在隐藏筛选残留。
- 待刊登分组可批量刊登；已刊登分组可继续新增店铺和 Item；商品详情汇总继续可用。
- 旧四周总结接口返回 404，旧表不再存在于新迁移后的开发库。
