# 分配台紧凑重设计

## 目标

减少分配台纵向滚动和重复信息，让主管在一个桌面视口内完成筛选、查看负载、生成推荐和提交分配。

## 页面结构

- 将“商品看板 / 机会池流程”和流程节点合并为一个横向导航条；测试阶段提示保留在导航条右侧。
- 非认领、非二次调研页面的主管统计栏缩窄到约 `170px`，四个指标单列纵向排列。
- 分配台顶部使用紧凑工具栏；“提交分配 / 运营配置”组成不可拆分的相邻操作组，筛选、清空、关键词搜索和分页保留在下方命令栏。
- 桌面宽屏保持一行；空间不足时允许按控件组换行，不能横向溢出或遮挡。

## 运营负载卡

- 继续按站点、自定义顺序显示运营，不改变排序和负载计算。
- 站点只显示一次，不再同时出现在右上角标签和说明文字中。
- `assignment_priority > 0` 时在姓名前显示彩色优先级徽标；`0` 不显示徽标。
- 重点品类 1/2 改为两个紧凑标签，长文本省略并通过 `title` 提供完整内容。
- 负载条和“组 / 子 SKU / 本次增加”保留。
- 所有运营负载卡放在吸顶自适应网格中；主管下滚分配列表时仍可见，运营较多时直接换行，不提供内部横向滚动。
- 当前预览分配发生变化后，负载卡的合计及“本次增加”立即更新。

## 运营配置

- 从分配台主内容底部移除常驻配置表。
- 分配台页头增加“运营配置”按钮，点击打开右侧宽抽屉。
- 抽屉复用现有启用、运营姓名、站点、品类、优先级、站点内排序、新增、删除和保存能力。
- 站点内排序支持拖拽和上下按钮；跨站点拖拽不生效，拖拽仅修改待保存配置。
- 关闭抽屉不自动保存；点击“保存运营配置”沿用现有 API 和成功提示。

## 分配公平性跟进

- 站点仍是硬过滤条件。
- 推荐改为当前主 SKU 组负载优先的贪心列表调度；重点品类、人员优先级、自定义顺序和姓名只处理同负载并列。
- `assignment_priority` 是同负载决胜项，不是可持续扩大个人任务量的权重。
- 该跟进由 2026-07-16 用户反馈授权，覆盖了本设计最初“只改界面、不改算法”的边界。

## 非目标

- 不修改分配提交接口、人员配置数据库字段或权限；不引入匈牙利算法、整数规划或新依赖。
- 不新增依赖，不拆分现有 `App.tsx`。
- 不改变移动端业务能力；移动端只做自然换行和全宽抽屉适配。

## 验证

- 静态布局测试覆盖合并导航、相邻提交/配置操作组、可换行工具栏、吸顶负载网格、配置抽屉、同站点拖拽、优先级徽标和去重站点信息。
- 前端完整测试与生产构建通过。
- Playwright/Edge 最新覆盖 2048px 和 1366px，验证 16 名运营分别自动换为 2 行和 4 行，负载区及整页横向溢出为 0，“提交分配 / 运营配置”同排相邻；此前移动端、吸顶、实时计数和拖拽检查继续保留。
- 后端全量回归通过后，API 与前端使用候选容器滚动切换，不重启 PostgreSQL、Redis、worker 或 scheduler。
