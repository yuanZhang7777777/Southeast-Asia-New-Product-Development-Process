# 销售自选与备货申请工作流设计规格

> 日期：2026-07-21
> 状态：已确认，可实施
> 适用分支：`lxc/integrated-workflow`
> 环境边界：仅开发环境验收；不得连接、重启或部署生产服务器 `101.132.26.138`。

## 1. 目标

在现有“机会池 → 分配/认领 → 主管复核 → 导出 → 到货 → 二次调研 → 刊登与观察”主链路中补齐正式备货申请，并新增销售自选入口：

- 选品1、选品2经主管复核通过后，由对应运营填写并提交自己的备货申请。
- 销售自选不再复刻旧选品3 Excel；运营直接创建主 SKU 与一个或多个子 SKU，并逐子 SKU 决定是否备货。
- 主管在导出中心勾选已提交申请导出；导出即确认，不新增独立审核页面。
- 有可用库存且不备货的销售自选商品直接进入待刊登；无库存且不备货进入“暂不推进”。
- 复用现有到货、二次调研、刊登和 Item 周期观察能力，不新增第三套工作流引擎。

## 2. 非目标

- 本期不接入旧选品3、选品4 Excel 导入。
- 本期不自动查询海外仓库存；库存由运营在公司系统查看后人工确认。
- 本期不在平台内执行采购、供应链核价、MOQ、交期或备货仓库审批。
- 不把 ERP、PLM、钉钉账号密码、Cookie、token 或 `.env` 提交到仓库。
- 不触碰生产服务器、生产数据库、生产 Redis、生产上传文件和生产端口。

## 3. 业务对象与粒度

### 3.1 责任记录

`SalesClaimForecast` 继续作为“运营 + 子 SKU”的负责人和后半段状态真源。同一选品2子 SKU 被多名运营通过时，每个 claim 独立，不互相覆盖。

### 3.2 备货申请

`StockingRequest` 是运营最终填报快照；一条 claim 最多对应一条有效申请。申请必须关联 `claim_record_id`，导出行必须关联 `stocking_request_id`。

### 3.3 销售自选

一次销售自选可创建一个主 SKU 和多个子 SKU。系统为每个子 SKU 建立：

1. `NewProductOpportunity`；
2. `SourceRecordSnapshot`，来源标记为销售自选；
3. 当前登录运营的 `SalesClaimForecast`，不要求再次填写认领表，也不经过主管认领复核。

销售自选业务期由系统按北京时间创建日期生成 `销售自选YYYYMMDD`，保证导出中心和后续按期页面不会漏记录。

## 4. 状态模型

### 4.1 选品1 / 选品2

```text
主管复核通过
  → claim.waiting_stocking_request + request.draft
运营提交
  → request.submitted + claim.waiting_export
主管勾选并成功导出
  → request.exported + claim.waiting_arrival
PLM 匹配到货
  → claim.waiting_secondary_research
二次调研提交
  → claim.waiting_listing 或 disabled
刊登完成
  → listing_observation
```

### 4.2 销售自选逐子 SKU 决策

```text
确认无可用库存 + 选择备货
  → request.draft + claim.waiting_stocking_request

确认有可用库存 + 不备货
  → 不创建正式申请 + claim.waiting_listing

确认无可用库存 + 不备货
  → 保留机会/claim/草稿内容 + claim.stocking_paused
  → 后续“改为备货”恢复到 waiting_stocking_request
```

决策按子 SKU 保存，不按主 SKU 整组强制一致。“确认有可用库存”和“选择新增备货”互斥，页面和 API 均拒绝同时为真的矛盾组合。

### 4.3 编辑边界

- 草稿可反复保存。
- 已提交但尚未导出时，运营仍可修改并再次提交；导出始终使用最新提交值，审计日志保留修改前后。
- 已导出申请只读，不允许运营直接覆盖；本期不实现撤回、退回或重复导出。
- 导出失败不得推进 request 或 claim 状态。

## 5. 正式申请字段与校验

| Excel 列 | 字段 | 页面/系统规则 |
|---|---|---|
| A | 操作状态 | 首次导出留空，由外部表后续处理 |
| B | 申请日期 | 必填；默认北京时间当天，运营可改为其他日期；Excel 仅输出日期 |
| C | 备货类型 | 必填；`首次备货` / `补货`，默认首次备货 |
| D | 选品数据源 | 系统生成：选品1、选品2/财根、销售自选 |
| E | 销售员 | 服务端取当前登录运营或关联 claim，客户端不可伪造 |
| F | 主 SKU | 来源带出；销售自选手填 |
| G | 子 SKU | 来源带出；销售自选逐条手填，组内不可重复 |
| H | 成本价 | 大于 0；选品1从“商品成本-含税（元）”预填，选品2从“进价”预填，销售自选手填；运营可修改最终值 |
| I | 单个体积 | 大于 0；优先 ERP 计算，失败或缺尺寸时允许运营手填 m³ |
| J | 备货单销 | 大于 0，运营填写 |
| K | 备货数量 | 服务端计算 `ceil(备货单销 × 30)` |
| L | 备货国家 | 必填；默认来源国家/站点，运营确认或修改 |
| M | 备货仓库 | 可选自由文本；不提供默认/建议；可留空，由主管在外部表补填 |
| N | 货值 | 服务端计算 `最终成本价 × 备货数量` |
| O | 体积 | 服务端计算 `单个体积 × 备货数量` |
| P | 补货原因 | `补货`时必填；`首次备货`时可空 |

主/子 SKU、国家和自由文本提交前去除首尾空白。金额与体积在数据库保存原始数值，前端和 Excel 负责合适的小数格式，不将百分比规则误用于金额。

## 6. ERP 单个体积

### 6.1 接口边界

- 登录使用现行 Open Login，token 仅保存在进程内存。
- 业务请求使用 `Authorization: <accessToken>`，不得加 `Bearer`，不得使用 Cookie 或历史固定 token。
- 产品列表业务 URL 通过环境变量配置，不在代码中提交账号密码。
- 产品列表下载沿用已核实的“两段式”协议：创建产品列表任务，再轮询下载列表中新增的 `productList/success` 记录并下载 XLSX。
- 测试使用桩函数/内存工作簿，不访问真实 ERP。

### 6.2 体积算法

1. 包装后三维均为大于 0 的数时，使用整组包装尺寸。
2. 包装维度有任一缺失/无效时，整组回退到产品三维；禁止两组混用。
3. 产品三维也不完整时返回“需手填”，不阻止保存草稿，但阻止正式提交；不从来源表“包装后体积”静默预填。
4. `单个体积(m³) = 长(cm) × 宽(cm) × 高(cm) ÷ 1,000,000`。
5. 字符串数字、前后空白按数字解析；零、负数和非数字视为无效。

样例必须固定验证：

- `GSHWAC225ND` → `0.000132916 m³`
- `SH-OD-492-BL` → `0.000088775 m³`

## 7. 后端接口

现有 `/stocking` router 保留，但权限下沉到具体接口：

- `POST /stocking/self-selections`（operator）：创建销售自选主/子 SKU 记录并提交逐子 SKU 决策。
- `GET /stocking/my-requests`（operator）：只返回当前登录运营自己的申请/暂停/直达刊登记录。
- `PUT /stocking/requests/{request_id}`（operator）：保存自己的草稿或更新尚未导出的提交记录。
- `POST /stocking/requests/{request_id}/submit`（operator）：服务端校验和计算后提交。
- `POST /stocking/decisions/{claim_record_id}`（operator）：变更逐子 SKU 库存/备货决策；只允许本人记录。
- `POST /stocking/volume-preview`（operator）：批量按子 SKU 尝试 ERP 体积解析，失败返回可手填状态。
- `GET /stocking/export-periods`、`GET /stocking/available-list`（manager）：只展示 `submitted` 申请。
- `POST /stocking/available-list/export`（manager）：请求体携带非空且去重的 `request_ids`，只导出所选已提交申请。

所有写接口从认证上下文获取运营/主管身份，并写审计日志。开发环境关闭认证时仅允许测试显式提供 actor；非本地环境不得信任客户端销售员姓名。

## 8. 导出、PLM 与追溯

- 主管选择导出成功后，`ExportBatch.exported_by` 记录登录主管。
- `ExportRow` 关联 request/claim，并保存导出所需最终值快照，避免申请后续变化破坏历史。
- Excel 保持 16 列顺序与现有按国家分 Sheet 规则；B 列使用各申请的 `application_date`，不是统一导出时间。
- 已导出 request 不再进入待导出清单，重复 request ID 返回业务错误，不重复推进状态。
- PLM 仅匹配 `waiting_arrival` 且存在对应 `ExportRow` 的 claim；不再让尚未导出的 `waiting_export` 提前进入到货。
- 销售自选没有 ReviewRecord 也可在真实导出后被 PLM 匹配。

## 9. 前端交互

### 9.1 导航

- 运营看到“备货申请”；主管看到“导出中心”。
- 复用现有 `stock` 导航，不增加第三套选品工作台。

### 9.2 运营页面

- 顶部提供“销售自选”按钮，抽屉/弹层内填写主 SKU、主 SKU 名称、国家，并可增加多个子 SKU。
- 每个子 SKU 单独选择“有/无可用库存”和“备货/不备货”。
- 需要备货时展开申请字段；可批量保存草稿，逐条或勾选提交。
- 页面按主 SKU 分组，并提供状态、来源、国家、关键字筛选；默认优先显示待填写/待提交。
- 申请表不强行塞进超宽 16 列；身份与计算字段紧凑只读，编辑字段使用分组表单。

### 9.3 主管页面

- 保留现有业务期列表和 16 列预览。
- 增加状态筛选、申请勾选与“导出选中”；全选等价于导出当前筛选结果。
- 不保留无业务价值的“查看明细”二次入口。

### 9.4 其他页面

- 商品看板展示 `待填备货申请`、`待导出`、`暂不推进`、`待刊登` 等中文状态。
- “有库存且不备货”的销售自选直接复用现有刊登与观察工作台，不增加特例页面。

## 10. 错误处理

- 权限越界返回 403；对象不存在返回 404；业务字段或状态不合法返回 400/409。
- 批量创建或导出采用事务：任一子项失败则整批不写入/不推进，前端标出具体错误。
- ERP 超时、登录失败、下载失败或 SKU 无数据时不泄露 URL 查询参数、账号、token 或响应头；返回“未取得体积，可手填”。
- 导出文件生成成功后再提交状态变化；生成失败回滚。
