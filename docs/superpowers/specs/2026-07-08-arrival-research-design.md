# 到货承接与二次调研第一版设计

日期：2026-07-08

## 目标

把前段已经复核通过并进入备货导出的商品，在 PLM 出现前一天到货 / 入库 / 可发库存后，自动生成给对应运营的二次调研待办。第一版只做到“货到了以后运营知道该填什么”，不做推品、刊登后 1-4 周监控和四周总结。

## 范围

包含：

- 使用练玉君业务账号同步 PLM 前一天库存明细。
- 同步窗口按 Asia/Shanghai 前一自然日 00:00:00-23:59:59。
- 保存同步批次、源文件和拆分结果：全量、集团八部、其他集团。
- 按平台内已通过主管复核的认领记录匹配主 SKU / 子 SKU / 国家。
- 到货 / 二次调研待办以 PLM `海外仓可发 > 0` 触发；库存来自其他集团时不阻塞，仍按平台认领关系给对应运营生成待办。
- `公共池库存` 第一版只作为展示 / 对账字段，不单独触发待办。
- 二次调研待办填写市场监控表的 `AL-AO` 字段：调研时间、竞对链接、二次调研结论、产品定位。
- PLM 销售员只做校验 / 辅助展示，不覆盖平台认领运营。

不包含：

- 推品表 `【推品】海外仓精品流程.xlsx` 的 1-4 周监控。
- 刊登确认、Item、店铺、广告、刷单等刊登后动作。
- 自动写回钉钉在线表。
- 全量库存常驻 BI 查询。

## 数据来源

### PLM 前一天到货源

第一版使用旧 PLM 导出链路，因为它已确认支持日期窗口：

- 登录：`/api/system/login`
- 导出：`/api/hz-inventory/overseas/details/exportSummaryExcel`
- 下载中心：`/api/hz-inventory/minioDownloadFile/selectPage`
- 日期参数：`latestStorageTimeStart` / `latestStorageTimeEnd`

新 IT 库存明细接口可以用于当前库存查询和对账，但在确认日期筛选与固定排序前，不作为每日前一天到货主链路。

### 平台业务源

匹配对象只来自平台中已经通过主管复核的认领记录。运营归属使用平台认领销售员。前段字段继续保留 source file、sheet、row、batch 等追溯信息。

## 匹配规则

第一版用最小可解释规则：

1. 主匹配键：`子 SKU + 国家`。
2. 辅助校验：主 SKU、商品名称、仓库。
3. 如果一个子 SKU + 国家对应多个平台认领记录，按认领记录分别生成待办。
4. 如果 PLM 有到货但平台没有通过复核的认领记录，不生成运营待办，只进入未匹配列表。
5. 如果平台有认领记录但 PLM 没有前一天到货，不生成到货待办。

## 待办触发

满足以下条件生成二次调研待办：

- 平台记录已通过主管复核。
- PLM 前一天数据匹配到该商品。
- PLM `海外仓可发 > 0`。

集团判断不阻塞待办：

- `集团 = 集团八部`：正常到货待办。
- `集团 != 集团八部`：仍生成待办，因为可发库存不因集团归属阻塞。

## 去重与状态机

已确认口径：

- 到货待办唯一键：`认领记录ID + 子 SKU + 国家`。
- 同一期同一个认领记录下，同一子 SKU + 国家第一次满足 `海外仓可发 > 0` 时生成待办并推送。
- 后续每日 PLM 同步再次命中同一唯一键，只更新库存快照、最后同步时间和展示字段，不重复生成待办、不重复推送。
- 如果后续产生新的认领记录 ID，即使子 SKU + 国家相同，也按新的业务责任生成新的待办。

状态机：

- `pending_research`：首次可发后创建待办，等待运营填写 AL-AO。
- `submitted`：运营已提交二次调研字段。
- `stale_stock_update`：库存更新事件类型；同一唯一键后续再次命中时记录事件，但待办继续保持 `pending_research` 或 `submitted`。
- `closed`：进入刊登 / 推品后关闭；关闭规则在后半段实现前再细化。

## 二次调研字段

运营页面第一版只开放以下字段：

| 市场监控列 | 字段 | 责任 |
|---|---|---|
| AL | 调研时间 | 运营填写，默认今天可改 |
| AM | 竞对链接 | 运营填写；无变化可空 |
| AN | 二次调研结论 | 运营填写；无变化填“无变化” |
| AO | 产品定位 | 运营选择：引流款 / 利润款 / 淘汰款 / 信心款 |

如果产品定位为淘汰款，系统标记“需主管处理外部定位”，并可复用后续钉钉提醒能力通知主管。

## 页面设计

新增一个后段入口：`到货 / 二次调研`。

列表展示：

- 运营、主 SKU、子 SKU、国家、仓库、商品名称。
- 认领单销、公司单销、海外仓可发、公共池库存、首次上架时间、产品定义。
- 来源集团：集团八部 / 其他集团。
- 待办状态：待调研、已提交、淘汰款待主管处理。

运营只能看到自己的待办。主管 / 管理员可以看到全部。

## 后端设计

复用现有 `arrival` 模块，不新建大模块。

最小新增数据：

- 到货同步批次：记录日期窗口、源文件、总行数、集团八部行数、其他集团行数、未匹配数量。
- 到货匹配记录：保存 PLM 行关键字段、匹配到的平台 opportunity / claim、运营、状态。
- 二次调研提交：保存 AL-AO 字段和提交人 / 时间。

接口草案：

- `POST /arrival/sync-previous-day`：主管触发前一天同步。
- `GET /arrival/research-tasks`：按角色返回二次调研待办。
- `POST /arrival/research-tasks/{id}/submit`：运营提交 AL-AO。
- `GET /arrival/export-market-monitor`：后续导出市场监控表结构，第一版可以只做预留。

## 错误处理

- PLM 登录失败：同步批次标记失败，不改已有待办。
- 下载中心超时：同步批次标记失败，可重试。
- 源文件字段缺失：拒绝导入并记录缺失字段。
- 匹配不到平台记录：进入未匹配列表，不生成运营待办。
- 重复同步或跨天连续命中：幂等处理，同一 `认领记录ID + 子 SKU + 国家` 不重复生成待办，只更新最新库存快照。
