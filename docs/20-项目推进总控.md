> Updated: 2026-07-21 Asia/Shanghai

## 1. 当前阶段

当前不是需求从零确认阶段，也不是只确认导入口径阶段。

当前阶段是：

```text
前段 MVP 稳定运行
  -> 前半段与后段代码已合并为统一开发分支
  -> 当前统一基线已验证并部署开发环境
  -> 销售自选与新版备货申请本地候选已实现，待开发部署 / UAT
  -> 运营 / 主管完成独立开发环境业务验收
  -> 获取周 Item 真实接口并接自动调度
  -> 生产窗口另行审批
```

当前已经实现并进入 UAT 的第一版范围：

- 只处理 `选品1：海外仓开发部门开发新品认领-反馈`。
- 只处理 `选品2：海外仓财根团队开发新品认领-反馈`。
- 做导入、主管分配、运营认领/不认领、主管复核、导出。
- 不做在线表自动写回入口。
- 不做选品3、选品4、直发转海外仓、老品来源。
- 不做采购/供应链/下单待办。

2026-07-21 销售自选与新版备货申请已形成本地候选，待部署到开发环境并完成 UAT：库存由运营自行查看；已有库存且不新增备货时直接进入待刊登，无库存且需要备货时进入申请、主管勾选导出、待到货和二次调研；无库存且不备货时进入可恢复的 `暂不推进`。备货仓库为可选自由文本；采购 / 供应链 / 下单执行仍在平台外。

## 4. 下一步推进顺序

当前优先顺序为：先由运营 / 主管完成独立开发环境业务验收，再接周 Item 真实接口和自动调度；下列前段演示步骤保留为回归路径，不再代表唯一主线。

### Step 1：开发环境业务验收

目标：让运营和主管确认统一版本符合真实业务操作。

要做：

- 使用 `http://139.224.2.166:18081`，不得在生产环境做写入式验收。
- 第一轮由刘学城使用同一账号测试：先用主管视角导入、分配，再切换运营视角处理认领、二次调研、刊登和观察，最后切回主管视角复核与核对汇总。
- 用开发账号和少量可控数据检查商品看板、机会池、分配台、运营认领、主管复核、按期导出、二次调研和刊登观察。
- 当前可直接从运营视角“二次调研”进入 `GZMO075`：3 个子 SKU 均为开发 UAT 模拟到货，先验证整组字段和同步，再按定位分支继续；开发库变更前备份为 `workflow_dev_before_secondary_uat_20260721_114310.sql.gz`。
- 刊登观察阶段先在“业务状态”选择`全部`，展开主 SKU 后核对 Item 和当前可见周期；未开始周期不会提前显示。商品看板详情的“二次调研”“刊登与观察”用于核对只读历史。
- 记录实际操作问题，再按影响程度做局部修正。

### Step 2：用少量真实 Excel 走完整链路

目标：确认真实 `选品1`、`选品2` 能从导入走到导出。

要做：

### Step 4：接入钉钉通知和入口

目标：用户能在钉钉里收到通知，点击后进入我们的平台处理。

第一版钉钉做：

- 企业内部应用 / 网页应用作为入口。
- 新品待办互动卡片发送个人任务提醒。
- 卡片按钮带平台入口链接。
- 链接进入具体任务或模块。
- 后端记录通知发送日志和去重 key。
- 工作通知 `link` / `action_card` 保留为兜底。

第一版钉钉不做：

- 钉钉待办。
- 在线表自动写回。
- 聊天机器人复杂交互。
- 真正的卡片内直接填写业务数据。

### Step 5：生产发布评估

目标：开发环境 UAT 完成后，再决定是否申请生产发布窗口。

要做：

- 汇总开发环境 UAT 结果和未解决问题。
- 单独申请非工作时间生产窗口。
- 发布前备份生产数据库，构建候选容器并验证健康。
- 发布过程不重启 PostgreSQL、Redis、worker 或 scheduler；切流后回读实际上游和静态资源。
