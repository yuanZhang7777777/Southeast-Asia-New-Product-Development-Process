## 1. 当前阶段

当前不是需求从零确认阶段，也不是只确认导入口径阶段。

当前阶段是：

```text
第一版 MVP 功能基本开发完成
  -> 本地端到端演示验收
  -> 修正 UI / 流程 / 导出细节
  -> 接入钉钉通知和钉钉内入口
  -> 云服务器部署
  -> 小范围试用
```

第一版范围已经冻结：

- 只处理 `选品1：海外仓开发部门开发新品认领-反馈`。
- 只处理 `选品2：海外仓财根团队开发新品认领-反馈`。
- 做导入、主管分配、运营认领/不认领、主管复核、导出。
- 不做在线表自动写回入口。
- 不做选品3、选品4、直发转海外仓、老品来源。
- 不做采购/供应链/下单待办。

## 4. 下一步推进顺序

### Step 1：本地重新跑起来

目标：确认当前系统不是“代码写了但跑不通”。

要做：

- 跑后端测试。
- 跑前端构建。
- 启动后端和前端。
- 跑 `backend/scripts/seed_demo_statuses.py`。
- 检查商品看板、机会池、分配台、运营认领、主管复核、导出入口都能打开。

### Step 2：用少量真实 Excel 走完整链路

目标：确认真实 `选品1`、`选品2` 能从导入走到导出。

要做：

- 用少量真实 `选品1` 数据导入。
- 用少量真实 `选品2/财根` 数据导入。
- 主管一键分配。
- 运营认领/不认领。
- 主管复核。
- 导出两个 Excel：
  - `海外仓备货申请表` 结构。
  - 新品中央字段追溯导出。

### Step 3：修业务演示中暴露的问题

只修影响演示和试用的问题：

- 页面文案不对。
- 状态看不懂。
- 按钮位置不合理。
- 商品卡片信息缺失。
- 导出字段不对。
- 真实 Excel 导入失败。

不在这个阶段新增后段大功能。

### Step 4：接入钉钉通知和入口

目标：用户能在钉钉里收到通知，点击后进入我们的平台处理。

第一版钉钉做：

- 企业内部应用 / 网页应用作为入口。
- 新品待办互动卡片发送个人任务提醒。
- 卡片按钮带平台入口链接。
- 链接进入具体任务或模块。
- 后端记录通知发送日志和去重 key。
- 工作通知 `link` / `action_card` 保留为兜底。

第一版钉钉不做：

- 钉钉待办。
- 在线表自动写回。
- 聊天机器人复杂交互。
- 真正的卡片内直接填写业务数据。

已确认钉钉卡片接入文档：

| 内容 | 文件 |
|---|---|
| 新品待办卡片模板、变量、createAndDeliver 调用方式 | `docs/19-钉钉新品待办卡片接入说明.md` |
| 最新模板 ID | `a428e864-5416-4ea6-ad29-36e19e0615e2.schema` |
| 当前后端最小 sender | `backend/app/dingtalk_card_sender.py` |

### Step 5：云服务器部署和小范围试用

目标：让主管和少量运营真实试用。

要做：

- 配置 PostgreSQL。
- 配置生产环境变量。
- 配置文件存储：OSS 作为主存储；如果运行时异常，先用服务器本地存储兜底。
- 部署后端、前端、反向代理。
- 配置钉钉回调/应用首页 URL。
- 小范围试用一轮，记录问题。
