## 1. 当前阶段

当前已经离开“只做原型 / 只对齐字段”阶段，进入真实业务切入准备：

```text
前后段统一开发分支
  -> 销售自选与正式备货申请写入式 UAT 已确认无问题
  -> 二次调研待处理 / 已提交显隐、紧凑刊登 / 观察、备货折叠、国家标签和 SKU 详情入口已部署并完成只读 UI 冒烟
  -> PLM 下载、解析和手工精确处理已具备，自动下载到正式处理尚未闭环
  -> 2026-07-23 历史关注命中 1 条并向刘学城成功投放 1 张卡，业务表未变化
  -> 14 周 FineBI 历史 Item 候选对账已完成，周指标聚合与运行调度尚未接入
  -> 下一步完成历史命中自动生成二次调研和旧 Item 周指标最小 UAT
  -> 再确定新业务切入期，停止新增数据双录
  -> 下一笔正式导出完成现行 PLM 精确匹配 UAT
  -> 复用已有 FineBI ItemID 过滤前原始数据接自动取数
  -> 生产窗口单独审批
```

第一版继续冻结为：两张内部反馈表导入、主管分配、运营认领 / 不认领、主管复核、销售自选三分支、运营备货申请和主管勾选导出。第一版不做在线表自动写回、采购 / 供应链 / 下单待办、匹配异常工作流或选品3/4等新来源。

## 4. 下一步执行顺序

### Step 1：可操作界面收敛到测试版（已部署，待用户业务实测）

- `刊登与观察` 分为 `刊登任务 / 周期观察`，默认进入有数据的周期观察；周期摘要优先展示 Item、店铺、国家、当前周、指标、定位和操作，SKU 可进入现有商品详情，长文本按需展开。
- 站点 / 国家是结构化一级筛选，店铺是独立辅助筛选；二次调研按待处理 / 已提交保留记录，并支持关键词、站点 / 国家、业务期和负责人组合筛选。备货申请默认收起且一次只展开一条。
- 已复盘周期默认只读，点击“纠错”后才允许编辑；取消不写入，保存仍沿用现有校验和审计。

### Step 2：用一条历史 PLM 命中验证后半段

- 历史到货单人卡已成功且幂等状态完成；后续只监控次日新命中，不再重放 2026-07-22 卡片。
- 用开发专用开关和单条样本，把一个历史命中转换为可追溯二次调研任务；保留当前 PLM 销售员为真实责任人，明确记录刘学城是开发代测操作人。
- 备份后验收任务、来源快照、到货时间、状态、审计和幂等；不批量导入 2,237 个关注键。

### Step 3：单独完成现行正式 PLM UAT

- 选择尚未处理过的旧缓存日，从其 `new_arrival` 挑 1 条，准备唯一的正式 `waiting_arrival + exported ExportRow` 开发记录。
- 写前备份并只读预查，要求 `国家 + 子 SKU + 当前 PLM 销售员` 计划匹配恰好为 1；调用一次正式处理入口，保持定时和钉钉自动发送关闭。
- 验收 batch / item / ArrivalRecord、`waiting_secondary_research`、审计和同文件重跑幂等。开发库现有 2026-07-16 匹配痕迹先审计，不用作本次样本。

### Step 4：用历史 Item 做一条周指标 UAT

- 从 202 个唯一候选中按 TH / VN / PH 各挑一条无冲突样本；第一轮先在测试库处理，不自动应用 364 个多候选。
- 使用过滤前 FineBI 原始行，按精确 `Item + 店铺 + 国家 + 周四至周三周期` 求和订单量、总收入和一次毛利；不使用 `< 7` 成品表。
- 来源快照校验完整后才调用 `apply_week_metrics(...)`；覆盖真实零、完全缺行、多归属、店铺 / 国家不一致、停跟和重复运行。
- 纯聚合和落库边界通过后，再接受控下载、调度、失败重试、观察期提醒发送和运行监控。

### Step 5：确定新业务切入期并平台先行

- 业务指定切入期和首批实际使用人员；切入期后新增 `选品1 / 选品2 / 销售自选` 全部从平台进入，旧 Excel 只读或接收平台导出。
- 每天核对导入数、分配数、提交数、导出数和异常，不再维护第二套手工状态；ERP 凭据未齐前继续手填长宽高。

### Step 6：生产发布评估

- 汇总切入期试运行、两条 PLM UAT、Item 周指标 UAT 和开放风险。
- 单独申请非工作时间生产窗口；发布前备份，构建候选容器并验证健康。
- 不在业务使用时段重启生产；PostgreSQL 和 Redis 不随应用发布重建。
