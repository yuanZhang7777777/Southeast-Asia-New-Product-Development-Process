# 东南亚新品流程项目文档入口

> 本目录是后续需求讨论、开发实现、会话切换时的共同上下文。  
> 新会话或新开发人员接手前，优先阅读本文件，再阅读下方两份核心文档。

> 🧭 一句话框架（2026-06-29 运营视角校正）：本平台是 **“两段主流程 + 一座外部桥”**。
> 平台只拥有 **前段（入池→分配→认领→审核→出可备货清单）= MVP** 与 **后段（到货承接/提醒→二次调研→具体调整/竞品监控→刊登确认→1-4周监控→四周总结）**；
> 中间 **采购 / 供应链 / 下单执行 = 外部桥**。开发部署版已支持销售自选、运营填写 / 保存 / 提交备货申请、主管勾选导出和外部状态登记；写入式业务 UAT 仍待完成，且仍不建设采购 / 供应链执行待办。
> 角色口径：销售 = 运营、主管 = 运营负责人。

统一开发分支：`lxc/integrated-workflow`；开发环境当前部署 `36a9ae9`，开发库为 `d0e2f3a4b567 (head)`，验证地址为 `http://139.224.2.166:18081`；生产仍运行 `b373d65`，本次未连接或变更生产，两者严格隔离。

## 口径优先级

发生冲突时按以下顺序判断，不从旧原型或旧实施计划反推需求：

1. `2026-07-09-已确认需求记录.md`：用户逐项确认的现行口径。
2. `01-需求文档-东南亚新品流程.md`：按现行口径整理后的完整业务说明。
3. `21-后半段需求领导对齐问题清单.md`：后半段已确认事项和仍需业务回答的问题。
4. `02-功能实现状态.md`：代码是否已经实现，不能用需求文档中的“已确认”代替实现验证。

`09-MVP第一版-选品1单表跑通规格.md`、`12-新品全链路原型架构设计.md`、`14-新品流程产品原型需求确认.md`、`15-新品流程业务会议待确认问题清单.md` 以及 `docs/superpowers/` 下的旧规格 / 计划保留为历史讨论材料；其中旧导出状态、店铺字段、从刊登日起滚动 7 天、周记录选填或移除四周总结等旧描述均不得作为当前实现依据。

`specs/001-frontstage-mvp/plan.md` 与 `specs/001-frontstage-mvp/tasks.md` 是原始前段 MVP 的历史执行基线；当前 Spec Kit 行为以同目录 `spec.md`、`data-model.md`、`quickstart.md` 和 `contracts/api.md` 的最新口径为准。

## 文档维护规则

1. 讨论出新规则时，先更新 `01-需求文档-东南亚新品流程.md`。
2. 功能实现、联调、上线、废弃时，更新 `02-功能实现状态.md`。
3. 不确定的内容不要写成已确认结论，统一放到“待确认问题”。
4. 已确认规则如果被推翻，要在变更记录中说明日期、原因和新口径。
5. 文档里的“建议表/模块名”不等于最终数据库表名，最终实现前需要再做技术命名。
