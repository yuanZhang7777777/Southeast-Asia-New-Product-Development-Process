# 内部 Agent 协作与实现规范

> 日期：2026-06-30  
> 用途：约束我们怎么用多个 Agent 开发本项目。  
> 边界：这是内部开发方法，不属于产品功能，不给业务用户展示。

## 1. 持久化原则

Agent 的“角色规则”可以持久化，Agent 的“运行记忆”不作为事实来源。

真正持久的来源是：

| 持久化对象 | 用途 |
|---|---|
| `docs/` | 业务口径、架构、边界、交接 |
| Spec Kit `spec.md / plan.md / tasks.md` | 正式规格、计划、任务 |
| 测试和验收记录 | 证明功能是否真的完成 |
| `AGENT_HANDOFF.md` | 新会话恢复上下文 |
| 工作日志 | 周报和历史追踪 |

## 2. 推荐 Agent 角色

| Agent | 负责什么 | 交付物 |
|---|---|---|
| 主控 Agent | 控范围、拆任务、合并结果、决定先后顺序 | 最终方案、任务边界、验收结论 |
| 需求规格 Agent | 冻结 MVP、字段、状态、验收标准 | spec / checklist / 待确认问题 |
| 原型 UX Agent | 页面架构、状态展示、产品评审图 | 原型说明、页面清单、状态图 |
| 数据导入 Agent | Excel 源表、字段映射、有效行、图片和 CH 证据 | 导入规则、字段验证、异常清单 |
| 写代码 Agent | 按任务实现 P0 功能 | 修改文件、验证命令、未做项 |
| 测试验收 Agent | 跑导入、认领、审核、导出验收 | P0/P1 验收结果、缺陷清单 |
| Review Agent | 查非 MVP、过度设计、无关改动、缺测试 | review findings |

## 3. 写代码 Agent 规则

写代码 Agent 只能在需求冻结后启动。

输入必须包括：

- 已确认的 spec / tasks。
- 本次只做的任务。
- 允许改的文件或模块。
- 验收方式。

限制：

- 不得修改无关文件。
- 不得新增运行时依赖，除非主控 Agent 明确批准。
- 不得把采购、供应链、到货、四周总结混进 Phase 1。
- 不得删除来源追溯、图片证据、CH 证据、不认领审核。
- 不得把内部 Agent 设计写进业务产品页面。

输出必须包括：

```text
修改文件：
验证命令：
手工验证路径：
未做项：
风险：
```

## 4. 并行规则

可以并行：

- 数据导入 Agent 做 Excel/字段。
- 前端 Agent 做页面展示。
- 后端 Agent 做状态流转。
- 导出 Agent 做可备货清单。
- 测试 Agent 做只读验收。

不能并行：

- 两个 Agent 同时改同一个文件。
- 一个 Agent 改状态枚举，另一个同时改依赖状态的页面。
- 需求没冻结时启动实现 Agent。
- 测试 Agent 和实现 Agent 同时改测试口径。

## 5. 推荐执行顺序

```text
需求规格 Agent
  -> 原型 UX Agent
  -> 主控 Agent 合并
  -> Spec Kit spec / plan / tasks
  -> 写代码 Agent
  -> 测试验收 Agent
  -> Review Agent
  -> 主控 Agent 收口
```

## 6. 当前项目第一批实现拆分建议

| 任务 | 建议 Agent | 写范围 |
|---|---|---|
| 选品1导入和字段映射 | 数据导入 Agent | importer、models、tests |
| 状态流转和审核逻辑 | 后端写代码 Agent | services、routers、tests |
| 机会池/认领/审核页面 | 前端写代码 Agent | frontend 页面和 API 类型 |
| 可备货清单导出 | 导出 Agent | export service、Excel 生成、自测文件 |
| 中文化和搜索分页验收 | 测试验收 Agent | 只读验收，必要时提 bug |
