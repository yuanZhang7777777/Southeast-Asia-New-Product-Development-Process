## 分配台推荐规则

- 先按站点硬隔离：PH/TH/VN 等站点不混分，不属于该站点的运营不能接该站点 SKU。
- 同一主 SKU 在同一来源、同一期、同一站点内整组分配；同一主 SKU 跨站点时按站点拆开，各站点单独推荐。
- 重点品类1和重点品类2优先级相同，只要命中任一重点品类，就进入同一优先级池。
- 负载均衡按“主 SKU 组数”计算，不按子 SKU 数量计算；一个主 SKU 下有多个子 SKU 也只算 1 组负载。
- 推荐时要计入数据库里已经分配但未完成的认领任务，按“负责人 + 来源 + 期数 + 主 SKU + 站点”去重统计当前负载。
- 在同站点候选人中优先推荐当前主 SKU 组负载更少的人；重点品类命中、人员优先级和自定义顺序仅处理同负载并列。例如 A 已分配 3 个主 SKU，新任务在 A/B/C/D 都可接时，即使 A 命中重点品类或优先级最高，也应先分给负载更低的人。
- 同站点候选人初始负载相同时，单位主 SKU 组的一轮推荐结果最大相差 1 组；提高某人的 `assignment_priority` 不能让其独占同类任务。

## 项目流程与 PLM 到货边界（2026-07-13）

- 平台主流程顺序为：源表导入 -> 新品机会池 -> 主管分配 -> 运营认领 -> 主管复核 -> 导出中心 -> 外部备货/采购/运输 -> PLM 到货识别 -> 到货提醒 -> 二次调研及后续流程。
- 到货位于导出之后；当前前端把“到货预览”排在“导出中心”之前，属于待修正的流程顺序问题。
- PLM 到货数据不依赖本系统的导出记录。集团八部的全部到货都可以进入独立的到货提醒，包括老品补货和本系统没有的商品。
- 老品补货或本系统没有的商品只通过钉钉发送到货提醒，不进入商品看板，不产生平台状态或待办，也不参与本系统后续业务流程。
- 只有本系统中“主管复核通过”的子 SKU 才有资格进入二次调研及后续流程；是否实际点击导出不影响该资格。
- PLM 到货与平台后续记录按“子 SKU + 国家 + 销售员”精确匹配。同一子 SKU、同一国家由多人备货时，每位销售员分别保留独立的后续记录，不得相互覆盖。
- 仅三项完全匹配时才关联平台后续；销售员不一致表示不是该运营的商品，不做姓名纠错、不做人工匹配列表，也不生成该运营的后续任务。
- PLM 每日到货通知按销售员汇总发送：每位销售员每天只收到一条消息，消息内区分“新品到货”和“老品补货”，不按单个 SKU 连续发送。
- 每天北京时间 08:00 获取前一天 PLM 数据，09:00 汇总发送；09:00 数据尚未准备好时继续重试，成功后当天补发一次。
- 待认领使用钉钉互动卡片模板 `a428e864-5416-4ea6-ad29-36e19e0615e2.schema`。
- 到货通知使用钉钉互动卡片模板 `a4053068-a70c-4ec8-a5b7-293d38a67a84.schema`。
- 到货通知卡片变量固定为：`card_title`、`summary_text`、`left_label`、`left_count`、`sku_markdown`、`action_text`、`action_url`。
- 到货通知卡片的 `sku_markdown` 按“新品 / 老品”分区；每个分区按主 SKU 汇总，每条只展示“主 SKU、该主 SKU 下本次到货的子 SKU 数量、商品名”，不逐个展示子 SKU 明细。
- 新品待办卡片变量固定为：`card_title`、`summary_text`、`left_label`、`left_count`、`right_label`、`right_count`、`tip_text`、`action_text`、`action_url`。
- 当前仍处于测试阶段，未明确正式启用前不得向真实运营批量发送，也不得自动创建真实后续待办。

## 商品看板与生命周期状态（2026-07-13）

- 不单独建设运营使用的“到货页面”。系统内商品的到货与后续状态统一放在商品看板，运营通过负责人、业务状态、到货日期等条件筛选自己的商品。
- 运营默认按“负责人 = 我”查看；主管和超级管理员可以查看全部负责人。
- 多人认领状态必须记录在“子 SKU + 国家 + 销售员”的责任关系上，不能只记录在商品全局状态上。
- 同一商品由多人认领时，每位销售员筛选“我的商品”都能看到；一人完成二次调研不得影响其他人的状态。
- 商品看板主表按“主 SKU + 业务期数 + 站点”一行展示，不按销售员拆成多行；认领人、多人责任和每位销售员各自状态只在展开行或详情中查看。
- 主管查看同一主 SKU 时可以展开查看每位销售员各自的责任状态。
- 当前可见业务状态固定为：`待分配`、`待认领`、`待复核`、`退回待补充`、`已确认不认领`、`待导出`、`待到货`、`待二次调研`、`待刊登`、`已刊登`、`1-4周观察期`、`已停用`。
- 二次调研提交成功只记录“二次调研完成”审计事件，不作为需要停留和再次操作的页面状态；二次调研后的状态顺序为：`待二次调研 -> 待刊登 -> 已刊登 -> 1-4周观察期`，其中 `1-4周观察期` 是流程最后一环。
- 运营确认商品已刊登后，系统自动进入 `1-4周观察期`，不需要运营再次手动开启观察期。
- 第 1 至第 4 周均以运营确认已刊登的时间为起点，系统按每 7 天自动划分一个观察周。
- 观察期内可以按周补充记录，但不强制填写；未填写周记录不阻塞流程，也不生成催办。
- 不设置 `四周总结待复核` 或 `流程完成` 状态，不要求观察期结束后再走总结复核。
- 不单独设置“已到货”状态；PLM 精确匹配成功后，责任状态从 `待到货` 直接进入 `待二次调研`。
- `部分认领`、`多人认领`只作为商品看板汇总标签，不作为独立业务状态；任务表的 `pending/completed` 也不作为商品状态展示。

## 钉钉人员 userId 缓存规则（2026-07-13）

- 首次接入时全量获取整个公司的人员 userId，生成一份可交付保存的人员清单，同时在服务器安全缓存中保留全量快照。
- 全量人员清单保留钉钉通讯录接口返回的全部字段，包括手机号、邮箱、职位、工号、部门、人员状态等，不只保留姓名和 userId。
- 日常发送优先使用缓存中的 userId，不做每周全量刷新。
- 当系统人员配置新增运营、主管或管理员，且该姓名尚未绑定 userId 时，才重新向钉钉查询该员工并保存对应 userId。
- 人员配置没有新增时，不重复调用钉钉通讯录接口。
- 全量人员清单和缓存属于内部敏感数据，不写入 Git、不进入公开日志，账号密码和钉钉密钥不得写入需求文档。
- 2026-07-13 已完成首次全量拉取，共 1066 人、23 个字段，并生成私有 Excel 与原始 JSON 缓存。

## 二次调研字段流转与当前开发范围（2026-07-13）

- `【市场监控】海外仓精品市场调研.xlsx` 的 `PH精品`、`TH精品`、`VN精品` 等国家 Sheet 使用同一套字段口径。
- 市场监控表 `A-AC` 均由选品1、选品2的对应上游字段流转，二次调研阶段不要求运营重新填写这些字段；具体实现按字段含义匹配，不因 Excel 列位置变化而错配。
- 选品1到市场监控表的已确认精确映射为：市场监控 `AD <- 选品1 K`、`AE <- 选品1 AJ`、`AF <- 选品1 AL`、`AG <- 选品1 AM`、`AH <- 选品1 AO`、`AI <- 选品1 AP`。
- 市场监控表 `AJ=认领单销`、`AK=首次调研结论`，分别来自运营在前段待认领阶段填写的认领日销和调研结论。
- 市场监控表 `AL=二次调研时间`、`AM=二次竞对链接`、`AN=二次调研结论`、`AO=产品定位`，是运营在到货后的二次调研阶段填写 / 确认的数据；二次调研页面的人工填写范围只覆盖这四列。
- 同一主 SKU 下每个子 SKU 的 `AL-AO` 独立保存。运营首次填写一个子 SKU 时，系统默认把该次输入同步到同主 SKU 的其他子 SKU；同步后运营仍可逐行修改，修改某一行不再覆盖其他行。
- 同一“子 SKU + 国家”被多位运营认领时，运营可以查看其他认领人的二次调研内容，不需要把其他运营的数据隐藏起来；每位运营对应的责任进度仍按“子 SKU + 国家 + 销售员”独立记录。
- `AL` 默认由系统填写二次调研提交时间并允许运营修改；`AM` 二次竞对链接选填；`AN` 二次调研结论必填，可填写“无变化”或具体变化；`AO` 产品定位必选，选项为引流款、利润款、淘汰款。
- 二次调研按主 SKU 整组提交；提交前必须完成该主 SKU 组内全部子 SKU 的必填项，存在未填写完整的子 SKU 时整组不得提交。
- 二次调研输入框失去焦点后自动把当前内容保存为服务端草稿；运营关闭页面或重新进入后仍能继续填写。保存草稿不改变业务状态、不触发淘汰款或其他通知，只有点击整组提交后才校验全部子 SKU 并执行状态流转。
- 同一主 SKU 组允许不同子 SKU 选择不同产品定位；整组提交后按子 SKU 独立分流：`AO=淘汰款` 的子 SKU 进入 `已停用`，`AO=引流款` 或 `AO=利润款` 的子 SKU 进入 `待刊登`，不同子 SKU 的结果不得相互阻塞或覆盖。
- 运营提交的 `AO 产品定位` 为 `淘汰款` 时，系统记录为待汇总通知，提醒主管去外部系统调整产品定位，避免淘汰款因清仓销量被误判并触发持续补货；不按单条提交即时推送。
- `淘汰款` 提交后，该销售员对应的子 SKU 责任记录直接进入 `已停用`，不再进入 `待刊登`；平台只向主管发送通知，不要求主管在平台内复核或确认完成。
- 淘汰款通知默认发送给系统人员配置中所有已启用的主管和超级管理员；后续人员配置新增主管或超级管理员时，自动按最新启用名单纳入接收范围。
- 淘汰款提醒复用到货通知卡片模板 `a4053068-a70c-4ec8-a5b7-293d38a67a84.schema`，不新增第三个卡片模板；卡片动态使用“淘汰款提醒”标题，通过 `sku_markdown` 展示业务期数、站点、主 SKU、子 SKU、商品名、运营和二次调研结论，按钮进入商品看板。
- 二次调研页面默认展示当前最新业务期数的待二次调研商品；页面顶部可以切换其他历史期数，也可以选择查看全部期数。
- 二次调研采用独立全宽工作台，不要求运营先打开商品看板详情或另外进入商品详情抽屉。页面顶部压缩展示主 SKU、商品名、业务期数、站点、负责人、到货时间、类目、关键词和开品理由等当前处理所需信息。
- 二次调研工作台始终以同一主 SKU 下全部子 SKU 为行，默认打开 `二次调研` 模块并在一张表内填写 `AL-AO`、上传调研图片、查看其他运营记录；运营可以在同一工作台切换 `市场调研`、`价格 / 毛利`、`开发询价 / 包装`、`成本 / 备货` 和 `认领记录`，不需要离开当前页面查看完整来源记录。
- 子 SKU 列保持在表格左侧；宽字段只在当前模块内部横向滚动，不把来源字段和填写区压缩成左右两个狭窄面板。主 SKU 切换同时提供顶部按钮和页面两侧按钮。
- 二次调研表格底部固定展示草稿保存状态和“提交本主 SKU”按钮；整组提交结果按各子 SKU 产品定位独立分流。
- 多人认领时，当前运营编辑自己的二次调研记录，并可从对应子 SKU 行查看其他运营的二次调研记录；其他运营记录在当前运营页面中只读，不允许相互覆盖。
- 每周导入的一期数据必须在认领、复核、到货承接、二次调研等各阶段持续保留期数并相互隔离；相同主 SKU 或子 SKU 出现在不同期时，不得在页面或任务中合并成同一期记录。
- 选品1导入必须拆分“数据 Sheet”和“业务期数”两个概念：主管先选择实际读取数据的 Excel Sheet；业务期数可以直接采用该 Sheet 名称，也可以另行填写自定义名称。
- 自定义业务期数只作为贯穿认领、复核、到货承接、二次调研等阶段的期数标签，不改变实际读取的 Excel Sheet，也不改变源表追溯信息。
- 相同数据 Sheet、相同业务期数再次导入时，默认采用增量更新，不做全量覆盖：已存在的 SKU 更新字段，新 SKU 追加，本次文件中缺失的旧 SKU 继续保留，不自动删除或停用。
- 增量更新使用 `来源 + 业务期数 + 站点 + 主 SKU + 子 SKU` 判断同一条业务数据；Excel 行号只用于来源追溯，不参与重复判断。
- 同一期 SKU 重新导入时，只更新该业务记录的源表字段；已经产生的分配、认领、复核、到货承接、二次调研等流程数据和当前进度全部保留，不因重新导入而重置。
- 需要移除数据时，由有数据管理权限的人员单独停用 SKU 或停用整期数据；每次导入仍保留独立快照和审计记录。
- 系统内商品触发到货通知后，要保存该商品本次识别到货的日期和时间，作为后续二次调研的数据留痕。
- 仅下载“前一天最后一次入库”的 PLM 增量数据会漏掉系统接入前已经有库存的商品：这类商品不应继续停留在待到货，选品2中较常见。
- 后续需要对系统内符合后续资格的商品执行一次 PLM 全量库存匹配，用来识别接入前已经有货的商品；全量匹配的切入时点、去重和首次提醒策略仍待确认。
- 当前开发优先完成选品1的整套流程。选品2及其历史库存全量匹配问题先保留记录、暂缓实施，待选品1流程稳定后再继续。
- 当前实现把 `source_sheet` 同时当作数据 Sheet 和业务期数使用，必须修正为分别保存真实数据 Sheet 与业务期数，避免自定义期数导致读取错误或来源追溯失真。

## 钉钉汇总通知节奏（2026-07-13）

- 淘汰款不按单条提交即时推送。系统每天北京时间 `09:00` 汇总发送一次，扫描所有尚未成功通知的淘汰款记录，避免因周末、任务失败或重试造成漏发。
- 淘汰款汇总按运营、业务期数和主 SKU 组织明细；每次汇总中，每位已启用的主管和超级管理员最多接收一张卡片。没有新增未通知记录时不发送空卡片。
- 淘汰款卡片发送成功后必须记录发送时间或发送批次；定时任务重试时不得重复发送已经成功通知的记录，发送失败的记录保留到下一次重试或汇总继续发送。
- 认领与不认领提交均不按运营每次提交即时通知主管。系统每周四北京时间 `09:00` 向已启用的主管和超级管理员发送一张复核汇总卡片，展示当前待复核认领数和待复核不认领数，并进入主管复核页处理。
- 周四汇总卡片只提供当时的数量摘要和处理入口；主管进入复核页后查看实时队列，因此汇总发送后新增的待复核记录仍会正常显示和处理。
- 主管退回补充属于明确需要原运营及时处理的动作，仍在退回发生后即时通知对应运营，不等待周汇总。
- 当前仍处于测试阶段；以上定时规则只作为正式启用后的发送口径，在业务明确确认正式启用前不得向真实人员发送卡片。
